How Token Economics cuts what coding agents cost

Token Economics is a control plane that sits between coding harnesses (Claude Code, Codex CLI, Aider, SDK scripts) and any number of model backends, API or CLI. It measures cost per successful task, enforces budgets outside the agent, and turns on each saving only after a paired test shows it works.

Based on the plan in plan/. 423 sources, 8 stages, 79 components, 233 requirements.

Build in this order. Measure for four weeks before you block anything. Enforce budgets next. Optimise only once a 30 day baseline exists. Harden for production last. Without a baseline you cannot tell whether a saving is real.

One request, end to end

Every harness reaches Token Economics through a gateway URL. The gateway is the source of truth for cost. Hooks, OpenTelemetry and local transcripts add attribution detail but never carry enforcement, because a developer can switch them off.

The policy engine reserves the worst-case cost before dispatch and replaces it with the true cost once the response finishes. That makes a budget a hard cap at the gateway instead of a request the agent may ignore.

Make it pluggable with an adapter per harness

Each harness exposes different hooks, so Token Economics wraps each one in an adapter. An adapter has five functions.

  • route points the harness at the gateway.
  • identify returns tenant, team, session and prompt ids.
  • observe returns one normalised usage event.
  • cap turns a policy into the controls that harness supports.
  • replay rebuilds usage from local transcripts.

Each adapter also declares eight capability flags. When a flag is false, the policy engine downgrades that control to observation and says so.

FlagMeaning
baseUrlThe harness can be pointed at a gateway. This is the only flag that makes enforcement possible.
oauthPassthroughSubscription tokens can be forwarded without storing them.
hooksBlockingA hook can block a call. Developers can disable hooks, so this is weak.
otelThe harness emits OpenTelemetry metrics and events.
budgetFlag, headlessThe CLI accepts a budget or turn flag and runs without a terminal.
modelRewriteThe gateway may change the model id in flight.
transcriptPathLocal transcripts exist for replay.

Never mark a harness with baseUrl = false as enforced. Pin the route in managed settings where the harness allows it, so a developer cannot bypass the gateway.

Count tokens in five buckets before pricing anything

Providers report usage in incompatible shapes. Token Economics converts each response into five mutually exclusive buckets: fresh_input, cache_read, cache_write_5m, cache_write_1h and output. Reasoning tokens sit inside output and are never added a second time.

ProviderWhat the input field meansConversion
Anthropicinput_tokens excludes cacheTotal input is fresh plus read plus creation.
OpenAI, xAI, OpenRouterprompt_tokens includes cached tokensFresh is prompt minus cached. 17,903 prompt with 17,817 cached leaves 86 fresh.
Bedrock ConverseCache fields reported beside inputTokensTotal is the sum of the three.

The ledger then enforces nine rules. The four that bite first:

  1. One row per provider response id. Parallel tool calls that share a message id count once.
  2. Subagent spend gets its own row, because the parent result excludes it.
  3. Use exact model ids. Partial-name matching produced a silent wrong price in one tool.
  4. Failed and retried attempts are spend. Failed runs were 17 percent of tasks and 32 percent of spend in one study.

Prices live in an append-only price book. Every ledger row stores a price_row_id, a new price never rewrites old rows, and a weekly canary compares computed cost with the invoice.

Cut tokens the model never needed

In one study of 2,848 runs, 74.7 percent of billed cost was the harness base prompt and tool definitions. Tool outputs were 3.3 percent. That ranking decides which controls come first.

ControlDefault Token Economics ships
Schema deferralOn above about 20 tools, with a lookup path so the model can fetch a schema it needs.
Output cap25,000 tokens interactive, 12,000 for Codex, 6,000 batch. Never truncate tracebacks or edit anchors.
Observation maskingOnly above about 10 events. At 7 or fewer it lost money.
ClearingTrigger at 30 to 40k tokens, keep 5 results, clear at least 3,000 to 5,000.
CompactionLast resort. Recommend a restart at the third compaction.
max_tokensHard cap on every call, since effort settings do not cap tokens.
Output compressorsOff. One study cut tool-output tokens 38.4 percent and raised cost 6.8 percent.

History edits break the exact-prefix cache, so edit history only at a trigger, never every turn. A timestamp at the top of a prompt dropped cache reuse from 87 to 3 percent in one report.

Ship an optimisation only after a paired test

The headline metric is cost per successful task (CPS). It divides all attempt cost, failed runs included, by the number of successes. Token counts mislead. 106 of 336 price comparisons reversed the sticker-price ranking, and token reduction correlated with cost reduction at r = 0.154.

  1. Run each task on both arms with several repeats, and pair the results by task.
  2. Declare the non-inferiority bound for success before the test starts.
  3. Isolate the cache between arms. The median gap between arms in one study was 10.8 seconds, inside the 5 minute TTL.
  4. Charge router and classifier cost to the arm that uses them.
  5. Use a private task set with hard cases. Public sets saturate at 96 to 98 percent.
  6. Roll out as shadow, then a per-tenant canary, with a kill-switch per optimisation and automatic rollback.

Detect waste on its own, apply a fix only after a test

Token Economics finds waste automatically and does not fix everything on day 1. It reads detectors off the ledger, measures each finding, and applies a fix by class. Anything that changes what the model sees waits for a paired win on that harness, because savings are harness-specific. The Headroom compressor raised cost 48.4 percent in one setting and cut it 12.49 percent in another (C:024).

The metric list comes from anvesx/hermes-engine, a Claude Code plugin with 50 ranked leak rows and 103 detectors. It only observes. It never caps spend or blocks a tool, and it reads CLI transcripts that API traffic does not have. Its costs are list-price estimates that overlap, and no saving from any fix is measured. Token Economics uses it as a detector library, not as a forecast.
