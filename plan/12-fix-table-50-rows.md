# The 50 problems and how to fix each one

Each row is one of the 50 ranked token-leak rows in hermes-engine (`_research/hermes/notes/A-taxonomy.md`). For each row the table gives the fix for API agents (applied at the gateway) and for CLI agents (applied through hooks, settings and flags), the named techniques behind it, and the phase it ships in. Technique names are quoted from the corpus. Ids: `A:nnn` API corpus, `C:nnn` CLI corpus. Anything with no corpus source is labelled DevX proposal.

Counts: 50 rows, 165 techniques cited from 86 sources, plus 277 more technique entries from the coverage pass over the other sources (`12b-source-coverage.md`). Fix classes: 1 alert, 3 guard, 33 behaviour change, 13 human action. Fix evidence: the API fix rests on a DevX proposal in 21 rows and the CLI fix in 8 rows.

Terms: Model Context Protocol (MCP) is the tool-server standard. Time to live (TTL) is how long a cache entry lasts. Cost per successful task (CPS) is Token Economics's main metric. Language Server Protocol (LSP) gives code navigation. RTK is a command-line proxy tool (RTK) named in C:024. Project instruction files such as `CLAUDE.md`, `AGENTS.md` and `SPEC.md` hold standing rules for a harness.

## How to read the columns

- **Class** is the highest fix class involved (see `11-detect-measure-apply.md`). Class 2 fixes change what the model sees and wait for a paired cost-per-success win.
- **Phase** is where the fix ships. Every detector runs from P0 in alert mode. Class 3 rows ship as recommendations in P0.
- **Evidence** is `corpus` when a source in the corpus supports the fix, and `proposal` when it is a DevX proposal that needs a P0 spike.
- Mechanism, measured effect, where each technique loses and the test design are in `12a-fix-technique-detail.md`.
