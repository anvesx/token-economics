 s1-llm-auto-router

A decision model fine-tuned to classify a request to an LLM before you route it. In one CPU pass it answers
the seven questions an LLM auto-router needs to pick a model. It is served as a Jev-compatible decision model
on the Decision Models API, and the weights are published here under the MIT licence.

Architecture: jhu-clsp/mmBERT-small (MIT), pruned to 11 layers and distilled from a fine-tuned
mmBERT-base teacher, with seven classification heads. Per-head calibration temperatures are in meta.json.

Format: ONNX with int8 embeddings (model.gq.onnx, 183 MB) and a fast tokenizer. It needs neither
PyTorch nor transformers.

Latency: engine only, about 14 ms p50 and 47 ms p99 per decision (all seven answers) on 4 pinned cores of an AMD
EPYC 9555 server, and 26 ms p50 on 4 threads of an older Xeon E5-2680 v4. Through the hosted API, end to end: about 93 ms p50
(measured 2 Oct 2026).

Input: the user turn (up to 512 tokens in total) plus an optional short conversation summary (first 600
characters are used).

 Run it locally (CPU)

pip install onnxruntime tokenizers numpy huggingface_hub
python example.py "Refactor this ABAP report to use CDS views"

example.py in this repo contains the full code; the core is:

import json, numpy as np, onnxruntime as ort
from tokenizers import Tokenizer
from huggingface_hub import snapshot_download

root = snapshot_download("decisionmodels/s1-llm-auto-router")
T = json.load(open(f"{root}/meta.json"))["temperatures"]
tok = Tokenizer.from_file(f"{root}/tokenizer/tokenizer.json")
tok.enable_truncation(512, strategy="only_second")
sess = ort.InferenceSession(f"{root}/model.gq.onnx", providers=["CPUExecutionProvider"])

def softmax(x): e = np.exp(x - x.max()); return e / e.sum()
enc = tok.encode("(new conversation)"[:600], "Refactor this ABAP report to use CDS views")
ids = np.asarray([enc.ids], dtype=np.int64)
cat, dif, stk, flg = sess.run(None, {"input_ids": ids, "attention_mask": np.ones_like(ids)})
CATS = ["coding", "agentic", "math", "knowledge", "long_context", "tool_use", "design", "summarisation", "general"]
p = softmax(cat[0] / T["category"]); print(CATS[p.argmax()], p.max())

 Limitations

Fixed schema. It answers only the seven questions above. It is not a general-purpose classifier or a
typed-decision model, and it does not read the question text. For arbitrary typed decisions use the other
Decision Models.

Synthetic training data. About 39k routing requests that LLMs wrote from a persona × stack × task × language
grid (22 languages, 29 stacks including SAP ABAP, PL/I and COBOL). It contains no real user traffic or customer
data, so real traffic may be distributed differently.

LLM labels. Requests were written by DeepSeek-V4-Flash, Kimi-K2.6, Gemma-4-31B and Qwen3.8-27B. Five open LLMs
(those four plus GLM-5.1) labelled each request blind; a model never labelled its own requests. Training uses their soft vote. Most test gold labels come
from the same process, which is why the Claude-labelled set is reported separately.

Decontaminated. The data was deduplicated against all public and sealed JevBench items (exact, containment and
embedding near-duplicate checks) before training.

Language gaps. Weakest on Greek, Korean and Italian (category accuracy 0.73–0.78 at n ≈ 20 each).

Truncation. Inputs are cut to 512 tokens; only the first 600 characters of the conversation context are used.

Text only. needs_vision is a probability from the text of the request; the model cannot inspect images.

 Training

Teacher: mmBERT-base, fine-tuned on soft labels. Student: mmBERT-small layers 0, 2, …, 18 and 21, distilled with
alpha 0.9 for 12 epochs at learning rate 1.5e-4, on one RTX 4090 for about one hour.

Split by generation group: 34,671 train, 2,275 dev and 2,175 test examples. Temperatures fitted on dev.
