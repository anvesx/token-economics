# 051 — Tokenomics for coding agents: benchmark cost and quality on your own code
- **Source**: https://aws.amazon.com/blogs/aws-cloud-financial-management/tokenomics-for-coding-agents-benchmark-cost-and-quality-on-your-own-code (AWS, 2026-10)
- **Claim**: Coding-agent cost and quality depend jointly on the model, harness, and hosting path, so teams should benchmark those combinations on their own pinned repositories instead of using public model rankings. In the reported 21-task sample, task-level routing reduced total cost with a modest reduction in mean quality.
- **Mechanism**: Recreate closed issues at pinned commits, run every model–harness–provider combination on the same tasks, record tokens, turns, latency, and GPU-seconds or metered API cost, score artifacts with an independent rubric-based judge, and build a cost–quality Pareto frontier. A `swe-router` skill estimates task consequence, sets a quality floor, and selects the cheapest measured model above it; open-weight self-hosted runs are priced as total processed tokens divided by measured workload throughput, multiplied by GPU price per second.
- **Numbers**: Sample model frontier over 21 tasks: quality/cost per task was 59.2/$0.26, 59.7/$0.87, 78.5/$1.47, 79.2/$4.33, 80.1/$7.04, and 82.8/$11.95; the 27B dense model gained 18.8 quality points for $0.60, while models above it added 4.3 points for about $10.48 and the top model cost roughly 8× as much. One model cost about $8/task under the lighter harness versus about $24/task under the heavier harness. Routing across 21 tasks cost $138.84 versus $251.04 for the top model on every task, with mean score 78.84 versus 82.83: 44.7% cheaper for 4.8% lower mean quality. The example router recommended a $4.67/task model instead of $11.95/task, a 61% saving with 11.1 quality points above a floor of 65. The repository supports 5 harnesses, 3 hosting paths, and serving guides for 17 open-weight models.
- **Token-cost implication**: Benchmark at least five representative closed issues on two already-approved models, then route each task to the cheapest model that clears an empirically chosen quality floor; optimize the harness before assuming the model is the cost problem, and move from per-token hosting to a GPU only after sustained volume crosses the fixed-cost break-even point.
- **Caveats**: AWS authored the post and released demonstration sample code under MIT-0; the model names are replaced by class placeholders. The 21-task results come from one Python/React repository with an LLM judge, do not establish results for other repositories, and compare metered closed models with GPU-time-derived open models on different cost bases; self-hosting also incurs idle cost.
- **Topic**: routing
