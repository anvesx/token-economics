# 016 — EmbedLLM: Learning Compact Representations of Large Language Models
- **Source**: https://arxiv.org/abs/2410.02223 (ICLR, 2024-10)
- **Claim**: Compact model embeddings learned from a model-by-question correctness matrix can support fast routing, unseen-question correctness prediction, and benchmark-performance forecasting without learning a separate rich model representation for every task. The matrix-factorization router approaches per-benchmark best-model accuracy while exploiting specialists across a 112-model pool.
- **Mechanism**: Collect binary correctness for each model–question pair; learn one vector per model and project sentence-transformer query embeddings into the same space; use their element-wise product and a linear classifier to reconstruct correctness with binary cross-entropy. At routing time score every candidate model against the query and select the highest predicted correctness; for benchmark forecasting, fit a linear regressor from frozen model embeddings to held-out benchmark accuracy.
- **Numbers**: 112 open-source models and 36,054 questions from 10 benchmarks; 80%/10%/10% question split; initial query embeddings 768 dimensions; full-training correctness forecast accuracy 0.7409 versus KNN 0.7152; routing 3,000 questions averaged 3.80 s over 50 trials on one NVIDIA A100 80GB; more than 750 model selections/s versus fewer than 50 requests/s for the compared causal LLM router, 15× faster while choosing among 112 versus 2 models; training used under 1GB GPU memory, described as 60× cheaper in memory than fine-tuning Llama-3-8B; benchmark prediction was significant in 7 of 10 benchmarks; avoiding MMLU evaluation saved about 14,000 questions and around 2M input tokens/model.
- **Token-cost implication**: Amortize evaluation across a stable model catalog: learn reusable model embeddings once, route with a cheap scorer, and forecast which full benchmarks are worth running before paying their complete token cost.
- **Caveats**: The authors assembled and evaluated the dataset; it has only 112 models and binary correctness labels. The pool is fixed—adding a model requires retraining matrix factorization—and benchmark forecasting failed to show significance on three benchmarks; response quality beyond correctness and changing API models were not tested.
- **Topic**: routing
