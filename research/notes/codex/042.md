# 042 — Trust by Design: Skill Profiles for Transparent, Cost-Aware LLM Routing
- **Source**: https://arxiv.org/abs/2602.02386 (arXiv, 2026-02)
- **Claim**: BELLA proposes selecting the cheapest model that meets a task’s explicit skill requirements, with a natural-language rationale, instead of routing from aggregate benchmark scores or opaque learned policies.
- **Mechanism**: Benchmark candidate models and retain outputs, performance, cost, and latency; have a critic LLM label demonstrated skills, missing skills, and their criticality per instance; embed and cluster the free-text labels into a canonical taxonomy; build model×skill proficiency, task×skill requirement, and model-cost matrices. For a new task, infer or accept required skills, filter models whose skill proficiency exceeds a threshold for every required skill, then maximize predicted performance subject to a budget, using Pareto optimization or weighted scalarization for multiple constraints.
- **Numbers**: Illustrative pricing compares GPT-5 at $10 per 1M tokens with Llama-3.3-70B at $0.88 per 1M tokens, described as 11× cheaper; the paper’s example aggregate model accuracy is 85%. No BELLA accuracy, savings, routing recall, latency, or experimental sample count is reported.
- **Token-cost implication**: Profile reusable skills once, cache the profiles, and route only to models that clear the task’s critical-skill thresholds; include the critic/profiling spend in amortization because BELLA requires a critic call for every model-task-instance before it can save inference cost.
- **Caveats**: Framework/design paper rather than an empirical validation; authors explicitly say the core hypothesis still needs comparison with RouteLLM, FrugalGPT, and an oracle. Critic accuracy, cross-critic consistency, clustering stability, profiling overhead, skill transfer, and multi-constraint selection are unmeasured; the $10 and $0.88 prices are illustrative TogetherAI API pricing, not BELLA results.
- **Topic**: routing
