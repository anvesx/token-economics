# 067 — Prompt Caching in the API
- **Source**: https://openai.com/index/api-prompt-caching (OpenAI, 2024-10)
- **Claim**: OpenAI automatically discounts and accelerates eligible input prefixes that were processed recently, with no integration change required. Repeated codebase context and multi-turn conversation history can therefore cost half as much on a cache hit.
- **Mechanism**: For supported models, the API finds the longest previously computed prompt prefix, beginning at 1,024 tokens and extending in 128-token increments, then reports reused tokens in `usage.prompt_tokens_details.cached_tokens`. Keep invariant instructions and context at the front of prompts and monitor that field to verify reuse.
- **Numbers**: Cached input was priced at a 50% discount per 1M tokens: GPT-4o $2.50 uncached/$1.25 cached/$10.00 output; GPT-4o fine-tuning $3.75/$1.875/$15.00; GPT-4o mini $0.15/$0.075/$0.60; GPT-4o mini fine-tuning $0.30/$0.15/$1.20; o1-preview $15.00/$7.50/$60.00; o1-mini $3.00/$1.50/$12.00. Caching applies to prompts longer than 1,024 tokens, grows in 128-token increments, typically clears after 5–10 minutes of inactivity, and is always removed within 1 hour of the last use. The example response had 2,006 prompt tokens, 1,920 cached tokens, 300 completion tokens, and 2,306 total tokens.
- **Token-cost implication**: Put stable system instructions, tool definitions, and shared code context first; reuse them within the cache lifetime, and track `cached_tokens` rather than assuming a repeated prompt received the discount.
- **Caveats**: This is an OpenAI product announcement and pricing snapshot, not an independent benchmark. It measures neither realized latency reduction nor application-level savings, applies only to the listed model versions, and caches are organization-isolated and time-limited.
