# 058 — Claude Code Best Practices
- **Source**: https://www.anthropic.com/engineering/claude-code-best-practices (Anthropic, 2025-04)
- **Claim**: Claude Code is most effective when users supply only information the repository cannot reveal, give the agent executable pass/fail checks, and enforce exception-free constraints in the harness rather than relying on prompt text. Cost grows when unrelated work, unused integrations, background loops, or unnecessary subagents repeatedly expand the context sent on every request.
- **Mechanism**: Keep `CLAUDE.md` short and limited to commands, hidden decisions, and recurring gotchas; scope local rules by path and put infrequent procedures in on-demand skills. Close the implementation loop with tests, typecheck, lint, screenshots, goals, Stop hooks, and independent review; use deny rules or command/HTTP hooks for deterministic constraints. Inspect `/usage`, clear between unrelated tasks, compact with a focus, keep stable work in separate sessions/worktrees, choose lower effort or smaller subagent models for routine work, and cap unattended runs with `--max-turns` or `--max-budget-usd`.
- **Numbers**: The memory guide recommends keeping `CLAUDE.md` under 200 lines. A Stop hook that blocks 8 consecutive stops without an intervening tool call is overridden on the next stop. Auto mode pauses after 3 consecutive blocks or 20 total blocks. `/usage` flags long-context or cache-miss patterns after they exceed 10% of usage. Most current models are described as having a 1M-token context window; subscription prompt cache lasts about 1 hour, API/cloud-provider/usage-credit cache about 5 minutes, and a subscription session above about 200K tokens is compacted shortly before the 1-hour cache expires. `/batch` splits a mechanical change into 5–30 units; the example scripted run caps each file at 20 turns.
- **Token-cost implication**: Start a fresh session for each unrelated task, remove unused plugins/MCP servers, keep long procedures out of always-loaded instructions, use Haiku for simple subagent collection work, request short subagent summaries, and watch `/usage` for context replay and cache misses before changing models.
- **Caveats**: This is Anthropic product guidance, not a controlled cost or quality study, and it gives no per-token prices or measured savings. Defaults, model names, context limits, commands, and cache lifetimes are product-specific and may change; subagents can save wall time or isolate noisy output but add their own context-gathering tokens and may be slower.
