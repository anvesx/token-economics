# 008 — MTRouter: Cost-Aware Multi-Turn LLM Routing with History–Model Joint Embeddings
- **Source**: https://aclanthology.org/2026.acl-long.2045 (ACL, 2026-07)
- **Claim**: Turn-level routing over interaction history can outperform a fixed frontier model on long-horizon agent tasks while cutting total API cost. The reported gains come from stable, selective switching and model specialization rather than switching after every transient error.
- **Mechanism**: Encode the task plus recent interaction history with a frozen text encoder, truncating oldest context beyond 8,192 tokens; combine that history vector with each candidate model’s structured metadata and learned residual embedding; train an MLP outcome estimator on logged random-router and single-model trajectories to predict terminal score, with later and more severe logged errors penalized more; at each turn choose the model with the highest predicted outcome under a cost and turn cap.
- **Numbers**: 6-model pool spanning a 20× cost range; offline data: 1,291 training instances, 29,693 trajectories, 515,221 turns, approximately $1,620 one-time collection cost; GPT-5 pricing $1.25/M input tokens and $10.00/M output tokens versus GPT-OSS-120B $0.09/M input and $0.36/M output; evaluation cap $2.00/episode, 50 ScienceWorld turns, 30 HLE turns; ScienceWorld test score 53.8 ± 3.2 at $5.7 total versus GPT-5 48.4 ± 2.1 at $13.9, a 58.7% saving; HLE test accuracy 26.0 ± 2.3% at $35.0 versus GPT-5 25.1 ± 1.6% at $61.8, a 43.4% saving; data collected over three runs; after errors MTRouter retained the same model about 90.2% of the time on ScienceWorld and 80.9% on HLE.
- **Token-cost implication**: For agents, route per turn using full trajectory state, but penalize unnecessary model changes because each switch can forfeit prompt/KV-cache reuse and force the next provider to reprocess the history.
- **Caveats**: The authors collected and evaluated their own offline trajectories; training data collection is expensive and capped at 50/30 steps. The router has no online adaptation, uses only two benchmarks and six models, commercial OpenRouter used a different model pool, and the paper notes that provider-side cache loss can raise latency and effective token cost when switching.
- **Topic**: routing
