# 047 — Beyond Leaderboards: A Method for Application-Specific Capability Profiling of Large Language Models
- **Source**: https://arxiv.org/abs/2610.25659 (arXiv, 2026-10)
- **Claim**: Model selection should use versioned measurements from complete reference applications rather than a universal leaderboard, because model, prompt, framework, retrieval, judge, and evaluation context can materially change observed capability and cost.
- **Mechanism**: Package each application as a container that declares datasets, modes, prompt slots, owned metrics, provenance, and dashboard variables; let agents propose runs but have deterministic code reapply scope, require baselines, canonicalize and SHA-256-hash the plan, execute it, and compute metrics. Store a sparse per-model metamodel keyed by attribute, dataset, evaluation context, and plan; reject cross-context comparisons, keep tested-model, judge, and agent spend separate, attach evidence levels L0–L4, diagnose the measurement instrument before the system, and choose only among eligible models with a context-consistent Pareto set.
- **Numbers**: Reported infrastructure checks: 93 MAS Core tests, 21 P1 evaluation-service tests, and 232 chatbot backend tests. Migration corpora: 1,000 pairs sampled with seed 42 producing 1,448 tasks, plus 216 migration units from 34 Oracle files and 1,802 P1 files; 108 of 216 Oracle-checked units were demonstrably correct, while 25 of 114 accepted units were wrong or unverifiable. Automation model choice changed mean state-changing effects/run from 0.5 to 1.8 versus framework choice from 0.4 to 0.7; tokens/run ranged 1,953–9,465; effect-free success claims ranged 0%–55%. A prompt rewrite changed intent accuracy by +4.6, -3.4, and 0.0 percentage points across three deployments; judge churn was 16.2% at temperature 0.
- **Token-cost implication**: Price the whole evaluation and application path, but never merge model-under-test tokens with judge/agent overhead; freeze prompt and plan identities, route only from measurements produced in the same context, and report cost per evidence-backed successful task rather than cost per nominal completion.
- **Caveats**: EPAM-authored self-report with preliminary, application-specific evidence; some comparisons are single-run or small-sample, some expected labels lack independent behavioral validation, and the paper explicitly does not establish a universal model ranking or causal ordering of model versus framework effects. Judge and controller can share a model family with a tested model, generated-adapter quality and live Grafana provisioning were not measured, and “demonstrably correct” covers only exercised Oracle cases. The supplied corpus text ends during the reference-application section, so later experimental details are not present.
- **Topic**: observability
