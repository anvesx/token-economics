# 039 — Experts are all you need: A Composable Framework for Large Language Model Inference
- **Source**: https://arxiv.org/abs/2511.22955 (arXiv, 2025-11)
- **Claim**: Comp-LLM composes independently fine-tuned domain LLMs through an explicit sub-query DAG, achieving higher multi-domain QA accuracy with less resident model capacity than monolithic baselines and lower latency than sequential sub-query execution.
- **Mechanism**: Fine-tune a decomposer to emit sub-queries and pairwise dependencies, route each sub-query by cosine similarity between its mean-pooled embedding and precomputed domain-dataset embeddings (falling back to a base model below a threshold), build a DAG, then topologically schedule ready nodes in parallel subject to GPU availability. Append each expert response as context to dependent nodes and give only the original query plus leaf responses to a final instruction-tuned aggregator.
- **Numbers**: Evaluated on 4×80GB A100s; decomposer trained 10 epochs on 1,000 examples, experts trained 1 epoch with LoRA, router threshold 0.7. Decomposer F1 was 0.87 on HotpotQA and 0.86 on MuSiQue versus 0.48 and 0.42 for Llama 2 few-shot prompting. Comp-LLM reported up to 11.01% accuracy improvement, 1.67×–3.56× model-size reduction, and 1.1×–1.7× latency improvement versus sequential sub-query processing. On 2-expert MultiExpertQA-All, Llama-based Comp-LLM (35B) scored 0.78 versus Llama 2 34B at 0.69 and Llama 2 70B at 0.79; on one A40, it took 108.78 s/example versus 4.12 s for Llama 2 7B, 4.64 s for 13B, and 892.07 s for CPU-offloaded 70B.
- **Token-cost implication**: Decompose only static multi-domain tasks, route each sub-query to one small relevant expert, and execute independent DAG branches concurrently; the approach saves model memory, but multiple generation and aggregation calls can still cost more and run slower than a small monolith.
- **Caveats**: Purdue-authored self-report on synthetic MultiExpertQA-P/All benchmarks built with GPT-4o from Chemistry, Biology, and Math data; no token counts, API prices, energy, or dollar savings. The strongest latency comparison is distorted by CPU offloading of the 70B baseline, while Comp-LLM remains much slower than 7B/13B models. It requires sufficient domain experts, applies only when dependencies can be planned statically, and suffers error propagation from wrong upstream answers.
- **Topic**: routing
