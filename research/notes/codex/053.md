# 053 — Run long horizon tasks with Codex
- **Source**: https://developers.openai.com/blog/run-long-horizon-tasks-with-codex (OpenAI, 2026-02)
- **Claim**: A Codex session using GPT-5.3-Codex at Extra High reasoning stayed coherent through a long, greenfield design-tool build when the target, milestones, validation commands, and project status were externalized in repository files. The author presents durable project memory plus repeated plan–edit–test–repair loops as the key to long-horizon execution.
- **Mechanism**: Store the immutable specification and “done when” checks in `Prompt.md`, break work into validated milestones in `Plan.md`, put scope and execution rules in `Implement.md`, and continuously update decisions and status in `Documentation.md`. At every milestone the agent runs tests, lint, and typecheck, repairs failures before advancing, and uses repository state, tool output, and worktrees as external memory that survives a long conversation.
- **Numbers**: The experiment ran about 25 hours uninterrupted, used about 13M tokens, and generated about 30,000 lines of code. The article cites a rough 7-month doubling time for software-task horizons at approximately 50% and 80% reliability. The resulting prototype included canvas editing, cross-tab collaboration, inspector and layers controls, snapping, history and replay, prototype flows, comments, and JSON plus React/Tailwind export.
- **Token-cost implication**: For a large agent task, spend tokens on a stable written spec and milestone-specific validation so the agent can recover from failures without repeatedly rediscovering intent; isolate parallel runs with worktrees and preserve only decision/status state needed for the next loop.
- **Caveats**: This is a self-reported OpenAI experiment, not a production rollout or controlled benchmark. It used a blank repository, one model at Extra High reasoning, and no comparator, success rate, quality score, dollar cost, cache data, or independent review; the author explicitly says the result was not perfect or production-ready.
