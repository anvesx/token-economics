# 187 — Accelerating LLM Inference with Prompt Caching for Open-Source Models on Databricks
- **Source**: https://www.databricks.com/blog/accelerating-llm-inference-prompt-caching-open-source-models-databricks (Databricks, 2026-05)
- **Claim**: Databricks added automatic prompt caching for open-weight models across batch, pay-per-token and provisioned workloads, reporting a production throughput and latency gain on GPT-OSS.
- **Mechanism**: Identical prompt prefixes reuse KV cache so prefill is skipped on a hit. Implicit with no configuration; caches are isolated, held only in volatile memory and never persisted. Supported: GPT-OSS 20B and 120B, Gemma 3 12B, fine-tuned Llama 3.1 8B (PEFT serving), Llama 3.1 8B and 3.3 70B; also applies to services built on them (Agent Bricks, Genie, AI Functions).
- **Numbers**: In one large-scale production batch-inference pipeline on GPT-OSS: per-replica input-token throughput 2.5x, P50 latency 3x lower, at a cache hit ratio of 30%. No price discount stated.
- **Token-cost implication**: Even a modest hit ratio (30%) raised throughput per replica, so share a long stable system prompt across requests; higher throughput per replica means fewer replicas for the same load on self-hosted or provisioned capacity.
- **Caveats**: Vendor self-reported single pipeline, no baseline or methodology detail; no dollar pricing for cached tokens; rollout to other models pending.
- **Topic**: caching
