# 169 — Evaluating models with Inspect
- **Source**: https://huggingface.co/docs/inference-providers/en/guides/evaluation-inspect-ai (Hugging Face, date not stated)
- **Claim**: Guide to running Inspect (UK AI Security Institute's eval framework) against models through Hugging Face Inference Providers, including comparing models, providers and provider-selection policies.
- **Mechanism**: Write an Inspect Task (dataset, solver generate(), scorer model_graded_fact()), run with inspect eval or inspect eval-set using model ids prefixed hf-inference-providers/. Append a provider suffix (e.g. :groq) or a policy suffix: :fastest (highest throughput, the default), :cheapest (lowest price per output token), :preferred (your settings order). eval_set can sweep providers in Python. Custom VLM eval uses an HF dataset with images resized to 1024x1024 thumbnails.
- **Numbers**: Same model openai/gpt-oss-120b on a small theory-of-mind benchmark, score by provider: fireworks-ai 0.82, nscale 0.82, scaleway 0.81, together 0.81, cerebras 0.80, novita 0.80, groq 0.80. VLM animal-count task accuracy: Qwen/Qwen3-VL-8B-Instruct 0.7 vs Qwen/Qwen3-VL-30B-A3B-Thinking 0.9. For :fastest vs :cheapest the text says only that on this tiny benchmark the fastest provider scored better accuracy and was significantly faster (no figures given). No dollar prices.
- **Token-cost implication**: Before switching to a cheaper provider or smaller model, run your own eval across the candidates, since the same model scored differently by provider (0.80 to 0.82 here) due to inference implementation, hardware and batching. Choose :cheapest only after checking quality, as this doc gives a single case where fastest was more accurate.
- **Caveats**: Tiny benchmarks, differences of 0.01 to 0.02 are likely within noise (not stated by source); the same model grades its own output via model_graded_fact. Vendor tutorial, not a rigorous cost study; no latency or price numbers reported.
