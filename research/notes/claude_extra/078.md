# 078 — A Vector Storage Engine for Scalable Long-Context LLM Inference (RetroInfer)
- **Source**: https://arxiv.org/abs/2505.02922 (arXiv; Microsoft Research with USTC, Tsinghua, Wuhan Univ., SJTU authors, 2025-05)
- **Claim**: RetroInfer treats the KV cache as a vector store: it offloads KV to CPU memory, builds a clustering-based "wave index", and retrieves only the important tokens per decode step, with a "wave buffer" managing GPU/CPU data. It matches full-attention accuracy while raising long-context decoding throughput.
- **Mechanism**: Wave index splits attention into three zones: a steady zone (4 sink + 64 local tokens, always on GPU), a retrieval zone (top clusters, exact attention on their KV fetched from CPU) and an estimation zone (remaining clusters approximated from centroid plus summed values weighted by cluster size, with an accuracy bound). Clusters come from segmented k-means (8K-token segments, 10 iterations, about 1 centroid per 16 tokens) via a Triton kernel; a modified FlashAttention kernel merges the three outputs. Wave buffer keeps a GPU KV block cache (LRU, 5% of KV vectors, 2KB blocks) plus an execution buffer, a mapping table updated asynchronously, and custom CUDA copy kernels (about 1,000 LoC). During prefill, KV is offloaded to CPU asynchronously while the GPU clusters, so only clustering is on the critical path. Training-free; per-head, so it scales across GPUs.
- **Numbers**: Test bed: A100 80GB, PCIe 4.0 x16 (32GB/s), 1.7TB CPU RAM; models Llama3.1-8B, Qwen2.5-7B, Llama3-8B-1048K, Qwen2.5-72B (8 GPUs). Retrieval budget 1.8% (150 of 8192 clusters at 128K); estimation zone 23.2% of clusters; zones cover about 25% of context. RULER at 128K: drop vs full attention of 0.66% / 1.50% / 1.97% / 0.73% (Llama3.1-8B / Qwen2.5-7B / Llama3-8B-1048K / Qwen2.5-72B); 1.40% to 46.47% better than sparse baselines. NIAH: 100% up to 1M tokens. Decoding throughput vs full attention: 4.1x, 4.4x, 4.4x at 30K, 60K, 120K context; 3.3x to 22.8x over sparse baselines; at 1M context full attention and Quest run out of memory, RetroInfer is 10.5x over MagicPIG and 12.2x over PQCache. Across tasks 3.4-4.6x over full attention; across models 2.4x-24.4x over baselines. Prefill latency 6% (120K) and 3% (1M) above full attention; offloading adds 0.4%; segmented clustering under 5% of prefill. With XAttention / MInference, 1M prefill about 600s / 220s. End-to-end (120K in / 4K out) 1.8-7.8x throughput at equal latency (2.1-10.5x with XAttention); (512 in / 32K out) 2.7-70.8x. Reasoning pass@8 (32K max gen), AIME24 / GPQA, first row of each model block read as full attention: DeepSeek-Llama 73.30/68.00 full vs 76.70/68.00 RetroInfer (Quest 46.70/50.00, InfiniGen 36.70/62.00, PQCache 30.00/58.00); DeepSeek-Qwen 76.70/72.00 full vs 73.30/68.00 RetroInfer (Quest 46.70/62.00, InfiniGen 60.00/66.00, PQCache 13.33/46.00). Estimation adds up to 20% accuracy; segment 8K vs 128K global k-means: under 1% recall drop, 80% less index build time.
- **Token-cost implication**: For self-hosted long-context serving, KV memory, not compute, caps batch size. Offloading KV to CPU with a cluster index lets one GPU serve roughly 4x the decode throughput at 30K-120K context and run 1M-token contexts that otherwise OOM, lowering cost per generated token. Keep a small exact retrieval budget plus a larger cheap estimation zone rather than raising the retrieval budget, since retrieval costs PCIe bandwidth.
- **Caveats**: Authors' own measurements on A100 with open models; not independent. Gains need CPU memory and PCIe; at low load or small batch it is slightly slower than GPU-only full attention (a GPU-only variant is offered). MagicPIG excluded from reasoning and long-output tests (no index update). Only 50 GPQA examples sampled. Does not apply to API-priced models. Reasoning table row labels were inferred from garbled PDF extraction (first row unlabeled).
