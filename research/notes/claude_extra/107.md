# 107 — AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration
- **Source**: https://arxiv.org/abs/2306.00978 (arXiv; MIT, NVIDIA and others, Ji Lin, Jiaming Tang, ..., Song Han; MLSys 2024 Best Paper; file is v6; 2023-06)
- **Claim**: AWQ is a weight-only post-training quantization method (W4A16, W3) that protects the roughly 1% of weight channels that matter most, chosen by activation magnitude, and so keeps accuracy at 3-4 bits. The TinyChat inference system turns the 4x weight-memory cut into measured decode speedups on GPUs, CPUs and edge devices.
- **Mechanism**: Salient channels are found from the activation distribution, not weight magnitude (weight-based selection performs like random selection). To avoid mixed-precision kernels, AWQ scales salient input channels up before quantization, Q(w*s)(x/s), and fuses the 1/s into the previous operator. The scale is s = s_X^alpha, with s_X the per-channel average activation magnitude; alpha is grid-searched over [0,1] (grid size 20) to minimize layer output error ||Q(W diag(s))(diag(s)^-1 X) - WX||. Weight clipping minimizes MSE. Calibration uses a small set from the Pile, with no backprop or regression. Group size 128 throughout. TinyChat: on-the-fly dequantization fused into the matmul kernel (no dequantized weights written to DRAM), SIMD-aware 4-bit weight packing (ARM NEON: 32 weights per 128-bit register ordered w0,w16,w1,w17,...; GPU: w{0,2,4,6,1,3,5,7}), kernel fusion (layernorm, fused QKV, on-the-fly positional embedding, preallocated KV cache updated inside the attention kernel), PyTorch frontend, CUDA/PTX, Neon, AVX backends.

- **Token-cost implication**: If you self-host open models, serve 4-bit AWQ weights for batch-1 or low-batch decode: weights shrink 4x, so a given GPU fits larger models or cheaper hardware and decode tokens/s rises up to about 3x. Pair it with fused kernels (TinyChat or a serving stack with AWQ kernels), since the gain comes from the kernels as much as the format. Use a small generic calibration set; no retraining is needed.
- **Caveats**: Self-reported by the authors. Perplexity is the main quality metric; downstream checks (GSM8K, MBPP, VLM suites, Vicuna GPT-4 judge) are limited to a few open models. Speedups are for batch size 1 on-device decode, memory-bound; the paper does not show large-batch server throughput. Does not apply to hosted API pricing.
