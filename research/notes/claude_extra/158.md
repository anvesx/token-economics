# 158 — Understanding intelligent prompt routing in Amazon Bedrock
- **Source**: https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-routing.html (Amazon Web Services, date not stated)
- **Claim**: Bedrock offers a single serverless endpoint that routes each request between two models in the same family by predicting which gives the best response quality at lowest cost.
- **Mechanism**: For each request the system analyzes the prompt, predicts the response quality of each model in the router, and forwards to the chosen one; the response reports which model was used. A configured router has exactly two models from the same family, a fallback model (the anchor) and a routing criterion, responseQualityDifference. Example in the text: with a 10% difference and Nova Lite as fallback, the router switches to Nova Pro only if Pro's predicted quality is more than 10% better than Lite's. Created via console Prompt Routers hub or CreatePromptRouter / aws bedrock create-prompt-router (example uses --routing-criteria '{"responseQualityDifference": 0.5}'). Default routers use select Amazon Nova and Meta Llama models (Nova Lite, Nova Pro, Llama 3.1 8B and 70B, Llama 3.3 70B), varying by Region.
- **Numbers**: none beyond the example thresholds (10% in prose, 0.5 in CLI sample). No cost-savings percentage or latency figure is given.
- **Token-cost implication**: A managed router is available if you want cheap-vs-strong model selection without writing orchestration; start with default routers, then configure your own and evaluate quality in the playground. Review router metrics regularly to pick up new models. You cannot tune it on your own performance data, so measure outcomes yourself.
- **Caveats**: Vendor documentation with no benchmark or savings data. Optimized only for English prompts; cannot adjust decisions from application-specific performance data; effectiveness depends on its initial training data; exactly two models per router, same family.
- **Topic**: routing
