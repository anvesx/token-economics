# 218 — Models, usage, and limits in Claude Code
- **Source**: https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code (Anthropic, date not stated)
- **Claim**: Help-center guide to how Claude Code usage is metered by sign-in type and five habits that reduce token consumption: clear between tasks, match model to job, reference files by path, keep CLAUDE.md lean, and plan before large changes.
- **Mechanism**: Each turn resends the whole conversation, project context (CLAUDE.md and files read) and the new prompt; the conversation grows fastest. /clear wipes chat history (CLAUDE.md stays); /compact summarizes and frees space (auto-compacts near the limit); /context inspects loaded context; /cost shows session spend for API billing; /model switches models mid-session without losing the conversation; /model opusplan uses Opus for planning and Sonnet for execution. Enterprise seats get a pool of usage on a rolling window; API keys are pay-as-you-go with no hard stop. The @ prefix injects the whole file plus its CLAUDE.md tree, so a bare path saves tokens. CLAUDE.md is prepended every turn but billed at the cache-read rate after the first turn; it still occupies context window.
- **Numbers**: CLAUDE.md under roughly 200 lines. Trim logs to 20-30 lines. A plan costs "a few hundred tokens" versus thousands for a wrong 400-line diff regenerated twice. Opus costs "several times more per turn" than Sonnet, and Sonnet more than Haiku (no exact ratio). No prices.
- **Token-cost implication**: Run /clear on task switches, default to Sonnet and reserve Opus for hard problems, reference files by path, trim pasted logs, keep CLAUDE.md small, require a file-level plan before multi-file changes, and plan with Opus then execute with Sonnet.
- **Caveats**: Vendor guidance with rules of thumb, not measurements; ratios and the 200-line figure are approximate.
- **Topic**: agent-cost
