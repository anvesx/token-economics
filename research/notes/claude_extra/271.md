# 271 — Context engineering: memory, compaction, and tool clearing (Claude cookbook)
- **Source**: https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools (Anthropic, 2026-03)
- **Claim**: A cookbook that runs one long-running research agent (8 synthetic ~41K-token documents, ~329K tokens total) with three first-party context primitives: server-side compaction, tool-result clearing, and the client-side memory tool. Each one targets a different kind of context growth and caps peak context at roughly half of the 335K baseline.
- **Mechanism**: Compaction (`compact_20260112`, beta `compact-2026-01-12`) fires at a token threshold (default 150K, minimum 50K), has the model summarize the transcript, and returns a `compaction` block that you send back so the API drops everything before it; `instructions` replaces the default summary prompt entirely. Clearing (`clear_tool_uses_20250919`, beta `context-management-2025-06-27`) is a mechanical edit with no inference: past a trigger (default 100K) it replaces old `tool_result` bodies with a placeholder, keeps the `tool_use` record, keeps the last `keep` results (default 3), and has `clear_at_least` and `exclude_tools` knobs. `clear_thinking_20251015` does the same for thinking blocks and must be first in the edits array. Memory (`memory_20250818`) is client-side: the model issues view/create/str_replace/insert/delete/rename calls and you implement file storage; an injected system prompt tells it to view /memories first. Response field `context_management.applied_edits` reports what was cleared.
- **Numbers**: Corpus ~328,955 tokens (8 docs, ~41,0xx-41,260 each); model claude-sonnet-5-5. Baseline peak ctx 335,279. Compaction run (trigger 180,000): peak 169,164, ~2,783-token summary, 7 turns, final ctx 5,829. Clearing run (trigger 30K, keep=4): peak 173,137, 4 clearing events each freeing ~162,930-163,817 tokens. Toy clearing demo: ~128,740 to ~43,060 tokens (67% reduction). Memory: Session 2 without memory read all 8 docs, 9 turns, peak ctx 333,977; with memory, 6 turns, peak ctx 172,623, and the memory file cost ~2,707 tokens to view. Earlier models cap at 200K and hard-fail above it. No dollar figures given.
- **Token-cost implication**: Diagnose which kind of growth you have first. Re-fetchable tool output (file reads, API responses): use clearing, which is free and lossless because the agent can re-call the tool. Dialogue and reasoning that cannot be re-fetched: use compaction, which costs one summarizer inference. Cross-session knowledge: have the agent write to memory so a later session skips re-reading. Set `clear_at_least` high enough to be worth the prompt-cache invalidation, since each clearing makes the next request write a new cached prefix. Write notes before clearing fires, or the agent will re-read documents. Replace the compaction prompt with one naming the specifics you cannot lose.
- **Caveats**: Self-reported by Anthropic on a synthetic corpus and a single run per configuration; no cost in dollars, no repeat runs or variance, and no accuracy scoring of the final answers. The compaction probe states high-level facts usually survive while obscure appendix cells usually do not, but the exact probe counts are not in the text I read. Clearing run used a trigger of 30K for demonstration, not a recommended value. The memory handler is a sample with path-traversal guards only.
