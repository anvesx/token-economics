# 075 — Cache Me If You Must: Adaptive Key-Value Quantization for Large Language Models
- **Source**: https://arxiv.org/abs/2501.19392 (arXiv, Shutova, Malinovskii, Egiazarian et al., 2025-01, v4 28 Feb 2025)
- **Claim**: AQUA-KV compresses the KV cache to about 2-2.5 bits per value with under 1% relative error in perplexity and LongBench on Llama 3.2, by predicting each layer's keys and values from the previous layer and quantizing only the unpredictable residual.
- **Mechanism**: Per layer, a small linear predictor guesses keys from the previous layer's reconstructed keys, and values from the previous layer's reconstructed values plus the current layer's reconstructed keys; only the quantized residual (true minus predicted) is stored. Layer 1 is quantized on its own (4-bit HIGGS default for Llama). Predictors are fit by closed-form linear regression, one layer at a time on reconstructed (de-quantized) inputs, using 256 RedPajama sequences of 8192 tokens (224 train, 32 holdout). Backbone quantizer is pluggable (HIGGS: Randomized Hadamard Transform + vector quantization grid, group size 1024; or Quanto round-to-nearest, group size 64). Compression is pre-RoPE and per-token. First 4 tokens (attention sinks) stay uncompressed; a recent-token buffer of up to r=128 tokens stays uncompressed and is quantized in blocks when full. Only one layer is de-quantized at a time. Can be combined with H2O token pruning.
- **Numbers**: Llama 3.2 3B, 2-bit: AQUA-KV(HIGGS) 2.09 bits, WikiText-2 PPL 7.03 vs 6.98 uncompressed, LongBench avg 44.30 vs 44.61 (Table 2); HIGGS alone 2.02 bits PPL 7.47, LongBench 42.80; KIVI 2.25 bits PPL 9.34, LongBench 39.64; KVQuant 2.33 bits PPL 9.43, LongBench 20.56. Llama 3.1 8B: 2.08-2.09 bits, PPL 5.72 vs 5.61, LongBench 47.77 vs 48.13. Llama 3.1 70B: 2.04-2.09 bits, PPL 2.62 vs 2.54, LongBench 52.79 vs 52.92. Qwen 2.5 3B and 7B at 2 bits: LongBench 38.31 and 46.43 vs 38.80 and 46.82 uncompressed (their AQUA-KV is 2.44 and 2.48 bits because the first block is not quantized). KV cache for Llama 3.1 70B at 131K tokens, batch 1: 40 GiB uncompressed (text elsewhere: 42.9 GB per sequence for Llama 3.1 70B and Qwen 2.5 72B, 15 GB for Llama 3.2 3B). Predictors for Llama 3.x 70B need at least 500x fewer FLOPs per token than the base model. Calibration: about 4 hours on one GPU, at most 16GB VRAM, for 70B (abstract: 1-6 hours). Speed on 2-bit HIGGS: 8B on one A100 24.02 tok/s vs AQUA-KV 23.31; 70B on 2xA100 5.91 vs 5.76 tok/s (about 3% slowdown, unoptimized PyTorch). H2O keeping 20% of tokens: 5.0x memory saved, LongBench 3B 38.82; H2O+AQUA-KV 38.3x saved, 38.43 (3B), 40.88 (8B); H2O+HIGGS 39.6x saved, 37.02 (3B), 40.53 (8B). Predictor size for 3B: linear 162 MiB, MLP 540 MiB, RRR 68 MiB, GPTQ-4bit 41 MiB. Ablations (3B, 2-bit): no K predictor PPL 7.50, LongBench 42.92.
- **Token-cost implication**: If self-hosting long-context serving, KV cache memory (not weights) is the limiter; 2-bit predictor-assisted KV quantization cuts cache roughly 8x versus 16-bit at about 1% accuracy loss, allowing longer contexts or larger batches per GPU. Not relevant to API pricing directly; matters for self-hosted cost per token.
- **Caveats**: Academic preprint, authors' own benchmarks. Tested only Llama 3.x and Qwen 2.5 (up to 70B), WikiText-2 perplexity and LongBench; no throughput gains shown (it is about 3% slower than the plain quantizer); no integration with vLLM or optimized kernels; needs one-time calibration per model; PPL measured on base models and LongBench on instruct models. Quanto-backed AQUA-KV is much worse than HIGGS-backed at 2 bits (PPL 10.33).
