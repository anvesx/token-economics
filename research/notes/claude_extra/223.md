# 223 — How Prompt Caching Works (xAI)
- **Source**: https://docs.x.ai/developers/advanced-api-usage/prompt-caching/how-it-works (xAI, 2025-03; page last updated March 16, 2026)
- **Claim**: xAI's prompt cache matches the beginning of the messages array against previous requests and serves the matching prefix from cache at a reduced billing rate.
- **Mechanism**: The system checks how many leading messages match a previous request exactly; that matching portion is the prefix and is served from cache. First request processes and caches the full prompt; later requests with the same prefix get a cache hit and only the new messages are computed. Example: system + user + assistant messages from request 1 are cached in request 2, and only the new user message is computed. The x-grok-conv-id header is recommended to maximize hit rate.
- **Numbers**: none (no price or hit-rate figures on this page; says cached tokens are billed "at a reduced rate").
- **Token-cost implication**: Keep stable content (system prompt, earlier turns) at the start of the messages array and append new content at the end. Send x-grok-conv-id on every request in a conversation. Do not rely on caching being guaranteed.
- **Caveats**: Vendor documentation. Caching is explicitly not 100% guaranteed: entries can be evicted under memory pressure and requests may route to different servers. No discount rate or minimum prefix length is given on this page.
- **Topic**: caching
