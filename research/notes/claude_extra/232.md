# 232 — Token & Cost Tracking (Langfuse)
- **Source**: https://langfuse.com/docs/observability/features/token-and-cost-tracking (Langfuse, no date)
- **Claim**: Langfuse records usage and USD cost per usage type for every generation, either ingested from the provider response or inferred from model definitions with prices, and supports pricing tiers.
- **Mechanism**: Each generation/embedding observation stores usage_details (units per type) and cost_details (USD per type). Cost is ingested (takes priority) or inferred by matching the generation's model against a model definition via a regex match_pattern, then multiplying per-type prices by usage; user-defined models take priority over Langfuse-maintained ones. Pricing tiers have a name, priority (0 is default), conditions (regex-summed usage details with gt/gte/lt/lte/eq/neq, top-level model parameter, or metadata key match; all conditions must match) and prices; the first matching tier in priority order is used. Usage keys are mutually exclusive buckets: input excludes input_* (e.g. cached), output excludes output_*, total is their sum; inclusive provider counts (OpenAI) must be converted. Langfuse no longer estimates tokens from text. OpenTelemetry gen_ai.usage.* has cache reads/writes subtracted from input; an OpenAI-style usage object with any extra key is stored flat without subtraction.
- **Numbers**: Example conversion: OpenAI-style 17,903 prompt tokens with 17,817 cached and 188 completion tokens, total 18,091, is stored as input 86, input_cached_tokens 17,817, output 188, total 18,091. Pricing-tier examples: Claude Sonnet 4.5 and Gemini 2.5 Pro have higher pricing above 200K input tokens (tier condition input > 200000). Example cost_details assume 1 USD input, 1 USD output, 0.5 USD cache_read (illustrative only).
- **Token-cost implication**: Report cached and reasoning tokens as separate non-overlapping buckets or cost will be double counted. Capture provider-reported usage rather than estimating, model long-context and fast/priority tiers explicitly, and add custom model definitions for self-hosted or fine-tuned models. Use dashboards, alerts and the Metrics API on this data.
- **Caveats**: Vendor documentation. Price updates apply only to generations ingested after the change; stored costs are not recalculated. Self-hosted instances use the prices shipped with their version. Cost is only tracked for generation and embedding observations.
- **Topic**: observability
