# 198 — Cost optimization
- **Source**: https://developers.openai.com/api/docs/guides/cost-optimization (OpenAI, date not stated)
- **Claim**: Short OpenAI API guide listing three ways to cut cost and latency (fewer requests, fewer tokens, smaller model) and pointing to Batch API and flex processing.
- **Mechanism**: Reduce requests; minimize input tokens and shorten outputs; choose a smaller model that keeps accuracy. Batch API: collect requests into a file, start an asynchronous job, poll status and retrieve results. Flex processing: significantly lower cost for Chat Completions or Responses requests in exchange for slower responses and occasional resource unavailability, suited to evals, data enrichment and asynchronous workloads. Nearly all of the file text is site navigation; the guide itself is a few paragraphs.
- **Numbers**: none (the page says "significantly lower costs" for flex without a percentage; no Batch discount stated).
- **Token-cost implication**: Route non-urgent work to Batch or flex processing and cut request count and tokens first; a pointer to prompt caching is in the navigation only.
- **Caveats**: Vendor overview with no figures; details live in the linked Batch, flex and latency guides, which were not part of this document.
- **Topic**: pricing
