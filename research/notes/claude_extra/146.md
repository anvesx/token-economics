# 146 — Calculate Provisioned Throughput requirements
- **Source**: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/provisioned-throughput/measure-provisioned-throughput (Google Cloud documentation, last updated 2026-11-07)
- **Claim**: Provisioned Throughput on Google's Gemini platform is sized in generative AI scale units (GSUs) using per-model burndown rates that convert input and output tokens into a common unit; cached tokens burn down at a reduced rate.
- **Mechanism**: throughput_per_second = (inputs_per_query + outputs_per_query) * queries_per_second, where each modality's tokens are multiplied by its burndown rate. GSUs needed = total tokens per second / throughput per GSU, rounded up to the model's minimum purchase increment. Provisioned traffic is prioritized over on-demand, unused throughput does not accumulate or carry over to the next month, and a purchase is tied to one project-region-model-version combination. Implicit and explicit caching are supported; the cache discount is applied as a lower burndown rate.
- **Numbers**: Gemini 2.5 Pro: 1 input text token = 1 token, 1 cached input text token = 0.1 tokens (1,000 cached tokens burn 100 tokens/sec). Gemini 3.6 Flash: 675 tokens per GSU, minimum increment 1 GSU; input text/image/video/audio token = 1, cached input tokens of those types = 0.1, output text response token = 5. Worked example: 10 QPS, 1,000 text + 500 audio input tokens, 300 output tokens: 1,500 + 1,500 (300 x 5) = 3,000 tokens/query, x 10 = 30,000 tokens/sec, / 675 = 44.44, so buy 45 GSUs.
- **Token-cost implication**: Output tokens count 5x input for Gemini 3.6 Flash capacity planning, so shortening outputs frees more capacity than trimming inputs; high cache hit rates cut reserved capacity needs by up to 90% on the cached portion. Size GSUs from token mix, not requests per minute.
- **Caveats**: Vendor documentation; the caching feature is labeled Preview (Pre-GA) on this page; no dollar price per GSU given; the doc itself notes that uncached similar queries burn more throughput.
