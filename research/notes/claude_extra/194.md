# 194 — Using Codex with your ChatGPT plan
- **Source**: https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan (OpenAI, date not stated; page says "Updated: 5 days ago")
- **Claim**: Help-center guide to Codex under ChatGPT plans, covering availability, shared usage allowances and credits, enterprise token-based billing, and what to do when limits are hit.
- **Mechanism**: Codex usage draws on a shared allowance and credit pool with ChatGPT Work, ChatGPT for Excel and Workspace Agents; usage depends on model, where the task runs, task complexity, context, reasoning, speed and tools, and long-running tasks can use substantially more than short requests. Enterprise token-based agreements bill in USD instead of deducting credits. Auto-review (a separate reviewer approving actions) is free and does not count toward plan limits when signed in with ChatGPT. Cloud environments have no separate VM charge at launch. Usage windows: 5-hour and weekly; /status in the CLI and Settings > Usage show limits; admins can set workspace model defaults (model, reasoning level, speed, Fast Mode on by default). If a limit is reached mid-turn, Codex can finish the turn subject to fair use. If "Context automatically compacted" repeats without progress, start a new chat with a short summary; this does not reset usage.
- **Numbers**: none (no limits or prices stated; refers to chatgpt.com/pricing). GPT-5.4 and GPT-5.4 mini were removed from Codex under ChatGPT sign-in as of August 31, 2026 (replaced by GPT-5.6 Terra and GPT-5.6 Luna); API unaffected. CLI 0.149.0 and later drops approval_policy "untrusted".
- **Token-cost implication**: In subscription-metered agents, cost tracks context size, reasoning level and task length, not just request count. Use per-chat credit visibility and enterprise analytics to find high-usage chats, set admin default model and reasoning level, and restart a stuck compaction loop in a fresh chat with a summary.
- **Caveats**: Vendor help article with no quantitative limits; dollar values are described as planning estimates, not invoices. Describes product behavior, not measured savings.
