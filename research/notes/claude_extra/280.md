# 280 — Context caching overview (Vertex AI)
- **Source**: https://cloud.google.com/vertex-ai/generative-ai/docs/context-cache/context-cache-overview (Google, 2026-05; page last updated 2026-11-07)
- **Claim**: Google documents two caching modes for Gemini on its agent platform. Implicit caching is on by default and gives a 90% discount on cached tokens. Explicit caching is manual, guarantees the discount for referenced content, and adds storage costs.
- **Mechanism**: Implicit caching stores prefixes in an in-memory tier and a durable tier (evicted in-memory prefixes move to durable storage); both are on by default, a prefix lives at most 24 hours, and either tier can be disabled. Explicit caching: you create a cache through the API, reference it by resource name in later prompts, and can update the TTL (default 60 minutes) or delete it. `cachedContentTokenCount` in response metadata reports cached input tokens. To raise implicit hit odds, put large common content at the start of the prompt and send similar-prefix requests close together.
- **Numbers**: Implicit cached tokens: 90% discount versus standard input. Explicit: 90% discount on Gemini 2.5 or later, 75% on Gemini 2.0. Cache creation tokens are billed at the standard input price; explicit caches also incur storage cost by duration (no rate given in the text); implicit has no storage cost. Minimum cacheable size: 4,096 tokens for Gemini 3 (with exceptions) and Gemini 4; 6,144 for Gemini 3.0 Flash Preview, 3.1 Pro Preview, 3.7 Flash and 3.8 Flash (implicit only); 2,048 for Gemini 2 family. Max cached blob/text 10 MB. Min TTL 1 minute, no maximum for explicit caches. Durable caching only on Gemini 4 Argon, 4 Argon Cyber Permissive, 3.8 Flash, 3.8 Flash Cyber.
- **Token-cost implication**: Put stable content (system prompt, documents, tool definitions) first and keep it identical so implicit caching applies for free. Use explicit caches for large content reused over a known window, but weigh storage cost against the 90% discount. Prompts below the minimum token count (4,096 or 6,144 on current models) will not cache. Scope caches per user session in multi-tenant agents so cached data is not shared.
- **Caveats**: Vendor documentation, no measured hit rates. Eviction timing is "most entries are evicted earlier" than 24 hours and unquantified. Storage price is not in this page (it points to pricing). Savings apply to input tokens only.
