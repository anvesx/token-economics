# 098 — Generating Structured Outputs from Language Models: Benchmark and Studies (JSONSchemaBench)
- **Source**: https://arxiv.org/abs/2501.10868 (arXiv, 2025-01; EPFL and Microsoft authors)
- **Claim**: JSONSchemaBench is a benchmark of about 10K real-world JSON schemas (9,558 in Table 1) used to compare six constrained-decoding frameworks (Guidance, Outlines, Llamacpp, XGrammar, OpenAI, Gemini) on efficiency, schema coverage and output quality. Constrained decoding can be faster than unconstrained decoding, and coverage differs widely by framework.
- **Mechanism**: Constrained decoding masks tokens that violate a grammar derived from the schema at every step (compute mask, apply to logits, sample). Cost components measured: Grammar Compilation Time (GCT), Time to First Token (TTFT) and Time Per Output Token (TPOT). Guidance computes constraints dynamically (near-zero compile) and fast-forwards tokens that the grammar forces, so it skips model forward passes. XGrammar overlaps compilation with prompt prefill. Outlines converts the schema to a regex, which gives high compile time. Coverage is split into declared (schema accepted without error), empirical (output actually validates) and compliance rate (empirical / declared); also theoretical coverage. Efficiency was computed only on the intersection of schemas all engines cover, to avoid bias toward engines that handle only simple schemas.
- **Numbers**: Setup for efficiency: Llama-3.1-8B-Instruct (Q8) on one A100-80GB, batch size 1, median values, prefix caching on, grammar cache not useful since each schema is unique. Table 2 (llama.cpp backend, GlaiveAI): TPOT LM-only 15.40 ms, Guidance 6.37 ms, Llamacpp 29.98 ms, Outlines 30.33 ms; GCT Guidance 0.00 s, Llamacpp 0.05 s, Outlines 3.48 s; TTFT 0.10 / 0.24 / 0.20 / 3.65 s. GitHub Medium: GCT Outlines 8.05 s, TPOT Guidance 7.57 ms vs LM-only 16.68 ms. Total generation time GlaiveAI: LM-only 1.08 s, Guidance 0.50 s, Llamacpp 1.47 s, Outlines 4.84 s; Guidance fast-forwarded 15.70 of 41.56 output tokens. HF Transformers backend (Table 3, GlaiveAI): TPOT Guidance 36.92 ms vs XGrammar 66.78 ms; GCT XGrammar 0.12 s vs Guidance 0.01 s. Headline claim: constrained decoding speeds generation up to 50% versus unconstrained. Coverage (Llama-3.2-1B, greedy, one sample): GlaiveAI empirical LM-only 0.90, Guidance 0.96, Llamacpp 0.95, Outlines 0.95, XGrammar 0.93, OpenAI 0.89, Gemini 0.86. GitHub Hard empirical: LM-only 0.13, Guidance 0.41, Llamacpp 0.39, Outlines 0.03, XGrammar 0.28, OpenAI 0.09. OpenAI declared coverage is low on harder sets (GitHub Easy 0.30, Medium 0.21, Hard 0.09) but compliance rate is about 1.00. Test suite: Guidance full coverage on 13 categories, Llamacpp 1, XGrammar 1, Outlines 0 (43 categories used). Failure categories: XGrammar under-constrained in 38 categories vs Guidance 1. Quality (Llama-3.1-8B, Table 8): GSM8K LM-only 80.1%, XGrammar 83.7%, Llamacpp 82.4%, Outlines 81.6%, Guidance 83.8%; Last Letters LM-only 50.7%, Guidance 54.0%; Shuffle Objects LM-only 52.6%, Guidance 55.9%. Reported gain up to about 4%.
- **Token-cost implication**: Structured output with a fast engine does not have to cost extra latency, and can cut time per output token because forced tokens are skipped. Pick the engine by schema complexity: engines with low declared coverage silently reject or ignore complex schemas. Check TTFT and compile time if schemas change per request, since Outlines compile took several seconds. Cache compiled grammars when schemas repeat. A "reasoning" field before the answer in JSON kept accuracy, so do not drop reasoning to save tokens without measuring.
- **Caveats**: Authors' own benchmark (Microsoft authors, Guidance is a Microsoft-linked project), so the framework that wins is the authors' own. Open-source engines used Llama models while OpenAI and Gemini used proprietary models, so empirical coverage is not directly comparable. Coverage used one greedy sample with a 1B model. Efficiency was batch size 1 on one GPU. Quality tasks are three simple reasoning tasks. No dollar costs. Text states "50% faster" while the table shows the gain depends on engine and dataset.
