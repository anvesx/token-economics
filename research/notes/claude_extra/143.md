# 143 — Save costs and decrease latency while using Gemini with Vertex AI context caching
- **Source**: https://cloud.google.com/blog/products/ai-machine-learning/vertex-ai-context-caching (Google Cloud, 2025-10-16)
- **Claim**: Vertex AI offers implicit (automatic) and explicit (declared) context caching for Gemini; cached input tokens are billed at 10% of standard input cost for Gemini 2.5 and above.
- **Mechanism**: Serving infrastructure reuses KV states from previous requests. Implicit: on by default for all GCP projects, no API change, retention depends on load and reuse frequency, always deleted within 24 hours; cache writes are charged as standard input tokens. Explicit: the user creates a CachedContent object (one-time fee at standard input cost), then references it in generate_content requests; cached tokens are billed at a 90% discount, plus an hourly per-million-token storage fee based on TTL, prorated to the minute. Minimum cache size is 2,048 tokens, up to the context window (over 1M tokens on Gemini 2.5 Pro). Any modality (text, pdf, image, audio, video). Works with global and regional endpoints, implicit caching integrates with Provisioned Throughput, explicit caches can use CMEK. Hits are visible via cachedContentTokenCount in UsageMetadata.
- **Numbers**: cached tokens = 10% of standard input token cost (Gemini 2.5 and above); minimum 2,048 tokens; implicit caches deleted within 24 hours; storage billed per hour per million tokens (rate not given).
- **Token-cost implication**: Put the repeated content (system prompt, documents, codebase) at the start of the prompt, avoid caching small frequently changing pieces, monitor cachedContentTokenCount, and tune explicit TTL to trade storage cost against recreation cost.
- **Caveats**: Vendor blog, self-reported, no measured savings or latency numbers; storage rate not stated; applies to Gemini on Vertex only.
- **Topic**: caching
