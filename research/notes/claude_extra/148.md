# 148 — Prompt caching with Azure OpenAI in Azure AI Foundry Models
- **Source**: https://learn.microsoft.com/en-us/azure/ai-services/openai/how-to/prompt-caching (Microsoft, last updated 2026-11-06)
- **Claim**: Documents how prompt caching works on Azure OpenAI, including the newer GPT-5.6+ controls (prompt_cache_key, explicit breakpoints, TTL) and the new cache-write charges.
- **Mechanism**: Requests with an identical prefix of at least 1,024 tokens reuse cached input computations; hits appear as cached_tokens in prompt_tokens_details. Pre-GPT-5.6 models: automatic caching, hits in 128-token increments, no cache-write charge, retention via prompt_cache_retention (in_memory or 24h; extended retention offloads KV tensors to GPU-local storage). GPT-5.6 and later: prompt_cache_key improves matching; prompt_cache_options.mode is implicit (default, breakpoint on latest message plus any explicit ones) or explicit (only explicit breakpoints; with none, no caching and no write charges); ttl is 30m (default) or 12h on supported Responses API deployments; prompt_cache_breakpoint {"mode":"explicit"} on content blocks marks the end of a reusable prefix. Usage reports cache_write_tokens alongside cached_tokens. Cached content includes messages, images (same detail setting), tool definitions, and structured output schema (prepended to the system message).
- **Numbers**: Minimum 1,024 tokens, first 1,024 tokens must be identical. In-memory caches typically cleared after 5 to 10 minutes of inactivity, always within 1 hour of last use; extended retention up to 24 hours. Above approximately 15 requests per minute for the same prefix and prompt_cache_key, some requests might miss. Up to 4 new cache writes per request (3 explicit in implicit mode); reads consider the latest 50 breakpoints. Example usage: prompt_tokens 1566, cached_tokens 1408, cache_write_tokens 0, completion 1518, reasoning_tokens 576. Cache reads billed at a discount on Standard deployments (rate not stated; see pricing page). Charges for 12-hour cache writes apply from usage starting November 1, 2026. Provisioned deployments: cached input tokens do not consume PTU capacity before GPT-6.
- **Token-cost implication**: Put stable content first, keep conversation append-only, reuse a stable prompt_cache_key per prefix, and shard keys when one prefix exceeds about 15 requests per minute. On GPT-5.6+, writes can now cost extra, so monitor cache_write_tokens against later cached_tokens reads and use explicit mode with breakpoints only on content that will actually be reused. Pre-5.6 models cannot take these parameters (400 error).
- **Caveats**: Vendor documentation; gives no discount percentages or dollar rates. Applies to Azure OpenAI only; in-memory caches are not shared between subscriptions. No measured hit-rate data.
