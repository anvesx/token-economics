# 105 — TRIM: Token Reduction and Inference Modeling for Cost-Effective Language Generation
- **Source**: https://arxiv.org/abs/2412.07682 (arXiv, JPMorganChase AI Research, 2024-12; v5 24 Nov 2025)
- **Claim**: Prompt the expensive LLM to omit a fixed set of easily inferable function words in its answer, then have a much smaller fine-tuned model (BART, T5, Qwen2.5 0.5B/1.5B) restore them. This cuts generated output tokens by about 19% on average for GPT-4o with small drops in text-similarity metrics.
- **Mechanism**: (1) Rank candidate function words by how easy they are to infer: with RoBERTa, mask each word in 100,000 Wikipedia paragraphs and compute delta P = P(word | context) - P(best alternative | context), average per word, sort descending. (2) Choose the set size by fine-tuning T5 on top-N words (N from 5 to 60 in steps of 5) and watching metrics degrade; they cut at level 5, i.e. 25 words, about 18% saved tokens. (3) Add an instruction (169 extra prompt tokens, "Prompt 2") telling the generator to omit those words and return only the distilled answer. (4) A small encoder-decoder or small decoder-only model, fine-tuned on 100,000 Wikipedia (distilled, original) paragraph pairs, reconstructs the full text. Cost break-even: the saved output tokens times the generator's output price must exceed the instruction input cost plus the reconstruction model's input and output cost (the reconstruction model's cost is treated as negligible, 2 orders of magnitude smaller).
- **Numbers**: Exploratory test, GPT-4o (gpt-4o-2024-08-06), 500 knowledge questions, 23-word set: original answers averaged 22.50 words from the set (sd 5.77), distilled 0.32 (sd 0.62). NaLDA dataset: 44,800 entries over 5 task types (create, knowledge-answer, rewrite, summarize, translate). With GPT-4o as generator and T5 as reconstructor: saved tokens 19.41% (sd 5.84), theta F1 85.51, SacreBLEU 82.92, ROUGE-L 93.96, cosine similarity 99.99, perplexity 31.53 vs 25.59 original. Qwen2.5-1.5B: theta F1 86.10, SacreBLEU 83.99, ROUGE-L 94.10. Distilled text unreconstructed: SacreBLEU 49.25, perplexity 158.66. T5 is 0.223B params, trained 3 hours; Qwen2.5-1.5B trained 18 hours. Saved tokens by generator (T5 reconstructor): GPT-4o 19.41%, GPT-4.1-mini 22.79%, GPT-4.1 19.45%, Claude Sonnet 4 17.83%, Claude Opus 4.1 17.38%. Wikipedia sample: 18.85% saved tokens. Break-even: instruction costs 169 tokens, repaid after 42 omitted tokens (GPT) or 34 (Claude); with the observed savings, answers longer than about 216 tokens (GPT-4o) or about 190 tokens (Sonnet 4) cost less with TRIM. Input/output price ratio used: about 0.25 for GPT, about 0.2 for Claude. Task type: reconstruction is best on knowledge-answer; rewrite, summarize and translate score on average about 5.77% lower. Hardware: AWS g4dn.xlarge, Nvidia T4 16GB.
- **Token-cost implication**: Only worth it for long free-form prose outputs (roughly 200+ tokens); on short answers the 169-token instruction costs more than it saves. Output tokens are the pricier side, so trimming them pays, but the real saving is bounded at roughly 17-23% of output tokens. A builder must run and host a small reconstruction model, and measure the break-even with their own prices.
- **Caveats**: JPMorganChase authors, self-reported, no human evaluation. Savings are token counts; actual dollar savings are only estimated from list-price ratios and an assumption that the reconstruction model is negligible; generator model sizes are estimates from other papers. NaLDA's distilled and ideal answers come from the same session, which the authors admit differs from real use. English only; not tested on conversational, code, or reasoning models (the authors say code would break if one word is wrongly inferred). Does not test the effect of function-word-free text on the generator's own answer quality. Different models save different amounts with the same instructions.
