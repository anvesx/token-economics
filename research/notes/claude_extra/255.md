# 255 — Batch inference (Fireworks)
- **Source**: https://docs.fireworks.ai/guides/batch-inference (Fireworks, 2026-11)
- **Claim**: Fireworks' Batch API processes JSONL datasets asynchronously at 50% off serverless per-token prices, and batch jobs automatically use prompt caching for an additional 50% savings on cached tokens.
- **Mechanism**: Upload a JSONL dataset (each row has a unique custom_id and a body with either messages or pre-tokenized prompt_token_ids, mutually exclusive), create a batch inference job against a batch-compatible model (via UI, firectl or HTTP), monitor state (VALIDATING, PENDING, RUNNING, COMPLETED, FAILED, EXPIRED) and download an output dataset (results file plus error file). A job-level system prompt (--system-prompt / systemPrompt) is injected as a leading system message on rows lacking one, which shrinks the upload and keeps the byte-identical prefix cache-friendly; it cannot be combined with prompt_token_ids and counts toward the context window. For pre-tokenized input set user or prompt_cache_key in the body, otherwise the gateway has nothing to hash for cache affinity and hit rates drop. Expired jobs bill and save completed rows; --continue-from reprocesses only unfinished rows.
- **Numbers**: 50% off serverless per-token prices; additional 50% off cached tokens. Input dataset up to 80 GiB; output dataset max 8GB (job may expire early if reached). Job expiration 12 to 72 hours, default 24 hours (values outside clamped). Job stuck "creating" over 30 minutes: contact support. Out-of-vocabulary token IDs fail a row with a terminal 400.
- **Token-cost implication**: Run offline workloads (labeling, synthetic data, distillation data, evals, document processing) as batch jobs, put static content first in each prompt, and set the shared system prompt once at job level so caching still applies. Set sensible max_tokens. Verify the model supports batch before submitting.
- **Caveats**: Vendor documentation with no measured savings or latency data. Unsupported models may sit in pending without an error. Unlike the Groq batch API, this page states caching savings stack with the batch discount. Newly added models may lag in support.
- **Topic**: pricing
