# 229 — How OpenRouter rebuilt provider routing for better, faster inference
- **Source**: https://openrouter.ai/blog/announcements/how-we-rebuilt-provider-routing (OpenRouter, 2026-10-28)
- **Claim**: OpenRouter replaced its mostly price-only default provider routing with a "Routing Cost" algorithm that blends effective price, latency, throughput, reliability and quality, and reports faster, more reliable inference at a small cost increase.
- **Mechanism**: For each request the router estimates input/output tokens from the model's recent traffic, then computes a Routing Cost per provider: effective price (from measured realized traffic, including real cache hit rate and input/output mix, so cheap input price cannot hide expensive cached or output tokens) plus the cost of waiting (end-to-end throughput and TTFT converted using a per-model rate) plus expected retry cost (if 1 in 5 tries fails you pay for 1.25 tries per good answer), with penalties for 429s, provider errors and malformed tool calls. Traffic is shared among providers inside a competitive edge, with a floor (trickle traffic), back-off for failing providers, and a learned capacity cap that spills excess. Only the first request of a conversation is routed algorithmically; the conversation then stays pinned to that provider to keep the prompt cache warm, with fallback if it becomes unavailable. provider.order bypasses the new router; provider.only/ignore filter candidates; an explicit provider.sort (price, throughput, latency), the :floor slug suffix, or an account default sort of price keeps price-only routing.
- **Numbers**: ~77% of requests go to models served by more than one provider. Switchback experiment: 3-hour blocks, 1-hour burn-in, one week, open-source models, over 24 million requests and 103 billion input tokens split evenly. Legacy vs new: TTFT p50 1,007 ms vs 837 ms (16.9% lower); TTFT p95 4,601 ms vs 3,733 ms (18.9% lower); throughput p50 62.4 vs 72.6 tok/s (16.3% higher); cost per K requests $1.25 vs $1.32 (6.0% higher); cost per M tokens $0.301 vs $0.324 (7.3% higher); whole-request p50 4.00 s vs 3.24 s (19.0% lower); whole-request p95 41.5 s vs 34.9 s (16.0% lower); requests hitting at least one 429 7.1% vs 3.8% (46% fewer); needing a retry 10.4% vs 6.9% (34% fewer); time in failed attempts 349 ms vs 242 ms per request (30% less).
- **Token-cost implication**: Default routing now trades a few percent higher cost for latency and reliability; builders who want the cheapest provider must set provider.sort=price or :floor. Cache-aware pinning means a stable conversation keeps its cache discount, so do not switch providers mid-session. Compare providers on effective price (including cache and output mix), not input list price.
- **Caveats**: Self-reported by OpenRouter; open-source models only; measured one week; the algorithm's cost, latency and reliability weights are not published; providers had not yet adapted. The cost increase is real (6.0% per request).
