# 252 — Groq Batch API
- **Source**: https://console.groq.com/docs/batch (Groq, no date)
- **Claim**: Groq's Batch API runs asynchronous bulk requests at a 50% discount versus synchronous pricing, with a 24-hour to 7-day processing window and rate limits separate from synchronous limits.
- **Mechanism**: Build a JSONL file where each line has a custom_id, method, url (/v1/chat/completions, /v1/audio/transcriptions or /v1/audio/translations) and body in the synchronous request format. Upload through the Files API, create a batch with the file id and completion_window of 24h to 7d, poll status (validating, in_progress, ... completed, expired), then download the output file via output_file_id (errors via error_file_id). Results may come out of order, so match on custom_id. Multiple batches can be submitted at once. Expired batches charge only for completed requests, and unfinished requests can be resubmitted.
- **Numbers**: 50% cost discount versus synchronous API. Files API limit 50,000 lines and 200MB per .jsonl file; suggests splitting very large workloads (e.g. 1,000 requests per batch) for better completion odds; up to 200 batch IDs per status query; input, intermediate and result files stored up to 30 days. Models: openai/gpt-oss-20b, openai/gpt-oss-120b, llama-3.3-70b-versatile, llama-3.1-8b-instant, meta-llama/llama-guard-4-12b (chat); whisper-large-v3 and whisper-large-v3-turbo (transcription); whisper-large-v3 (translation).
- **Token-cost implication**: Move non-interactive work (bulk generation, dataset processing, evals) to batch for half price and to avoid consuming standard rate limits. Do not expect to combine it with prompt caching savings: the batch discount does not stack with caching discounts and all batch tokens bill at the 50% rate regardless of cache status. Use longer windows to reduce expiry risk.
- **Caveats**: Vendor documentation; no completion-time distribution given, only that capacity is best-effort within the window. Limited to listed models. No quality or throughput measurements.
- **Topic**: pricing
