# 133 — Byte Latent Transformer: Patches Scale Better Than Tokens
- **Source**: https://arxiv.org/abs/2412.09871 (Meta AI, 2024-12)
- **Claim**: BLT is a tokenizer-free byte-level LLM that, for the first time, matches tokenization-based (Llama 3) performance at scale while cutting inference FLOPs by up to 50% and improving robustness to noise and character-level understanding.
- **Mechanism**: Encode raw bytes into dynamically sized patches segmented by next-byte entropy from a small byte LM — more compute is spent where data is less predictable. Three transformer modules: a lightweight Local Encoder (bytes→patch reps via cross-attention), a large Latent Global Transformer (operates on patches, consumes most FLOPs), and a lightweight Local Decoder (patches→bytes). Patch boundaries set by a global entropy threshold θg or an approximate-monotonicity constraint (H(xt)−H(xt−1)>θr). Hash n-gram embeddings (n=3..8) augment byte embeddings. Because inference FLOPs are inversely proportional to average patch size and larger patches run the global model less often, model size and patch size can grow together at fixed inference budget — a new scaling axis.
- **Numbers**: Scaling study up to 8B params and 4T training bytes. Up to 50% fewer inference FLOPs than Llama 3 at parity (patch size 8). Llama 2/3 BPE avg token size 3.7/4.4 bytes; BLT uses avg patch size 6 and 8 bytes. BLT-Entropy 8B (4.5 bytes/patch, 4.5T bytes) avg benchmark 61.1 vs Llama 3 (1T tokens) 60.0; BLT-Space (6.1 bytes/patch, 6T bytes) 58.0. BLT-Entropy outperforms Llama 3 on 4/7 tasks. Entropy model 100M params, 14 layers, hidden 512, 512-byte sliding window; diminishing returns beyond 50M params / 512-byte context. Robustness: HellaSwag noise avg BLT 64.3 vs Llama 3 56.9 (8-point advantage), matching Llama 3.1 (64.3, trained on 16T tokens). CUTE benchmark: BLT beats both BPE Llama 3 models by >25 points; 99.9% on both spelling tasks. FLORES-101 translation: BLT +2 BLEU into English, +0.5 from English. Fixed-inference crossover where BLT beats BPE: ~3x→2.5x compute-optimal budget. Context: 8k bytes (Llama2 data), 16k bytes (BLT-1T), 16M-byte batches. Llama 3 vocab 128K. Output tokens priced 3–5x input elsewhere. "Byte-ifying" Llama 3.1 (init global transformer from its weights, 1/10 LR) beats from-scratch BLT at equal FLOPs.
- **Token-cost implication**: A dynamic-compute byte architecture lets builders decouple inference cost from model capacity — grow patch size for ~50% FLOP savings and reallocate to a bigger global model. Eliminating the tokenizer removes multilingual inequity, noise fragility, and lack of orthographic knowledge. For fixed inference budgets, over-train (spend more one-time pretraining) to win.
- **Caveats**: Meta-authored, self-reported. Scaling laws used were derived for BPE transformers (may be suboptimal for BLT). Many ablations only to 1B params. Theoretical FLOP-matched comparison; wall-clock parity with optimized tokenizer codebases not yet achieved. Entropy model trained separately (not end-to-end). BPE still wins at small training budgets and on word deletion/insertion tasks.
