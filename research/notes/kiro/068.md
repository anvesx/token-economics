# 068 — Token-saving updates on the Anthropic API
- **Source**: https://www.anthropic.com/news/token-saving-updates (Anthropic, 2025-03)
- **Claim**: Three Anthropic API updates for Claude 3.7 Sonnet — cache-aware rate limits, simpler prompt caching, and token-efficient tool use — increase throughput and cut token usage/cost with minimal code changes.
- **Mechanism**: (1) Prompt caching stores and reuses frequently accessed context (large docs, instructions, examples) between API calls so the same context isn't resent each request. (2) Cache-aware rate limits: prompt cache READ tokens no longer count against the Input-Tokens-Per-Minute (ITPM) limit for Claude 3.7 Sonnet (OTPM limit unchanged), so caching also raises effective throughput. (3) Simpler cache management: setting a cache breakpoint makes Claude automatically read from the longest previously cached prefix — no manual tracking of which cached segments to use. (4) Token-efficient tool use: enabled via beta header `token-efficient-tools-2025-02-19` (with beta SDK / anthropic.beta.messages), reduces output tokens on tool calls. (5) New `text_editor` tool makes targeted edits to specific portions of text (source code, docs) instead of rewriting, reducing tokens/latency and increasing accuracy.
- **Numbers**: Prompt caching reduces costs by up to 90% and latency by up to 85% for long prompts. Token-efficient tool use reduces output token consumption by up to 70%; average early-user reduction 14%. Features for Claude 3.7 Sonnet. Caching available on Anthropic API and Google Cloud Vertex AI; token-efficient tools and text_editor also on Amazon Bedrock and Vertex AI.
- **Token-cost implication**: For agents/coding assistants that resend large stable context (codebases, knowledge bases, product docs), put that context behind prompt caching and rely on automatic longest-prefix cache reads; combined with cache-aware ITPM limits this both cuts cost (up to 90%) and raises throughput headroom. Turn on token-efficient tool use (one beta header) for tool-heavy workloads, and use text_editor for document/code editing to avoid full-rewrite output tokens. Note cache-read tokens being exempt from ITPM is model/plan-specific (Claude 3.7 Sonnet, Anthropic API).
- **Caveats**: Self-reported by Anthropic; "up to" figures are best-case for long prompts, and the realistic token-efficient-tool average is only 14% (vs up to 70%). Cache-aware ITPM exemption stated only for Claude 3.7 Sonnet on the Anthropic API. Customer spotlight (Cognition/Devin) is a vendor testimonial, not independent measurement. No absolute prices given.
