# 099 — Explaining and Mitigating Crosslingual Tokenizer Inequities
- **Source**: https://arxiv.org/abs/2510.21909 (arXiv / EleutherAI + UC San Diego, NeurIPS 2025, 2025-10)
- **Claim**: Even monolingual tokenizers trained identically (same algorithm, dataset size, vocabulary size) show wide "token premium" differences across languages. Vocabulary size and whitespace pre-tokenization drive these inequities (not train-eval data similarity), and per-language "optimal" vocabulary sizes plus superword tokenizers substantially reduce them.
- **Mechanism**: Train ~7,000 comparable monolingual tokenizers for 97 languages, varying tokenizer type (BPE vs Unigram), vocabulary size (8192–262144), dataset size (300MB, optionally byte-premium-scaled), and whitespace pre-tokenization. Compression measured as Corpus Token Count (CTC) on parallel FLORES-200 text (lower = better; un-normalized token premium). Mitigations: (1) train on parallel data (NLLB) — tests data-similarity hypothesis; (2) per-language "optimal" vocabulary size — fit a power-law curve of CTC vs vocab size per language, pick vocab to hit a target CTC; (3) superword tokenizers (SuperBPE implementation) that allow merges across whitespace boundaries, with a transition point (keep X% of vocab from phase-1 BPE, fill rest with superword merges; default 0.9).
- **Numbers**: ~7,000 tokenizers, 97 languages, 300MB/language, 7 vocab sizes 16384–114688 (extended 8192–262144), all divisible by 128. BP-scaling: no effect on CTC (t(3544)=−0.615, p=0.539). BPE best compression; SentencePiece-Unigram worst. Factor R² (vocab 65536): Data Similarity 0.239, Mean Token Length (vocab) 0.168, Proportion Whitespaces 0.157, Combined 0.297. Byte premiums cited: Burmese 3.51, Dzongkha 3.64, Shan 3.94. Byte vs token premium: tiny negative effect β=−0.0418 (p<0.001), ~3.7% CTC drop per +1 byte premium — opposite of hypothesis; no significant BPE/Unigram interaction (p=0.127). Parallel data: statistically significant but tiny CTC reduction (paired t(152)=−2.356, p=0.0197; ~1% of CTC, mostly at smallest vocab 16384). Vocab size: smallest vs largest vocab variance not significantly different (F96,96=1.125, p=0.565); optimal-vocab tokenizers significantly less CTC variance (F80,387=0.150, p<0.001). SuperBPE: lower avg CTC and less variance at every vocab size; optimal-vocab SuperBPE even less variance (F558,76=3.8727, p<0.001). Optimal-vocab CTC estimation RMSE 3733. Contamination: 72% of languages had zero FLORES examples in training, 98% had <10; Samoan excluded (7155 occurrences). Tokenizers comparable to OLMo (vocab 50279), Pythia (50253), SmolLM (49152).
- **Token-cost implication**: Tokenizer design choices alone create unequal token (hence compute/inference) costs across languages. To cut cost for high-premium languages: use BPE over Unigram; allocate per-language ("optimal") vocabulary sizes rather than one global vocab; and adopt superword/whitespace-crossing tokenizers (SuperBPE), which reduce token premiums AND improve overall compression. Vocabulary size should be a language-dependent design choice; training on parallel data is NOT an effective fix.
- **Caveats**: No language models were trained, so no direct link to downstream model performance (compression affects training/inference cost regardless; English-compression vs performance link is weak per prior work). Small 300MB training data (chosen for low-resource inclusion) may be too little for SuperBPE. Parallel-data experiments limited to 7 languages and English-only baselines. Only FLORES used for eval (translation artifacts possible). Data-similarity measured via token overlap may conflate token diversity. Residual inequities from UTF-8 length ratios and bytes-per-character remain. Academic, self-reported.
- **Topic**: compression
