# 084 — Effective context engineering for AI agents
- **Source**: https://www.anthropic.com/research/effective-context-engineering-for-ai-agents (Anthropic, 2025-09)
- **Claim**: Context engineering — curating the minimal set of high-signal tokens that fit in an LLM's finite attention budget at each step — is the natural successor to prompt engineering for building capable multi-turn agents. The post offers mental models and concrete techniques (compaction, note-taking, sub-agents, just-in-time retrieval).
- **Mechanism**: Treat context as a finite resource subject to "context rot" (recall degrades as token count grows). Anatomy of good context: system prompts at the right "altitude" (not brittle hardcoded logic, not vague), minimal clear tool sets with no overlapping functionality, a few canonical few-shot examples (not an edge-case dump), organized with XML tags/Markdown headers. Retrieval: shift from pre-inference embedding retrieval to "just-in-time" — agents keep lightweight identifiers (file paths, queries, links) and load data at runtime via tools (Claude Code uses head/tail/grep/glob), enabling progressive disclosure; hybrid strategies retrieve some data up front. Long-horizon techniques: (1) Compaction — summarize a near-full context window and reinitialize (Claude Code keeps architectural decisions, unresolved bugs, implementation details + 5 most recent files; tool-result clearing is the lightest form); (2) Structured note-taking / agentic memory — persist notes (NOTES.md, to-do lists) outside context, pulled back later (memory tool in public beta on Claude Developer Platform with Sonnet 4.5); (3) Sub-agent architectures — specialized sub-agents with clean context windows return condensed summaries to a coordinating lead agent.
- **Numbers**: Transformer attention has n² pairwise relationships for n tokens. Sub-agents may each use "tens of thousands of tokens or more" but return condensed summaries of "often 1,000–2,000 tokens." Claude playing Pokémon example: maintained tallies across thousands of game steps (e.g., "for the last 1,234 steps... Pikachu has gained 8 levels toward the target of 10"). No pricing figures or benchmark percentages.
- **Token-cost implication**: Design agents to minimize tokens entering the attention budget each step: keep prompts/tools/examples tight; prefer just-in-time retrieval over loading full data; for long-horizon tasks apply compaction (clear stale tool results first), persist state in external notes, and offload deep exploration to sub-agents that only return distilled summaries. This reduces per-step token cost and mitigates context-rot performance loss.
- **Caveats**: Vendor blog (Anthropic), guidance and self-referential product examples (Claude Code, Claude playing Pokémon, Sonnet 4.5 memory tool); no controlled benchmarks, no cost/latency numbers, no independent measurement. "Context rot" asserted as emerging across all models with gentler degradation in some. Advice is qualitative and evolving as models improve.
