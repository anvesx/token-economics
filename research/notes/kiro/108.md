# 108 — GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers
- **Source**: https://arxiv.org/abs/2210.17323 (arXiv, 2022-10)
- **Claim**: GPTQ is a one-shot, post-training weight quantization method using approximate second-order (Hessian) information that compresses 175B-parameter GPT-class models to 3–4 bits/weight in ~4 GPU hours with negligible perplexity loss, enabling single-GPU inference and end-to-end generation speedups.
- **Mechanism**: Builds on Optimal Brain Quantization (OBQ), which quantizes weights one at a time in a layer and updates remaining weights to compensate (Hessian H = 2XXᵀ). Three key modifications scale it to billions of params: (1) Arbitrary Order — quantize all rows in the same fixed column order so H⁻¹_F is shared across rows, dropping runtime from O(d_row·d_col³) to O(max{d_row·d_col², d_col³}); (2) Lazy Batch-Updates — process B=128 columns at a time, deferring global H⁻¹/W updates to fix the low compute-to-memory ratio and get ~1 order-of-magnitude GPU speedup; (3) Cholesky Reformulation — precompute needed H⁻¹ rows via a stable Cholesky decomposition plus mild dampening (λ = 1% of avg diagonal) to avoid indefinite-matrix numerical blowups on large models. Inference uses a custom quantized-matrix × FP16-vector kernel that dynamically dequantizes weights (no activation quantization), cutting memory movement. Calibration = 128 random 2048-token C4 segments (zero-shot, no task data).
- **Numbers**: Quantizes OPT-175B / BLOOM-176B to 3–4 bits in ~4 GPU hours (OPT-175B 4.2h; BLOOM-176B 3.8h) on one A100-80GB. 2× the compression of prior one-shot methods. OPT-175B 4-bit loses only 0.03 WikiText2 perplexity vs FP16 (8.34→8.37) while RTN drops 2.2 points (→10.54); at 3-bit RTN collapses (7.3e3) but GPTQ holds 8.68. End-to-end speedup vs FP16: 3.25× on A100 (230ms→71ms/token), 4.5× on A6000 (589ms→130ms/token). GPU count reduction: FP16 5×80GB → 1 GPU (3-bit); LLM.int8() 8-bit needs 3 GPUs. 3-bit OPT-175B ≈ 63GB + ~9GB KV cache for 2048 tokens. Extreme: ~2.2 bit (group-size 128) <1.5 PPL increase; ternary (−1,0,+1) gives 9.20 WikiText2 PPL on OPT-175B (<1 pt drop). ZeroQuant-LKD took ~3h for a 1.3B model; GPTQ does 100× larger in ~4h. FC2 matrix decompress: <1.5ms A100 / <3ms A6000.
- **Token-cost implication**: To serve very large models cheaply, quantize weights to 3–4 bits with GPTQ to collapse the GPU count needed and get ~3–4.5× faster, lower-latency token generation without retraining or task data.
- **Caveats**: Self-reported (authors). Speedups come only from reduced memory movement, not fewer FLOPs — no gain for compute-bound/large-batch cases (kernels target batch size 1, memory-bound matrix-vector products). No activation quantization. Focus is generative tasks and perplexity; bias/secondary effects not studied. OPT-66B was an outlier (harder to compress, dead units in early layers). Larger models are generally easier to quantize.
