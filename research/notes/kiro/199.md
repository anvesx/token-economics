# 199 — Prompt caching (Claude Platform docs)
- **Source**: https://platform.claude.com/docs/en/build-with-claude/prompt-caching (Anthropic, undated)
- **Claim**: Claude prompt caching lets the API resume from a cached prompt prefix (tools → system → messages, in that order), cutting processing time and cost for repeated prefixes; cache writes cost more than base input and cache reads cost a fraction of base input.
- **Mechanism**: Enable via `cache_control: {"type":"ephemeral"}` either at the top level (automatic caching — breakpoint auto-placed on the last cacheable block and moved forward as the conversation grows) or on individual content blocks (explicit, up to 4 breakpoints). Cache writes occur ONLY at a breakpoint and the key is a cryptographic hash of the entire prefix up to and including that block. On each request the system hashes the prefix at the breakpoint and, if no match, walks backward up to a 20-block lookback window (consecutive tool_use or tool_result runs count as one position) looking for entries prior requests wrote. Default TTL is 5 minutes, measured from the START of the writing/reading request (generation time counts against it) and refreshed free on each use; a 1-hour TTL is available at extra cost. Caches are isolated per organization (and per workspace on Claude API / Claude Platform on AWS / Microsoft Foundry; org-level on Google Cloud + Bedrock). Pre-warming: send `max_tokens: 0` to write the cache and return immediately (empty content, stop_reason max_tokens). ZDR eligible — raw text not stored; KV cache + hashes held in memory for the TTL then deleted.
- **Numbers**: Multipliers — 5-min cache write = 1.25x base input; 1-hour cache write = 2x base input; cache read = 0.1x base input (per-model exceptions: Fable 5.1 / Mythos 5.1 reads & refreshes = 0.025x; Opus 5.5 / Sonnet 5.5 = 0.05x). Price per MTok (base input / output / 5m write / 1h write / hit-refresh): Fable 5.1 $10/$50/$12.50/$20/$0.25; Opus 5.5 $4/$20/$5/$8/$0.20; Sonnet 5.5 $2/$10/$2.50/$4/$0.10; Haiku 5.5 ≤100k-token prompts $0.10/$0.50/$0.125/$0.20/$0.01, >100k-token prompts $0.50/$2.50/$0.625/$1/$0.05; Opus 5 $5/$25/$6.25/$10/$0.50; Opus 4.5 $5/$25/$6.25/$10/$0.50; Opus 4.1 $15/$75/$18.75/$30/$1.50; Sonnet 4.5 $3/$15/$3.75/$6/$0.30; Haiku 4.5 $1/$5/$1.25/$2/$0.10. Minimum cacheable prompt: 512 tokens (Fable/Mythos 5.1, Opus 5.5, Opus 5, Sonnet 5.5, Fable 5, Mythos 5, Haiku 5.5), 1,024 (Opus 4.8, Sonnet 5, Sonnet 4.6/4.5, Opus 4.1/4), 2,048 (Mythos Preview, Opus 4.7), 4,096 (Opus 4.6, Opus 4.5, Haiku 4.5). Lookback window = 20 blocks; max 4 breakpoints. OpenAI prompt-caching discount cited elsewhere; here caching has no effect on output tokens. total_input = cache_read + cache_creation + input_tokens.
- **Token-cost implication**: Put static content (tools, system, long context, 20+ examples) at the prompt start and place the breakpoint on the LAST block that is identical across requests — never on a block carrying a timestamp or the incoming message, or you pay a fresh write every time and never hit. For prefixes reused more often than every 5 min, keep the 5-min cache (refreshes free); use the 1-hour cache only for gaps between 5 min and 1 hour. Cache reads are ~10x (or up to 40x) cheaper than uncached input, so padding a near-threshold prompt up to the minimum is often worthwhile. Keep tool_choice, images, thinking config, and effort stable to avoid invalidation; pre-warm with `max_tokens: 0` to cut first-request TTFT.
- **Caveats**: Vendor doc, no independent measurement. Prices/minimums are model- and platform-specific and will change. Thinking blocks can't be cached via cache_control directly (but are cached alongside other content and count as input tokens when read); changing tool definitions, images, thinking params, or effort invalidates caches. Concurrent/batch requests get cache hits only best-effort (entry available only after first response starts). Bedrock has its own per-model minimums and field names.
