# 221 — Usage & Pricing (xAI prompt caching)
- **Source**: https://docs.x.ai/developers/advanced-api-usage/prompt-caching/usage-and-pricing (xAI, none)
- **Claim**: xAI Grok reports cached prompt tokens in the usage object, and cached tokens are billed at a substantially lower cached-token rate than regular prompt tokens. Verifying cache hits means reading the cached_tokens field.
- **Mechanism**: Chat Completions API surfaces cached tokens in usage.prompt_tokens_details.cached_tokens; Responses API in usage.input_tokens_details.cached_tokens. cached_tokens = 0 means full cache miss (expected on first request or after eviction); >0 is a partial hit (number = tokens reused from the prefix); equal to prompt_tokens is a full hit (rare, same request resent). Multi-turn conversations show cached_tokens growing each turn as the prior prefix becomes cacheable. If cached_tokens stays 0 across a conversation, check that x-grok-conv-id (or prompt_cache_key) is set and that earlier messages aren't being modified. Billing: non-cached prompt tokens at full prompt rate, cached prompt tokens at reduced cached rate, completion + reasoning tokens at full completion rate. Long-context pricing applies when total prompt tokens (including cached) exceed the model's long-context threshold — both cached and non-cached then use long-context rates.
- **Numbers**: Example usage: prompt_tokens=125, cached_tokens=98. Multi-turn example: Turn 1 prompt 50/cached 0; Turn 2 prompt 120/cached 50; Turn 3 prompt 200/cached 120. Exact cached-rate figures not in this page (points to Pricing page). Last updated May 10 2026.
- **Token-cost implication**: Keep the prompt prefix byte-identical across turns and set prompt_cache_key / x-grok-conv-id so requests route to the server holding the cache; never modify earlier messages. Monitor cached_tokens to confirm hits — a persistent 0 signals a broken cache key or a mutated prefix. Watch the long-context threshold: crossing it reprices every token (cached included) at the higher long-context rate.
- **Caveats**: Vendor doc with no concrete cached-token prices (rates vary by model, deferred to Pricing page). No benchmark or measured savings — purely the usage/billing mechanics. "Substantially lower" is unquantified here.
