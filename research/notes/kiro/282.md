# 282 — Effort parameter (Claude)
- **Source**: https://console.anthropic.com/docs/en/build-with-claude/effort (Anthropic, 2026-07)
- **Claim**: Anthropic's `effort` parameter lets developers trade response thoroughness against token efficiency on a single model by controlling how many tokens Claude spends across all output (text, tool calls, and thinking).
- **Mechanism**: Set `output_config.effort` on a Messages API request (or on the agent model object for Managed Agents). Effort is a behavioral signal, not a hard token budget — at lower levels the model still thinks on hard problems but less. It applies to every output token: text, tool-call arguments, and thinking (when active). Lower effort → fewer/terser tool calls, combined operations, no preamble; higher effort → more tool calls, up-front plans, detailed summaries. Effort is distinct from the `thinking` parameter (which toggles thinking blocks); in adaptive thinking mode, effort governs how often/deeply the model thinks. Thinking always counts toward `max_tokens` even when thinking content isn't returned, so set `max_tokens` with room for both. Per-message effort (beta, header `mid-conversation-output-config-2026-07-01`) lets you change effort mid-conversation via a `role:"system"` message with empty content and new `output_config.effort`, which preserves the prompt cache; changing top-level effort between requests instead restarts the cache.
- **Numbers**: Five effort levels: low, medium, high, xhigh, max. Default is high on most models; medium on Claude Opus 5.5 and Claude Haiku 5.5. Setting effort to the model's default = omitting the parameter. Recommended `max_tokens` starting points: 64k for Opus 4.7/4.8/5 at xhigh/max; 128,000 (model max) for Sonnet 5.5 agentic coding. Requests with `thinking:{"type":"disabled"}` at xhigh or max return HTTP 400 on several models (Opus 5, Opus 5.5, Sonnet 5.5, Haiku 5.5). Claude Opus 4.5 is the only extended-thinking-only model that supports effort and pairs it with `budget_tokens`. xhigh is "for long-running agentic and coding tasks (over 30 minutes) with token budgets in the millions." Claude Haiku 4.5 and Claude Sonnet 4.5: effort not supported. No per-level token or price figures given.
- **Token-cost implication**: Use effort as the primary cost/latency lever on Claude: drop to low for high-volume/simple tasks (classification, extraction, routing, subagents) and reserve xhigh/max for frontier problems — max often adds significant cost for small quality gains and can cause overthinking. Run a fresh effort sweep on your own evals when switching model versions (levels are recalibrated between versions and don't transfer). To vary effort within a cached conversation, use the per-message (beta) form to preserve the prompt cache instead of changing top-level effort (which invalidates the cache). Leave headroom in max_tokens for thinking.
- **Caveats**: Vendor API documentation; no benchmark numbers or measured $ savings — guidance is qualitative ("significant savings", "small quality gains"). Effort behavior and defaults differ per model and are recalibrated across versions, so cross-model comparisons don't hold. Per-message effort is beta with platform-specific availability (Bedrock/Google Cloud variations). Effort is explicitly not a strict token budget, so cost reduction is not deterministic.
