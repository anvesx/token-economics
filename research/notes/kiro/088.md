# 088 — AttentionRAG: Attention-Guided Context Pruning in Retrieval-Augmented Generation
- **Source**: https://arxiv.org/abs/2503.10720 (arXiv / Shanghai Jiao Tong University, 2025-03)
- **Claim**: AttentionRAG prunes retrieved RAG context using LLM attention scores, via an "attention focus" mechanism that reformulates each query into a next-token-prediction template so the query's semantic focus collapses to a single token, achieving up to 6.3x compression while matching or beating LLMLingua methods by ~10% on key metrics.
- **Mechanism**: Three steps. (1) Construct answer hint prefix: turn the query into an incomplete answer template whose blank is the focal token (e.g., "Where is Daniel?" → "Daniel is in the ___"); generated by GPT-4o Mini per query, with a fixed fallback prefix ("Please output the most relevant keyword or phrase...") for yes/no or summarization queries. (2) Compute attention features: split retrieved context into uniform m-token chunks; for each chunk, concatenate chunk+query+instruction+hint prefix, run the LLM to predict the first token after the prefix (the anchor token; "none" marks irrelevant chunks), sum attention scores of that anchor token over ALL layers (to avoid task-specific layer bias). (3) Attention-guided compression: skip "none" chunks; select top-k tokens by attention feature, retain the sentences containing them, concatenate into compressed context. Chunks processed independently ⇒ batched generation; int4 quantization further accelerates. No training required.
- **Numbers**: Up to 6.3x context compression; outperforms LLMLingua methods by ~10% in key metrics (18% higher score than best LLMLingua on BABILong 1k; +2% EM over uncompressed on TriviaQA). Compression LLMs: Llama-3.1-8B/70B-Instruct and Qwen-2.5-7B-Instruct. Benchmarks: LongBench (2WikiMQA, HotpotQA, TriviaQA, GovReport), BABILong (1k/2k/4k). Example (Llama-3.1-8B, 2WikiMQA): AttentionRAG-large EM 0.42 at 15x CR vs LLMLingua2-large 0.33 at 5x vs original 0.49 at 1x. HotpotQA latency (int4): AttentionRAG compression 3.99s + answering 4.94s vs original answering 19.36s; LLMLingua2-small compression 0.44s. Ablation chunk-size/top-K (TriviaQA): larger chunk + lower K lowers CR with minimal performance drop (e.g., chunk 100/K10 → 1.9x CR, EM 0.90; chunk 400/K10 → 2.4x CR, EM 0.85). Combination with BGE-M3 vanilla RAG then AttentionRAG: HotpotQA 9.1x CR (+5.4x). Hyperparameters: HotpotQA chunk 300/K12, 2WikiMQA 300/K15, TriviaQA 150/K8, BABILong 1k/2k/4k chunk 50/100/200, K 8/10/12. Attention layer ablation (HotpotQA): full layers 0-31 best (LLM-judge 0.54) vs 0-10 (0.43).
- **Token-cost implication**: For RAG, prune retrieved context with attention scores guided by a single focal/anchor token (next-token-prediction template) rather than entropy-based filtering — this is question-aware, training-free, model-agnostic, and even an 8B (or int4-quantized) compressor works, cutting both token count and end-to-end latency while preserving or improving answer quality. Supports dynamic compression ratios via chunk size and top-K.
- **Caveats**: Self-reported academic results, three trials averaged. Compression ratios are modest on fact-retrieval tasks (e.g., TriviaQA ~1.7–2.0x) because relevant info scatters and uniform hyperparameters are used; no explicit control to hit a target ratio (stated limitation). Summing attention over all layers is acknowledged as not yet optimized. Requires an extra LLM forward pass per chunk for compression. Evaluation limited to LongBench/BABILong and 7B–70B models.
