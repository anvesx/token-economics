# 164 — NVIDIA Dynamo, A Low-Latency Distributed Inference Framework for Scaling Reasoning AI Models
- **Source**: https://developer.nvidia.com/blog/?p=95274 (NVIDIA, 2025-03)
- **Claim**: NVIDIA Dynamo is an open-source distributed inference serving framework that uses disaggregated prefill/decode serving plus KV-cache-aware routing and offloading to raise throughput and cut cost for generative/reasoning LLMs at multinode scale.
- **Mechanism**: Four components. (1) Dynamo Planner continuously monitors GPU capacity metrics + SLOs (TTFT, ITL) and decides per request whether to serve disaggregated vs aggregated and how many GPUs to assign to prefill vs decode. (2) Smart Router hashes incoming requests into a Radix Tree, computes an overlap score against KV-cache blocks already resident across the GPU fleet, and routes to the worker with best cache hit + load balance (vs round-robin), avoiding KV recomputation. (3) Distributed KV Cache Manager offloads older/less-used KV blocks from GPU memory to CPU host memory, local SSD, or networked object storage with hierarchical eviction policies (GPU/node/cluster levels). (4) NIXL (NVIDIA Inference Transfer Library) gives a common async point-to-point data-movement API across HBM/DRAM/SSD/networked storage over NVLink, InfiniBand, RoCE, or Ethernet. Disaggregation separates the compute-bound prefill phase from the memory-bound decode phase so each can use its own GPU count and parallelism strategy. Works with TensorRT-LLM, vLLM, SGLang, PyTorch.
- **Numbers**: Up to 30x more requests served on DeepSeek-R1 (671B) on NVIDIA GB200 NVL72 with disaggregated serving (TensorRT-LLM, FP4, ISL/OSL 32K/8K; baseline inflight batching TEP16PP4DP4 vs Dynamo context EP4DP16 / generation EP64DP3; projected). More than 2x throughput on Llama 70B on NVIDIA Hopper (vLLM, FP8, ISL/OSL 3K/50; baseline inflight batching TP8DP2 vs Dynamo context TP2DP4 / generation TP8). Smart Router benchmark: 2x HGX-H100 nodes, 8x DeepSeek-R1-Distill-Llama-70B, vLLM FP8 TP2, 100K real R1 requests, avg ISL/OSL 4K/800. Model sizes grown ~2,000x since Triton; Triton downloaded >1M times. KV offload up to petabytes.
- **Token-cost implication**: At scale, disaggregating prefill/decode and routing by KV-cache overlap can multiply requests-served-per-GPU (claimed up to 30x) and offloading KV cache to cheaper memory tiers avoids recomputation — large infra cost reductions for reasoning/long-context and agentic workloads without changing the inference backend.
- **Caveats**: Vendor (NVIDIA) blog with self-reported and explicitly "projected performance subject to change" numbers; gains are configuration-specific (exact parallelism, precision FP4/FP8, ISL/OSL stated per chart) and measured on NVIDIA's own top-end hardware. 30x figure is for one model/hardware/workload combo, not general. No per-token pricing. Independent verification not provided.
