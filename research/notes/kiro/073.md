# 073 — Efficient Memory Management for Large Language Model Serving with PagedAttention (vLLM)
- **Source**: https://arxiv.org/abs/2309.06180 (arXiv, 2023-09)
- **Claim**: KV-cache memory is the bottleneck for LLM serving throughput because existing systems waste it via fragmentation and can't share it. PagedAttention (an attention algorithm using OS-style virtual-memory paging) plus the vLLM serving engine achieve near-zero KV-cache waste and flexible sharing, improving throughput 2–4× at the same latency.
- **Mechanism**: PagedAttention partitions each sequence's KV cache into fixed-size KV blocks stored in non-contiguous GPU memory (blocks=pages, tokens=bytes, requests=processes). A KV block manager keeps block tables mapping logical→physical blocks, allocating physical blocks on demand (left-to-right, new block only when the prior is full) — eliminating internal/external fragmentation and reservation waste. Enables block-granularity sharing: parallel sampling and shared system-prompt prefixes map identical logical blocks to the same physical block (reference-counted, copy-on-write on divergence); beam search shares dynamically across candidates. Under memory pressure, vLLM preempts with FCFS, all-or-nothing gang-scheduled eviction, recovering blocks via swapping (to CPU RAM) or recomputation. Custom fused CUDA kernels (fused reshape+block-write, fused block-read+attention, fused block-copy) reduce paging overhead. Supports Megatron-style tensor parallelism with one centralized KV manager shared across GPU workers.
- **Numbers**: Throughput improvement 2–4× over FasterTransformer and Orca at same latency. Existing systems use only 20.4%–38.2% of KV-cache memory for actual token states (rest wasted). Example KV cache: 13B OPT = 800 KB/token, up to 1.6 GB for a 2048-token request; ~65% of A100-40GB memory is weights, ~30% KV cache. Basic sampling: vLLM sustains 1.7×–2.7× higher request rates than Orca (Oracle), 2.7×–8× vs Orca (Max), up to 22× vs FasterTransformer; batches 2.2× more requests than Orca (Oracle), 4.3× more than Orca (Max). Memory saving from sharing: parallel sampling 6.1%–9.8% (Alpaca), 16.2%–30.5% (ShareGPT); beam search 37.6%–55.2% (Alpaca), 44.3%–66.3% (ShareGPT). Shared prefix throughput: 1.67× (1-shot) and 3.58× (5-shot) over Orca (Oracle). Chatbot: 2× higher request rate. Prompt KV share in parallel sampling = 12% of total; beam search up to 55% saving. PagedAttention adds 20–26% attention-kernel latency but wins end-to-end. Default block size = 16 (best 16–128 on ShareGPT). vLLM = 8.5K lines Python + 2K lines C++/CUDA. Models OPT 13B/66B/175B, LLaMA-13B on A100s. An LLM request can be ~10× more expensive than a keyword query.
- **Token-cost implication**: Serving cost per request is dominated by how efficiently KV-cache memory is packed, not raw FLOPs — use a PagedAttention-based engine (vLLM) to raise achievable batch size and throughput 2–4× on the same hardware, directly lowering $/request. Design prompts to share prefixes (common system prompts / few-shot examples) so the cache is reused across requests (up to 3.58× throughput); multi-sample and beam-search workloads benefit most from block sharing. Choose a small block size (~16) to balance GPU utilization vs fragmentation; prefer recomputation at small block sizes and swapping at large ones.
- **Caveats**: Self-reported by the authors (academic, SOSP'23) but the technique is independently widely adopted (vLLM is open source). Evaluated on OPT/LLaMA on NVIDIA A100s with synthesized ShareGPT/Alpaca workloads (Poisson arrivals, no real timestamps); Orca is a re-implementation (original not public). Gains shrink when workloads are compute-bound rather than memory-bound (e.g. OPT-175B with short Alpaca sequences). Kernel paging adds 20–26% attention-op overhead. Measured 2023 hardware/models; absolute numbers predate current GPUs.
