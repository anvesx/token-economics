# 014 — Reward Model Routing in Alignment (BayesianRouter)
- **Source**: https://arxiv.org/abs/2510.02850 (National University of Singapore / arXiv, 2025-10)
- **Claim**: BayesianRouter is a hybrid reward-model (RM) routing framework for RLHF/RLAIF that pairs offline learning of per-RM strengths with online Bayesian Thompson sampling to pick one RM per query (O(1) RM calls), outperforming single RMs, RM ensembles, and the prior RM-routing method LASER.
- **Mechanism**: Addresses single-RM limits (no RM dominates all tasks, large RMs costly, overoptimization). Offline router: a SmolLM2-135M-Instruct encoder encodes each preference pair (prompt + two responses, fused via [e+e'; |e−e'|] MLP); multi-task objective with a Bradley-Terry head (ability scores from disagreement samples) + auxiliary per-RM classification head (BCE over all behavior labels), loss = L_bt + λ·L_cls. Online router: per-query Bayesian linear regression per RM (Gaussian posterior N(µ,Σ)); Thompson sampling draws a reward estimate per RM per pair, selects argmax, labels the preference pair with that RM, trains policy via online DPO, then updates only the chosen RM's posterior. Integration via prior injection: initialize online weight prior mean µ_n^(0) = offline BT embedding E_bt[n] (not naive weighted averaging) to fix cold-start. Rewards = negative DPO loss, batch-baseline-centered then quantile-rescaled (20th/80th percentile) for stability.
- **Numbers**: RM pool N=4 (Mistral-RM-RAFT, GRM-Llama3.2-3B, GRM-gemma2-2B, Skywork-Reward-V2-Qwen3-0.6B); policy LLaMA3-SFT-v2. Offline data 50,402 pairs (HelpSteer3 + RM-Bench). Main results (BayesianRouter vs best single RM): AlpacaEval-2 63.23 vs 61.86; MT-Bench 58.75 vs 56.25; Chat-Arena-Hard 66.20 vs 64.80; GSM8K 75.66 vs 74.22; MMLU 57.39 vs 57.03. w/o offline=61.61 (sic rows), w/o online variants lower; LASER AlpacaEval-2=60.50. Offline router routing accuracy: ID 90.31% (ours 135M) vs best single 81.43, majority 83.17, random 79.80, oracle 100%; OOD (RewardBench 2) 87.92 All. ID eval 1,723 pairs, OOD 2,939 pairs. Online training: 16 prompts/batch, 6 responses@temp0.8, 4 pairs/prompt = 64 pairs/batch; max input 128 / output 256 tokens (512 for MT-Bench turn 2). LoRA rank 16 α=32 on q_proj/v_proj, lr 5e-6. Offline encoder lr 2e-5, batch 8, λ=0.2, 2 epochs. Prior variance σ_w²=0.02 (with prior), noise σ²=1. 8× RTX A6000 (48GB). Efficiency: O(1) RM calls vs O(N) for majority vote; LASER marginally faster (reuses policy embeddings).
- **Token-cost implication**: In RLHF/RLAIF training, don't call a single large RM or an N-way RM ensemble per query—route to one small specialized RM per preference pair (O(1) cost) using a cheap offline prior plus online Bayesian updates; this aggregates complementary RM strengths while keeping annotation compute flat as the RM pool grows, and can fall below single-large-RM cost if cheap RMs are often chosen.
- **Caveats**: Self-reported by authors (code released on acceptance). Designed/evaluated for the DPO family (PPO untested). Controlled "online" DPO is simulated by replaying 2,939 labeled RewardBench 2 pairs, not live human annotation; those controlled numbers are lower than main results due to limited training samples. Offline router still far from oracle (generalization gap on OOD). Does not jointly optimize RM inference cost vs annotation accuracy (left as future work).
