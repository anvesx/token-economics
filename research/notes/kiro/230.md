# 230 — Introducing the new Auto Router
- **Source**: https://openrouter.ai/blog/announcements/introducing-the-new-auto-router (OpenRouter, 2026-07 [post dated 8/10/2026])
- **Claim**: OpenRouter's new `openrouter/auto` router selects models based on the aggregate "wisdom of the market" — which models the OpenRouter community actually spends on for each task type over the past 7 days — and claims equal-or-better benchmark performance at lower cost than the old router in most domains.
- **Mechanism**: (1) A fast lightweight classifier assigns each prompt one of ~30 fine-grained task types (e.g. code debugging, multi-step agent planning, knowledge Q&A, math, customer support, research reports). (2) For that task type, it ranks models by real-world Share-of-Spend over the last 7 days (live signal, follows migrations within days). (3) The `cost_tier` parameter (low/medium/high/xhigh/max) selects a cost band of candidates — low = cheapest capable, max = most capable/priciest. (4) Selected models become primary + fallbacks ordered by usage share, respecting account restrictions (allowed models, guardrails, ZDR). If classification/rankings are unavailable it falls back to a default model set. "Sticky" behavior keeps multi-turn conversations on one model (identified by explicit `session_id` or a message fingerprint) until it is no longer a leading candidate, to avoid wasteful cache-rebuild on frequent model switches. Rankings use anonymized aggregate spend; prompts classified in-flight without retention.
- **Numbers**: Over 55T weekly token spend on OpenRouter referenced. Lookback window: past 7 days. ~30 task types. cost_tier values: low/medium/high/xhigh/max. Old router uses numeric `cost_quality_tradeoff` (0=high quality, default 7); default new router = cost_tier=low ≈ old cost_quality_tradeoff=7; Max = cost_tier=max vs old cost_quality_tradeoff=0. Benchmark accuracy (New Default / Old Default / New Max / Old Max): MMLU Pro 85.2%±0.3 / 86.6%±0.1 / 91.4%±0.3 / 88.8%±0.3; τ³-bench Banking (Agents) 20.6%±1.0 / 21.0%±1.0 / 31.6%±1.6 / 7.2%±2.7; WideSearch 61.6%±2.6 / 53.1%±2.6 / 61.9%±2.4 / 54.8%±2.6; DSQA (Research) 62.9%±1.6 / 43.2%±1.7 / 63.0%±1.6 / 42.3%±1.7; SWE-Atlas QnA (Coding) 30.4%±2.0 / 30.4%±2.3 / 60.7%±1.7 / 2.4%±0.0. Cost ($, New Default / Old Default / New Max / Old Max): MMLU Pro $140.93 / $393.34 / $255.71 / $449.61; τ³-bench Banking $155.89 / $320.04 / $168.41 / $99.36; WideSearch $30.75 / $31.83 / $36.89 / $31.60; DSQA $276.00 / $147.11 / $248.83 / $144.18; SWE-Atlas QnA $297.23 / $463.73 / $1,325.08 / $205.52. No extra routing fee; you pay the standard rate of whichever model runs.
- **Token-cost implication**: For mixed/unknown workloads, sending `model: "openrouter/auto"` with a chosen `cost_tier` offloads model selection to market data and can cut cost substantially at equal quality on several tasks (e.g. MMLU Pro default ~$141 vs ~$393; DSQA default nearly doubled accuracy at ~2x cost). Use `session_id` and rely on stickiness to avoid paying repeatedly to rebuild input cache when switching models. Restrict candidates with `allowed_models` to bound spend/compliance. Watch that "max" tier can be far more expensive (SWE-Atlas QnA Max $1,325 vs old $206) for a large quality gain.
- **Caveats**: Self-reported vendor benchmarks; OpenRouter chose the benchmark set and acknowledges results "capture a moment in time" and shift with community preferences. New Default underperformed old on MMLU Pro accuracy (85.2% vs 86.6%) and cost more than old on DSQA and (at Max) on τ³-bench Banking and SWE-Atlas QnA. Any multi-model router incurs cache-rebuild cost on switches. Hypothesis that selection "improves with adoption" is unproven. `cost_quality_tradeoff` still accepted for backward compat and takes precedence if both sent.
