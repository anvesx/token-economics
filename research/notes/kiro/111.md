# 111 — Batch API guide
- **Source**: https://developers.openai.com/api/docs/guides/batch (OpenAI, none)
- **Claim**: OpenAI's Batch API processes asynchronous groups of requests at 50% lower cost than synchronous APIs, with a separate higher-rate-limit pool and a guaranteed 24-hour turnaround, suited to non-latency-sensitive jobs (evals, classification, embeddings).
- **Mechanism**: Upload a .jsonl file where each line is one request with a unique custom_id, method, url, and body (same params as the underlying endpoint; one model per file). Supported endpoints: /v1/responses, /v1/chat/completions, /v1/embeddings, /v1/completions, /v1/moderations, /v1/images/generations, /v1/images/edits. Flow: (1) upload file via Files API with purpose="batch"; (2) create batch with input_file_id, endpoint, completion_window="24h" (only value allowed), optional metadata; (3) poll status (validating → in_progress → finalizing → completed, or failed/expired/cancelling/cancelled); (4) retrieve results from output_file_id (and errors from error_file_id). Output line order may differ from input — map via custom_id. Output files auto-delete 30 days after completion. Cancelling takes up to 10 minutes.
- **Numbers**: 50% cost discount vs synchronous APIs. 24-hour completion window (often faster). Per-batch limits: up to 50,000 requests; input file up to 200 MB; /v1/embeddings capped at 50,000 inputs per batch. Batch creation rate limit: up to 2,000 batches/hour. No output-token limit. Each model has a separate "queued prompt tokens per model" cap. Expired batches: completed requests still billed; unfinished requests cancelled and written to error file with code "batch_expired".
- **Token-cost implication**: Route any workload that can tolerate up to 24h latency (evals, bulk classification, embedding large corpora) through the Batch API to halve token cost and bypass synchronous per-model rate limits.
- **Caveats**: Vendor documentation (OpenAI, self-interested). No immediate responses — unsuitable for interactive use. Prefer image_url references over base64 to stay under the 200 MB upload limit. stream=true rejected for moderation. Most but not all models support Batch — check the model reference.
