# 190 — Custom costs (Cloudflare AI Gateway)
- **Source**: https://developers.cloudflare.com/ai-gateway/configuration/custom-costs (Cloudflare, 2026-09)
- **Claim**: AI Gateway lets you set custom per-request costs (your negotiated input, output, cache-read, and cache-write rates) via a header that overrides the default/public model costs used in logs and analytics.
- **Mechanism**: Send the `cf-aig-custom-cost` header with properties `per_token_in`, `per_token_out`, `per_cache_read_token`, `per_cache_write_token` (any number of decimal places). Cache-token pricing is optional: specify at least one cache rate to enable it; if only one is given the other defaults to `per_token_in`; omit both and cache counts are ignored. The gateway handles provider differences in cache reporting: when a provider reports cache tokens inside the input count it subtracts them before applying `per_token_in`; when reported separately it adds cache costs — preventing double-counting. Custom-cost entries are underlined in the logs. Costs only compute for responses that return token info.
- **Numbers**: Worked inclusive example: 1,000 input tokens, 600 cache-read, 200 cache-write, 100 output → 200 fresh input tokens (1,000 − 600 − 200). Example negotiated rates: $1 per million input, $2 per million output, $0.10 per million cache-read, $0.50 per million cache-write (header values 0.000001 / 0.000002 / 0.0000001 / 0.0000005 per token).
- **Token-cost implication**: Feed your actual negotiated/BYOK rates into the gateway so logged cost and spend-limit enforcement reflect real spend rather than public list prices; always break out cache-read/write rates so cheap cache hits aren't costed as full input tokens.
- **Caveats**: Vendor doc. Custom costs apply only when the request reaches the provider — a cache hit served from the gateway is always cost 0 regardless of custom cost. Requests without token info get no cost. Figures are illustrative examples, not real prices.
- **Topic**: observability
