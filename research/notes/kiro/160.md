# 160 — Process multiple prompts with batch inference (Amazon Bedrock)
- **Source**: https://docs.aws.amazon.com/bedrock/latest/userguide/batch-inference.html (Amazon Web Services, n.d.)
- **Claim**: Amazon Bedrock batch inference lets you submit many prompts and generate responses asynchronously via S3, improving throughput/efficiency on large datasets.
- **Mechanism**: Format input records using InvokeModel or Converse API format, upload the input files to an S3 bucket, submit a batch inference job pointing at that bucket, and retrieve output files from S3 when the job completes. Use Amazon EventBridge to get job state-change notifications instead of polling. Tool/function calling is unsupported for Converse-type batch jobs (records with toolConfig fail with HTTP 400); to use tool calling, create the job with InvokeModel invocation type in the model's native request format. Structured (validated JSON) outputs are supported with both invocation types.
- **Numbers**: none (page references the Bedrock pricing and quotas pages for figures rather than stating them).
- **Token-cost implication**: Route large, non-time-sensitive prompt volumes through batch inference to cut inference cost (batch is discounted per the capacity doc) and improve large-dataset throughput; design around async S3 I/O and EventBridge notifications rather than synchronous calls.
- **Caveats**: Vendor documentation; no pricing, quota, or throughput numbers in this page. Batch inference is not supported for provisioned models, and Converse-type jobs cannot do tool calling (400 error). Pricing/quotas live on separate pages.
- **Topic**: serving
