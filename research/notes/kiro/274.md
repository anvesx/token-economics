# 274 — GPT-OSS on Day 0 (Perplexity)
- **Source**: https://www.perplexity.ai/hub/blog/gpt-oss-on-day-0 (Perplexity, 2025-08)
- **Claim**: Perplexity describes the inference-engine changes (kernels, quantization, parallelism) needed to serve OpenAI's open-weight gpt-oss-20b and gpt-oss-120b models on NVIDIA H200 (Hopper) GPUs on day 0, and benchmarks prefill/decode cost across sharding configs.
- **Mechanism**: The open-weight models ship with MXFP4 quantization (for Blackwell FP4 cores / consumer memory), but Hopper lacks FP4 tensor cores, so Perplexity serves them in FP8 (128×128 block scaling) to reuse existing DeepGEMM kernels. Model specifics they had to support: GQA attention with per-head pre-trained attention sinks (a bias added inside softmax: `attn = softmax(q@k^T * sm_scale + sink) * V`), YaRN positional encoding, QKV+output projection biases, sparse MoE with SwiGLU, softmax after Top-K for expert weights (computed in bf16 for accuracy), expert biases. They extended FlashInfer FA2 kernels for sinks (init the online-softmax running max to the sink value, only in the first chunk), added bias to DeepGEMM by initializing WGMMA accumulators to bias values, and reused DeepSeek-V3 MoE implementation. Their in-house engine ROSE (Python/PyTorch, migrating hot paths to Rust) is format-agnostic; the Harmony chat format (channels: analysis/commentary/final; `to=` recipient tags) is handled by a separate JSON API frontend formatter. Deployment: one replica per single node (small models) to avoid inter-node overhead; Prefill-Decode Disaggregation lets prefill and decode be tuned independently with EP/DP/TP sharding.
- **Numbers**: Cost model assumes nominal H200 rate of $3.00/hour (stated not to be their actual price). Best prefill = batch_size=1, DP=1. GPT-OSS 120B prefill cost/latency per 1M input tokens, EP1/DP1/TP1: 8192→0.364s/$0.037; 32768→2.421s/$0.062; 65536→7.375s/$0.094; 128000→23.902s/$0.156. 120B EP8/DP1/TP8 at 128000→5.119s/$0.267. GPT-OSS 20B EP1/DP1/TP1: 8192→0.239s/$0.024; 32768→1.610s/$0.041; 65536→4.895s/$0.062; 128000→16.037s/$0.104. 20B EP8/DP1/TP8 at 128000→3.365s/$0.175. Best decode config for most cases = EP4/DP1/TP4. Hidden dimension: GPT-OSS 2880 vs DeepSeek-family 7168. Speculative decoding 20B-drafts-120B gave only marginal speedup (active params 3B vs 5B are too close). Model sizes expected 100B–200B range.
- **Token-cost implication**: If self-hosting gpt-oss on Hopper, serve in FP8 (not MXFP4) to reuse existing kernels. Prefill cost per 1M input tokens scales steeply and non-linearly with input length (longer prompts are disproportionately expensive); higher TP cuts latency but raises cost per token, so pick the sharding config for your latency/cost target. Keep small MoE models to a single node. Don't expect speculative decoding to help when draft/target activated-param counts are close.
- **Caveats**: Vendor engineering blog; all numbers self-reported by Perplexity. Cost figures are derived estimates from an assumed $3.00/hr H200 rate that they explicitly say is NOT their real GPU price, so absolute dollars are illustrative only. Decode cost/speed trade-offs are shown only as figures (plots), not tabulated here. Measured on H200 Hopper, not Blackwell. Dated 2025-08 (day-0 bring-up), performance pre-optimization.
