# 150 — Use Flex processing with Azure OpenAI in Foundry Models (preview)
- **Source**: https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/flex-processing (Microsoft, no date; page last updated 2026-10-12)
- **Claim**: Flex processing (preview) offers inference at a 50% discount versus Standard for delay-tolerant, lower-priority synchronous workloads, selected per-request via service_tier=flex, trading predictable latency for lower cost.
- **Mechanism**: Set service_tier to "flex" on each Responses API or Chat Completions request (or use the x-ms-service-tier header, which overrides the body). Same Global Standard deployment, same underlying model/quality as Standard — only latency, availability, and price change. Flex capacity is preemptible: requests can return HTTP 429 when capacity is unavailable; there is NO automatic fallback to Standard (app must explicitly retry with service_tier=default). Unsupported models return HTTP 400 (no fallback). Recommended pattern: try Flex, on RateLimitError retry Standard (completion-first) or exponential backoff with jitter (cost-first). Flex and Standard share the deployment's quota. Billed on dedicated Flex meters.
- **Numbers**: 50% discount on both input and output tokens vs Standard rates; cached input tokens still get the applicable cached-token discount; a Flex request rejected due to unavailable capacity isn't billed. No latency SLA or service SLA. Suggested client timeout ~15 minutes (900.0s in examples). Supported models (first = gpt-5.6-sol, 2026-07-09): gpt-6.1-sol (2026-09-29), gpt-6-sol/luna (2026-09-22), gpt-6-astra (2026-09-03), gpt-5.6-sol/luna/terra (2026-07-09), all Global Standard regions. Comparison of tiers: Flex 50% discount / variable latency / 429 on no capacity; Standard pay-per-token; Priority lower consistent latency; Batch discounted rate, 24-hour target; Provisioned throughput hourly PTU billing. Error handling: 400 invalid_request_error (unsupported — don't retry unchanged), 408 timeout, 429 capacity/rate-limit (honor Retry-After), 500/502/503/504 transient (bounded backoff), 401/403 auth, 404 deployment not found.
- **Token-cost implication**: For evaluations, data enrichment, document analysis, and async/background work that can tolerate variable latency and transient 429s, route requests to Flex for a flat 50% token-cost cut on the same model — but build explicit retry/backoff and an app-level Standard fallback, and keep interactive traffic on Standard/Priority/provisioned. Shifting delay-tolerant work to off-peak reduces 429s. Prompt caching stacks with the Flex discount.
- **Caveats**: Vendor doc, preview feature; no latency or service SLA; limited model availability at launch; no automatic Standard fallback; 429 can mean either Flex capacity shortage or shared-quota exhaustion. Still synchronous (not Batch). Prices referenced ("50%") but current absolute rates point to the Azure OpenAI pricing page. Dates on this page appear to be forward-dated (2026).
