# 162 — Bring Kiro agents to your terminal with Kiro CLI
- **Source**: https://kiro.dev/blog/introducing-kiro-cli (Amazon Kiro, n.d.)
- **Claim**: Kiro CLI brings Kiro's agentic AI into the terminal, reusing Q Developer CLI technology (agent mode, MCP, steering, custom agents) and adding social login, Haiku 4.5, and an "Auto" agent that picks the optimal model per task to balance speed, cost, and quality.
- **Mechanism**: Custom agents are configured per workflow with pre-approved tools, persistent context (auto-loaded project files/standards like backend-standards.md), file-path restrictions (e.g. src/api/**), and granular tool permissions (the @builtin namespace pre-approves all built-in tools). Context is managed via Agent Resources (persistent), Session Context (temporary), and Knowledge Bases (semantic search over large codebases/PDFs without consuming the context window); `/context` shows a context-usage percentage. The Auto agent dynamically chooses the optimal model for each task. Config is shared with Kiro IDE via the .kiro folder (mcp.json, steering/*.md, docs). Supports multimodal image input, MCP servers, and GitHub/Google/AWS Builder ID/IAM Identity Center auth.
- **Numbers**: Tasks that cost X credits in Auto mode would cost 1.3X credits if you manually selected Sonnet 4 (i.e. Auto is ~23% cheaper than always using Sonnet 4 for those tasks). Scale-to-zero / tier figures: none. Model mentioned: Haiku 4.5.
- **Token-cost implication**: Use Auto instead of pinning Sonnet 4 to cut credit spend (~1/1.3 of cost on comparable tasks); scope custom agents with file-path limits and Knowledge Bases so each agent's context window holds only relevant material, reducing per-call token cost and improving relevance.
- **Caveats**: Vendor blog, self-reported; the 1.3X claim has no benchmark, task mix, or quality-parity evidence and is specific to "tasks that cost X credits in Auto mode" vs Sonnet 4. No absolute per-token/credit prices. Code examples in the post did not render ("Loading code example...").
