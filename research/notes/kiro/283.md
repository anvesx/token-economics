# 283 — What's new in Claude Opus 5
- **Source**: https://platform.claude.com/docs/en/about-claude/models/whats-new-opus-5 (Anthropic, undated)
- **Claim**: Anthropic's model-reference page for Claude Opus 5 (now legacy) listing its specifications, pricing, and prompt-caching rates alongside a comparison table against the current lineup (Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5).
- **Mechanism**: Claude Opus 5 (`claude-opus-5`) is a text+image→text model with a 1M-token context window, adaptive thinking, and a default effort of high. Cost levers documented: prompt caching (5-minute and 1-hour cache-write tiers plus cache reads), Batch API (50% discount on input and output), and the effort/adaptive-thinking controls. Minimum cacheable prompt length is 512 tokens. On the Message Batches API it supports up to 300k output tokens with the `output-300k-2026-03-24` beta header (vs 128k standard max output).
- **Numbers**: Claude Opus 5 pricing: input $5 / MTok, output $25 / MTok; 5-minute cache write $6.25 / MTok; 1-hour cache write $10 / MTok; cache read $0.50 / MTok; Batch API 50% discount on input+output. Context 1M tokens; max output 128K (300K via Batch API beta). Default effort high; knowledge/training cutoff May 2026; released July 24, 2026; retirement not sooner than July 24, 2027; min cacheable prompt 512 tokens. Comparison table (Context / Max output / Price per MTok / Default effort): Fable 5.1 1M/128K/$10/$50/high; Opus 5.5 1M/128K/$4/$20/medium; Opus 5 1M/128K/$5/$25/high; Sonnet 5.5 1M/128K/$2/$10/high; Haiku 5.5 1M/128K/from $0.10/$0.50/medium. All five listed models use adaptive thinking.
- **Token-cost implication**: Cache reads cost $0.50/MTok vs $5/MTok standard input — a 10× saving on repeated prefixes, so structure stable context as a cacheable prefix (≥512 tokens) and choose the 5m vs 1h cache-write tier by reuse frequency. Use the Batch API for a flat 50% cut on non-real-time jobs. Note the newer Opus 5.5 is cheaper ($4/$20 vs $5/$25) and defaults to medium effort, so migrating off legacy Opus 5 reduces both token price and default spend. For very large single outputs, the 300k-output Batch beta avoids splitting requests.
