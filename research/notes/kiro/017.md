# 017 — Capability Instruction Tuning: A New Paradigm for Dynamic LLM Routing (MODEL-SAT)
- **Source**: https://arxiv.org/abs/2502.17282 (AAAI 2025, Nanjing University, 2025-02)
- **Claim**: MODEL-SAT routes each instruction to the best LLM in a pool using "capability instructions" built from a lightweight aptitude test, achieving routing without inference on candidate models and matching ~70B LLM performance with a pool of sub-10B models; a combined small-model zoo can cover most of what a giant LLM (GPT-4o) answers correctly.
- **Mechanism**: Each candidate model is profiled by an aptitude test: 50 core tasks sampled from MMLU, each 20-shot, results described in natural language = model capability representation (can also include extra expert knowledge like supported languages). A "capability instruction" = capability representation c_m + user instruction x_i + a performance inquiry prompt p ("predict whether the model can handle ... 'Yes'/'No'"). Architecture: a capability encoder E5-Large ~0.5B (ψ) maps c_m, a single-layer MLP connector aligns it into the embedding space of a Phi-3-Mini 3.8B LLM (φ); the concatenated sequence is fed to φ which outputs P('Yes'|z_i) as the routing score. Trained end-to-end with in-batch negative sampling (1 positive + k−1 negatives per capability rep), cross-entropy loss; two-stage (connector first, then full params with larger LR on encoder/connector). Core-task sampling favors instructions where half the models succeed. New models only need inference on 50×20-shot tasks to get a representation—no candidate inference per query and no router retraining.
- **Numbers**: 66 open-source LLMs (60 under 10B, 15 between 10–20B, 5 around 60B). Coverage: Phi-1 (1.3B) + four 7B models (released ~1 year before GPT-4o, ~30% worse) jointly cover 90% of instructions GPT-4o answers correctly and ~80% it gets wrong; strategic routing could exceed GPT-4o by ~15%. Phi-1+ChatGLM2+Zephyr covers 80% of GPT-4o's correct instructions. Smaller-scale zoo (5 models <10B): MODEL-SAT mean 75.28% ≈ Meta-Llama-3-70B 76.90% and beats it on ARC-C and TruthfulQA. High-Performance zoo (three 70B+): MMLU 85.64%, ARC-Challenge 73.63%. Capability rep = 50 tasks × 20-shot. Re-ranking baselines (Cappy, BGE-Large, GTE-Large) need all candidate outputs; MODEL-SAT cost independent of pool size. Other strategies on capability instructions: RoBERTa+MLP mean 64.90, +kNN 64.52, +Random Forest 67.75, Phi-3 alone 68.83, MODEL-SAT 72.50. Multimodal zoo (MiniCPM-Llama3-V, Phi-3-Vision, InternLM-XComposer2-VL): MMMU-VAL 43.21, AI2D-TEST 80.38, CCBench 56.96. 60 incremental new-model routing scenarios tested.
- **Token-cost implication**: You can serve near-flagship quality cheaply by routing each instruction to the right sub-10B model; profile models once with a 50×20-shot aptitude test (text capability descriptions) instead of running all candidates per query (re-ranking), so routing cost stays flat as the pool grows and new models are onboarded with ~1000 cheap inferences.
- **Caveats**: Self-reported by authors (code released). Coverage/"could exceed by 15%" is an upper-bound/oracle-style observation of combined correctness, not achieved end-to-end routing accuracy. Evaluated on academic benchmarks (MMLU, WinoGrande, ARC-C, BoolQ, TruthfulQA, MRPC, MNLI + multimodal), not production traffic. No explicit monetary cost/latency modeling—"cost" framed as parameter scale and avoided candidate inference overhead; capability reps derived only from MMLU categories.
- **Topic**: routing
