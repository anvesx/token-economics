# 004 — GraphRouter: A Graph-based Router for LLM Selections
- **Source**: https://arxiv.org/abs/2410.03834 (UIUC, 2024-10; published ICLR 2025)
- **Claim**: GraphRouter frames LLM selection as an edge-prediction task over a heterogeneous graph of task/query/LLM nodes, letting one router pick the best cost/performance LLM per query and generalize to new LLMs without retraining.
- **Mechanism**: Build a heterogeneous graph with task nodes, query nodes, and LLM nodes; interactions (performance + cost of an LLM answering a query) are edge features. Nodes are initialized with embeddings: GPT-4o generates descriptive text for each task and each LLM (strengths, token pricing, context length), then a BERT-style PLM encodes the description (averaged output token embedding). Task-query edges init to 1; LLM-query edges init to concatenation of performance and cost. A 2-layer heterogeneous GNN (GAT, 32-dim hidden) aggregates neighbor info; LLM selection = predicting the query→LLM edge with max logit via dot product of query-task combined embedding and LLM embedding. Best LLM per query is labeled 1 (edge), others 0; trained with cross-entropy. For new LLMs, a small auxiliary few-shot interaction dataset (80 queries) is used at test time only, no retraining. Reward = α·Performance − β·Cost with three scenarios: Performance First (1,0), Balance (0.5,0.5), Cost First (0.2,0.8).
- **Numbers**: 10 LLMs on Together API, cost per 1M tokens: LLaMA-3 7b=0.2, Mixtral-8x7B 56b=0.6, NousResearch 34b=0.8, LLaMA-2 7b=0.2, Mistral-7b=0.2, LLaMA-3 70b=0.9, LLaMA-3-Turbo 8b=0.2, LLaMA-3-Turbo 70b=0.9, Llama-3.1-Turbo 70b=0.9, Qwen-1.5 72b=0.9. Extended set adds Qwen-2 72b=0.9, Code Llama 34b=0.8, Mixtral-8x22B 176b=1.2, Upstage 11b=0.3. 4 datasets (Alpaca, GSM8K, SQUAD, Multi-News), 600 cases each; 70/10/20 train/val/test split. GraphRouter beats strongest baseline by ≥12.28% on Reward; reaches ≥88.89% of Oracle. New-LLM few-shot setting: Reward improvement +9.52% vs most-costly C2MAB-V, Time Cost reduction 99.45% (3.00 vs 542.25). GraphRouter few-shot Reward=0.207, trained=0.219. Best GNN size=32, best #layers=2. Token counting via GPT-2. Single NVIDIA A100.
- **Token-cost implication**: A single contextual graph-based router can replace per-task routers and cut inference cost by routing most queries to cheap small LLMs while escalating only when needed; model descriptions (incl. token pricing) as text embeddings let you add a new model cheaply with ~80 few-shot examples instead of retraining.
- **Caveats**: Self-reported by authors. Costs are 2024 Together API list prices for a specific 10-LLM pool; performance metrics are F1/accuracy on 4 academic datasets (600 samples each), not production traffic. Limitation: does not model numerical pricing/context-length well via LLM text; does not test multi-agent or prompting-method selection; graph signals limited (no paths/taxonomy).
- **Topic**: routing
