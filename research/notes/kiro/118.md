# 118 — In Defense of RAG in the Era of Long-Context Language Models
- **Source**: https://arxiv.org/abs/2409.01666 (arXiv (NVIDIA), 2024-09)
- **Claim**: Contrary to work favoring long-context LLMs over RAG, an order-preserving RAG (OP-RAG) achieves higher answer quality than feeding the whole long context to an LLM, while using far fewer input tokens. Answer quality vs. retrieved-chunk count follows an inverted-U.
- **Mechanism**: Split a long document into N sequential, non-overlapping chunks (128 tokens each). Score each chunk by cosine similarity between query and chunk embeddings (BGE-large-en-v1.5). Retrieve top-k. Unlike vanilla RAG, which orders chunks by descending similarity, OP-RAG preserves the chunks' original document order (constraint: j_l > j_m ⟺ l > m). More chunks raises recall but adds distracting irrelevant context, so quality rises then declines — there is a "sweet point" that beats processing the full context.
- **Numbers**: En.QA (∞Bench): OP-RAG w/ Llama3.1-70B hits 44.43 F1 using only 16K retrieved tokens, vs 34.32 F1 for Llama3.1-70B on full 128K context, GPT-4O 32.36, Gemini-1.5-Pro 43.08. OP-RAG-48K reaches 47.25 F1 (48K tokens) vs 34.26 F1 for Llama3.1-70B w/o RAG (avg 117K tokens). Vanilla vs OP-RAG at 128 chunks on En.QA: 38.40 vs 44.43 F1; En.MC at 192 chunks: 81.22 vs 88.65 acc. Peak context length: Llama3.1-8B at 16K (both datasets); Llama3.1-70B at 48K (En.QA) / 32K (En.MC). En.QA = 351 QA pairs, avg 150,374 words; En.MC = 224 pairs, avg 142,622 words. Chunk size 128 tokens, non-overlapped. SELF-ROUTE (GPT-4O) 34.95 F1 at 85K tokens.
- **Token-cost implication**: For long-context QA, don't dump the entire document into the LLM; retrieve a modest number of chunks (tuned to a sweet spot) and preserve their original order — this cuts input tokens roughly 2–7× while improving answer quality.
- **Caveats**: Self-reported by NVIDIA authors; tested only on En.QA and En.MC of ∞Bench. Optimal chunk count (sweet point) is model- and dataset-dependent and must be tuned. LongBench excluded as too short (<20K words). Larger models tolerate more chunks before degrading. Some baseline numbers cited from Li et al. 2024 rather than re-measured.
