# 245 — Cost-aware model routing with Vercel AI Gateway
- **Source**: https://vercel.com/kb/guide/cost-aware-model-routing-with-ai-gateway (Vercel, 2026-11; published 17 Jun 2026)
- **Claim**: A how-to guide for building a router that classifies each request, picks a model tier (fast vs frontier), and runs it through Vercel AI Gateway, using per-key budgets to cap spend — so cheaper models handle easy work (summarization, classification, extraction) and frontier models only handle hard reasoning.
- **Mechanism**: Three-stage router. (1) Heuristic classifier runs first at zero cost/latency: regex checks for code blocks and hard-signal keywords (`debug|explain why|prove|step by step|refactor`) route to frontier, else returns null. (2) When heuristic returns null, call a decision model (`typesafe-ai/jev` or `openai/gpt-6-luna-decisions`) via AI SDK's `experimental_decide` with a typed "choice" question and per-tier profiles; accept the fast tier only if the model picks it AND its probability ≥ threshold, otherwise default to frontier. (3) `generate()` resolves the tier to a primary model with a cross-provider fallback, tags the call `role:answer`/`tier:*`. An escalation pattern starts on fast, runs a verifiable output check (schema + quote/city evidence check), and escalates to frontier only on failure. Budgets: create 3 separate AI Gateway API keys (router/fast/frontier) each with its own budget; budgets are soft caps checked at request start, in-flight/concurrent requests can overshoot, and exceeding returns HTTP 402 `quota_for_entity_exceeded` until reset — do not retry through another key. Observability tracks total cost per finished task, routing vs generation latency, served model, and quality against a baseline.
- **Numbers**: `FAST_THRESHOLD = 0.85` (example fast-tier probability threshold, tunable; explicitly NOT an 85% chance of acceptable answer). Example traffic fraction 0.2. Pinned deps: AI SDK 7.0.155, Node.js 22.18+, Next.js 16. Local OIDC tokens valid 12 hours. Budget rejection = HTTP 402. No price-per-token figures given (example model IDs like openai/gpt-6-luna, gpt-6-astra, claude-haiku-5.5, claude-fable-5.1 have no listed prices).
- **Token-cost implication**: Route cheap requests to a small model and reserve frontier models for genuinely hard requests; run heuristics before any decision-model call to avoid paying for classification. Measure total cost per finished task (including the decision call, fallbacks, and escalation) against always-fast / always-frontier baselines — the extra decision round trip can outweigh its benefit when the fast model already answers. Use per-tier API-key budgets as an independent hard cap distinct from routing; BYOK spend is NOT counted toward gateway budgets.
- **Caveats**: Vendor guide, no measured savings or benchmarks — illustrative only. Decision/Decisions API is experimental; model IDs are forward-dated examples. The 0.85 threshold and heuristic rules are placeholders to tune on a labeled holdout set. Budgets are soft caps (overshoot possible). Lower spend alone does not prove routing decisions were correct.
