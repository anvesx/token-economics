# 177 — How Does Cohere's Pricing Work?
- **Source**: https://docs.cohere.com/docs/how-does-cohere-pricing-work (Cohere, undated)
- **Claim**: Cohere prices generative models per token (input and output priced differently), Rerank per search, and Embed per token embedded; it also distinguishes "billed" tokens from raw token counts so customers aren't charged for tokens Cohere adds under the hood.
- **Mechanism**: Generative models (Command A+, Command A, Command R7B, Command R, Command R+) bill per input/output token. Rerank bills per search; Embed bills per token embedded. The Chat API response returns both a `billed_units` object (input_tokens, output_tokens you pay for) and a `tokens` object (overall counts). The two differ when Cohere adds tokens under the hood or a model emits special tokens the user didn't control — those are not charged. Trial API keys are free but rate/volume limited; production keys are paid. Up-to-date prices live on a separate pricing page.
- **Numbers**: Example response body: billed_units input_tokens 6772, output_tokens 248; tokens input_tokens 7596, output_tokens 645. No per-1M-token prices are given in this document (they are on the separate pricing page). 
- **Token-cost implication**: Read `billed_units`, not the raw `tokens` field, when computing actual cost — the gap (here ~824 input, ~397 output tokens) is not billed. Use trial keys for proofs of concept before paying for production usage.
- **Caveats**: Vendor doc, no dated prices in this page. Actual per-token figures must be pulled from the live pricing page. Describes v2 API default. Does not quantify the "under the hood" token additions beyond the one example.
