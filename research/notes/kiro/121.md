# 121 — Gemini 2.5 Models now support implicit caching
- **Source**: https://developers.googleblog.com/zh-hans/gemini-2-5-models-now-support-implicit-caching (Google, 2025-05)
- **Claim**: The Gemini API now supports implicit caching for Gemini 2.5 models, automatically passing a 75% token discount on cached shared-prefix content to developers without requiring them to create an explicit cache.
- **Mechanism**: When a request to a Gemini 2.5 model shares a common prefix with a previous request, it becomes eligible for a cache hit and the cost savings are dynamically returned. To maximize hits, developers keep the beginning of the prompt stable and append variable content (user question, extra context) at the end. Explicit caching API remains available (Gemini 2.5 and 2.0) to guarantee savings. Usage metadata field cached_content_token_count reports how many request tokens were cached and billed at the lower rate.
- **Numbers**: 75% token discount on cached content (same as the explicit-caching discount pioneered May 2024). Minimum request size for cache eligibility lowered to 1024 tokens for 2.5 Flash and 2048 tokens for 2.5 Pro.
- **Token-cost implication**: Structure prompts prefix-stable (static instructions/context first, variable user input last) so repeated calls automatically earn the 75% prefix-cache discount; for guaranteed savings use explicit caching, and monitor cached_content_token_count.
- **Caveats**: Vendor blog (Google, self-interested); no benchmark or independent measurement. Implicit caching is opportunistic (eligibility, not guarantee) — only explicit caching guarantees the discount. Applies to Gemini 2.5 (implicit) / 2.5 and 2.0 (explicit) models only. Related-post links reference forward-dated (2026) articles, indicating a possibly post-dated page capture.
- **Topic**: caching
