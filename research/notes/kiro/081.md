# 081 — LLMLingua-2: Data Distillation for Efficient and Faithful Task-Agnostic Prompt Compression
- **Source**: https://arxiv.org/abs/2403.12968 (Microsoft Research, 2024-03)
- **Claim**: Task-agnostic prompt compression framed as token classification (preserve/discard) using a small bidirectional Transformer encoder, trained on a distilled extractive compression dataset, beats information-entropy baselines while being much faster and faithful to the original text.
- **Mechanism**: (1) Data distillation: prompt GPT-4 to compress MeetingBank texts by removing unimportant words only (5 explicit constraints: only remove, don't reorder, don't change words, no abbreviations/emojis, no new words), chunk-wise (≤512-token chunks ending at sentence) to avoid aggressive over-compression on long context. (2) Data annotation: assign binary preserve/discard labels to each original word via sliding-window + fuzzy (lemmatized) matching. (3) Quality control: Variation Rate (VR, drop top 5%) and Alignment Gap (AG = hitting rate − matching rate, drop top 10%). (4) Compressor: Transformer encoder (xlm-roberta-large = LLMLingua-2; multilingual-BERT = LLMLingua-2-small) + linear head, cross-entropy loss; at inference keep top τN words by preserve-probability in original order. Can plug into LLMLingua's coarse-to-fine budget controller for ~15x.
- **Numbers**: 3x–6x faster than existing prompt-compression methods; end-to-end latency speedup 1.6x–2.9x at compression ratios 2x–5x. GPU memory reduced 8x (peak 2.1 GB vs LLMLingua 16.6 GB / Selective-Context 26.5 GB using LLaMA-2-7B). In-domain MeetingBank QA EM: LLMLingua-2 86.92 vs original 87.75 vs LLMLingua 67.52 (at ~3.1x, 970 tokens vs 3003). Latency on V100-32G: End2End w/o compression 14.9s; w/ LLMLingua-2 9.4s (1.6x) at 2x, 7.5s (2.1x) at 3x, 5.2s (2.9x) at 5x; LLMLingua-2 compressor itself 0.5/0.4/0.4s vs LLMLingua 2.9/2.1/1.5s. Model sizes: xlm-roberta-large 355M (train ~23h), multilingual-BERT 110M (train ~16h). Training: 10 epochs, Adam lr 1e-5, batch 10. Target LLM GPT-3.5-Turbo-0613, temp 0. Dataset: 5,169 samples, 41,746 chunks, original avg 3,635 tokens → compressed 1,415 (2.57x). GPT-4 distillation used GPT-4-32k, temp 0.3, top_p 1.0, max 4096 output tokens, transcripts >28K truncated. Zero-shot baselines reach 48x–306x compression but low accuracy. Dynamic per-sample ratio gives +4.4%/+4.5% at 7x/5x. LLMLingua-2+LongLLMLingua coarse: +25.3% avg on NaturalQuestions.
- **Token-cost implication**: Use a small bidirectional encoder-based classifier (not a 7B causal LM) for task-agnostic prompt compression — it is cheaper, faster, lower-memory, and more faithful, and generalizes across target LLMs and domains without retraining. Compress once (task-agnostic) rather than per-query. For RAG/multi-doc, combine with LongLLMLingua coarse stage for question relevance.
- **Caveats**: Dataset built only from MeetingBank (meeting transcripts); generalization argued but not exhaustive. Falls short of task-aware methods (LongLLMLingua) on LongBench because it ignores the question. Self-reported by Microsoft authors; target LLMs mainly GPT-3.5-Turbo and Mistral-7B. No model-performance link beyond these tasks; VR metric may conflate diversity.
- **Topic**: compression
