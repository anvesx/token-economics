# 155 — Copilot CLI auto model selection routes based on task
- **Source**: https://github.blog/changelog/2026-07-01-copilot-cli-auto-model-selection-routes-based-on-task (Microsoft GitHub, 2026-07)
- **Claim**: GitHub Copilot's Auto model selection now routes each Copilot CLI task to the best-fit model using real-time utilization and model-health signals, aiming for token efficiency without quality regression.
- **Mechanism**: Auto weighs real-time model availability and reliability signals, then evaluates the task across dimensions (reasoning, code-generation complexity, bug-diagnosis difficulty, tool-orchestration needs) to pick the optimal model. It honors admin model policies and draws from multiple model families depending on subscription/policy. It deliberately routes along natural cache boundaries to avoid unnecessary cache-related costs. Users can override via the `/model` command.
- **Numbers**: Paid subscribers get a 10% discount on model costs when using Auto, i.e. consume 10% fewer AI credits than running the same model directly. On legacy annual plans billed in premium requests, the 10% discount applies to the model multiplier (a 1x-multiplier model draws down 0.9 premium requests). Billing is at each selected model's published rate.
- **Token-cost implication**: Using Auto instead of pinning one model can cut credit spend ~10% and reduce cache-busting costs; not every task needs a high-reasoning/token-intensive model, so let the router downshift cheap tasks.
- **Caveats**: Vendor self-reported ("our evaluations show gains ... with no quality regression") with no benchmark numbers or methodology given. Available model families "will change over time." Discount/billing specifics differ by plan type (AI credits vs legacy premium requests).
- **Topic**: routing
