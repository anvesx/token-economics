# 114 — Semantic Caching for Low-Cost LLM Serving: From Offline Learning to Online Adaptation
- **Source**: https://arxiv.org/abs/2508.07675 (arXiv, 2025-08)
- **Claim**: Presents a principled, learning-based framework for semantic cache eviction under unknown query-arrival and serving-cost distributions, formulated as a combinatorial multi-armed bandit, with provably efficient offline and online algorithms that beat ad-hoc baselines.
- **Mechanism**: A semantic cache M of ≤ k query-response pairs in a vector DB. For an incoming query q_t, the optimal rule serves from cache if the mismatch cost d(q_t, M) (distance to nearest cached query, Euclidean/cosine on embeddings, scaling γ=1) is less than the LLM serving cost c(q_t), else invokes the LLM. Expected loss ℓ(M)=Σ p(q)·min{c(q), d(q,M)}. Computing optimal M is NP-hard (reduces to max vertex cover on bipartite graphs); loss is non-increasing and supermodular, so Reverse Greedy (start with all pairs cached, iteratively remove least-beneficial) gives an e^(β/(β−1)) approximation (β=c/(1−c), c=curvature). Offline: CUCB-SC estimates p (empirical means) and c (pessimistic UCB-penalized) from a static log dataset, then runs Reverse Greedy. Online: CLCB-SC-LS uses optimism (LCB cost estimates) with stage-based cache switching to bound switch count, since each cache update incurs a switching cost (must re-query LLM for new entries).
- **Numbers**: Over 30% of LLM queries are reportedly semantically similar (cited). Offline suboptimality gap scales as Õ(√(m/n)) (m queries, n samples). Online regret Õ(√(mT)) over T rounds with only O(m log log T) cache switches. Online experiments (synthetic, m=20, k=5 default): ≥11.75% average-regret improvement over strongest baseline (Epsilon-Greedy); improvement grows from 11.75% to 54.04% as cache size k increases. CLCB-SC-LS reduces cache switches by up to 90.91% and running time by up to 85.40% (abstract says "up to 85%") vs baselines. Embeddings via sentence transformer → 384-dim; cost = min-max-normalized query token count + N(0, 0.05) Gaussian noise; 10 runs per setting. Improves on Zhu et al. by O(k/√C1) (C1 = min query cost) in exact-match special case.
- **Token-cost implication**: Use semantic (embedding-similarity) caching rather than exact-match caching so near-duplicate prompts reuse responses; when parameters are unknown, learn them online with a low-switching bandit policy to avoid paying repeated LLM calls while limiting cache-refresh costs.
- **Caveats**: Evaluated only on a synthetic dataset (queries generated by ChatGPT, m=20), not real production traffic. Theoretical guarantees assume sub-Gaussian cost noise and specific feedback structures. Self-reported by authors. Mismatch cost is a modeled utility-loss proxy, not a measured quality degradation. v3 dated 2026-02 on arXiv.
- **Topic**: caching
