# 152 — How to use global batch processing with Azure OpenAI in Foundry Models
- **Source**: https://learn.microsoft.com/azure/foundry/openai/how-to/batch (Microsoft, no date; page last updated 2026-06-05)
- **Claim**: The Azure OpenAI Batch API processes large asynchronous groups of requests at 50% less cost than Global Standard with a 24-hour target turnaround, using a separate enqueued-token quota so online workloads aren't disrupted.
- **Mechanism**: Submit a JSONL file (one request per line, each with custom_id, method POST, url /v1/chat/completions or /v1/responses, and body with a model = Global-Batch deployment name) to a GlobalBatch or DataZoneBatch deployment. Upload file (purpose=batch), create batch job (completion_window must be "24h"), poll status (validating→in_progress→finalizing→completed; also failed/expired/cancelling/cancelled), retrieve output_file_id and error_file_id. Quota is measured in enqueued tokens — tokens in the file count against the limit until the job reaches a terminal state. Recommended: enable dynamic quota. A "fail fast" feature in certain regions lets you queue multiple batch jobs with exponential backoff so the next starts automatically when enqueued-token quota frees up. Supports base64/url images (multimodal models only) and structured outputs; does NOT support fine-tuned models, embeddings models, Assistants API, or On Your Data.
- **Numbers**: 50% cost reduction vs Global Standard; 24-hour target turnaround (jobs aren't expired if longer; you pay only for completed work; cancel takes up to 10 min). File/job limits: max batch input files 500 (no expiration) / 10,000 (expiration set); max input file size 200 MB (1 GB with bring-your-own-storage); max requests per file 100,000. Input-file expiration configurable 1,209,600–2,592,000 seconds (14–30 days, anchor created_at). Batch job records retained up to 365 days after terminal state. Poll ≥60s between status calls. Enqueued-token quota (Global Batch, Enterprise/MCA-E | Default | monthly card | MSDN): gpt-4.1 5B|200M|50M|90K; gpt-4.1-mini/nano & gpt-4o-mini & o3-mini & o4-mini 15B|1B|50M|90K; gpt-4o 5B|200M|50M|90K; gpt-5/5.1 5B|200M|50M|90K; gpt-5.2/5.4 family 5B|200M|50M|N/A; gpt-4-turbo 300M|80M|40M|90K; gpt-4 150M|30M|5M|100K. Data Zone Batch quotas generally lower (e.g. gpt-4.1 500M|30M|30M|90K). Fail-fast regions: australiaeast, eastus, germanywestcentral, italynorth, northcentralus, polandcentral, swedencentral, switzerlandnorth, eastus2, westus. Example exponential backoff: 5→10→20→40→80→160→320s.
- **Token-cost implication**: Route large offline jobs (data processing, content generation, doc summarization/review, extraction, NLP, personalization) through Batch for a flat 50% token-cost cut, isolated from online quota. Submit few large files (not many small ones) for best performance; set input-file expiration to raise per-resource file limits; enable dynamic quota and fail-fast queuing with exponential backoff to avoid enqueued-token-limit failures on very large workloads.
- **Caveats**: Vendor doc. 24-hour turnaround is a target, not guaranteed; no fine-tuned/embeddings-model support. Known issues: Azure-CLI-deployed resources' endpoint subdomains break global batch; UTF-8-BOM JSONL files are rejected; modifying the input blob after submission (BYOS) fails the job. Responses aren't returned in input order (hence custom_id). Successful jobs still emit an empty error file. Forward-dated model versions/pages (2026).
