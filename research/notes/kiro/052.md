# 052 — Cost per task: Using cheap classifiers to route across Gemini models and thinking levels
- **Source**: https://developers.googleblog.com/cost-per-task-using-cheap-classifiers-to-route-across-gemini-models-and-thinking-levels (Google, 2026-11)
- **Claim**: Per-token price is no longer the governing metric for agent economics; cost per successful task is. A near-free structured-output classifier (TypeSafe's Jev) placed in front of Gemini model calls can route each task to the cheapest model/thinking-level that still solves it, beating every single-model baseline on a 50-task coding benchmark.
- **Mechanism**: Instead of generating text, the classifier (Jev) evaluates structured primitives in a single forward pass — a Choice from a list, a numeric Score, or a Noul (0–1 probability for a binary statement). Routing is done by asking ONE atomic yes/no (Noul) question per factor rather than a broad "simple or complex" question (the broad version collapsed, routing nearly everything to "simple"). The working question: "does answering this require more than one sequential calculation, simulation step or logical deduction, rather than a single direct lookup/format check/one-step classification?" The router sends every task to Flash-Lite first and escalates only tasks Jev flags as complex to Gemini 3.8 Flash on LOW thinking. Key corollary: maxOutputTokens is only a ceiling, not a thinking-budget dial — set thinkingLevel:"LOW" directly instead. Alternative builds use the same Choice/Score/Noul API on DiffusionGemma (open-weights), billed by GPU-hour not token.
- **Numbers**: Benchmark = 50 questions, auto-graded, one run per setup, hand-assigned difficulty (25 hard tasks, 27 labeled SIMPLE). Local regex+length heuristic (escalate >35 words): 15/16 (93.8%) on the 16 tasks it was written on, dropped 23.2 points to 70.6% on 34 held-out tasks; 48/50 overall. Jev: 13/16 then 14/16 on initial set; 34/34 (100%) on held-out; 48/50 (96.0%) full suite. Flash-Lite alone: missed 6 of 25 hard tasks. Jev router (Flash-Lite → 3.8 LOW): 50/50. Gemini 3.8 Flash on LOW thinking alone: 50/50. maxOutputTokens=300 cap broke 7 of 25 hard tasks (6 ran out of room, 1 wrong). Context caching saves 75%–90% on resent context blocks. Pro configuration declined 2 short code-security prompts Flash answered. GPT-3 era reference not present.
- **Token-cost implication**: Start with a fast model on a light setting (Flash on thinkingLevel LOW) before building any router; it may already solve everything cheaper than default. Do not use low maxOutputTokens as a cost lever. Add a cheap classifier only to route short, standalone tasks; ask one yes/no question per factor, not one broad question. Keep long, context-heavy agent turns on ONE model so context caching keeps its discount (a cache belongs to one model; switching models loses it). Measure cost per successful task via trace/thinking-token logging to Cloud Logging/BigQuery.
- **Caveats**: Self-reported by Google; explicitly not an endorsement of TypeSafe (no partnership). Single run per setup, only 50 prompts, hand-assigned difficulty, simple automatic grading, short standalone prompts (not real long-context agent turns). Figures are single-run experimental measurements that will vary with prompt length, caching, and production load. Benchmark code "will be published after open-source review" (not yet available).
