# 259 — Batch API: Run Async Batch Inference at 50% Lower Cost (Fireworks)
- **Source**: https://fireworks.ai/blog/batch-inference-api (Fireworks, 2026-11; post dated JUL 31, 2025)
- **Claim**: Fireworks' Batch API runs large volumes of requests asynchronously on 1000+ open or fine-tuned models with no rate limits, 50% lower cost than synchronous Serverless, and a 24-hour turnaround.
- **Mechanism**: Upload a dataset in JSONL batch format (each line has a `custom_id` and a `body` with messages), create the dataset (`firectl create dataset ...`), launch a batch inference job (`firectl create bij --input-dataset-id ... --model ... --output-dataset-id ...`), poll status, then download results (`firectl download dataset ...`). Jobs run on base models, public community models, or your own fine-tuned variants. No upper limit on request count per job; dataset must be <500 MB.
- **Numbers**: 50% lower cost vs typical Serverless (synchronous) pricing. Turnaround: results in a few hours, max 24-hour turnaround. Dataset size limit <500 MB. No per-request rate limit. 1000+ models supported. Example model: accounts/fireworks/models/qwen3-14b. No absolute $/1M-token figures.
- **Token-cost implication**: Move any latency-tolerant bulk workload — evals/benchmarking, synthetic data generation for distillation, data augmentation (paraphrases, labels, QA pairs), daily ETL/document processing — to the Batch API to halve inference cost versus synchronous calls, accepting up to 24h latency.
- **Caveats**: Vendor blog, self-reported 50% discount, no independent benchmark. Only suitable for async/non-interactive work (up to 24h turnaround). Dataset capped at 500 MB per job. No concrete per-token prices given.
- **Topic**: pricing
