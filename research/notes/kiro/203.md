# 203 — Prompt Caching 101 (OpenAI Cookbook)
- **Source**: https://cookbook.openai.com/examples/prompt_caching101 (OpenAI, 2024-08)
- **Claim**: OpenAI automatically applies discounted prompt caching to prompts over 1024 tokens, giving up to ~80% latency reduction for long prompts (>10,000 tokens) by reusing a cached prefix across requests; no request change is required.
- **Mechanism**: Caching activates automatically for prompts >1024 tokens. On each request the system checks whether the prompt's beginning prefix is already cached; a cache hit reuses it (lower latency/cost), a miss processes the full prompt and caches the prefix for future use. Caching is scoped at the organization level (only same-org members share caches) and is ZDR-eligible (no data stored). Put static content (instructions, examples, tool/schema definitions, images) at the start of the prompt and variable/user-specific content at the end; tools and images must be byte-identical including ordering to be part of the prefix. Multi-turn: append new elements to the end of the messages array. Usage reports `usage.prompt_tokens_details.cached_tokens`; for images keep the `detail` parameter consistent since it affects tokenization. Caching discounts are based on actual tokens processed (including image tokens), which also count toward rate limits. Unused prompts are automatically evicted from the cache.
- **Numbers**: Discount threshold 1024 tokens (prompts under 1024 show cached_tokens = 0). Up to 80% latency reduction for prompts over 10,000 tokens. Worked tool example (gpt-4o-mini): run 1 prompt_tokens 1079, cached_tokens 0; run 2 prompt_tokens 1136, cached_tokens 1024. Image example (gpt-4o-2024-08-06): run 1 prompt_tokens 1548, cached_tokens 0; run 2 cached_tokens 1280; run 3 cached_tokens 0 (first image URL changed from veggie to eggs, breaking the prefix). No per-token prices in this doc.
- **Token-cost implication**: Place static instructions, tool/schema lists, and images at the front and user-variable content at the end to maximize prefix reuse; keep tool definitions and image ordering/detail identical across calls or the cache misses entirely (as shown by the run-3 miss from a reordered image). Maintain consistent/regular prompt usage to avoid eviction; monitor cached_tokens, hit rate, and latency.
- **Caveats**: OpenAI-authored cookbook; the "up to 80%" latency figure is self-reported and is a latency not cost claim, conditional on prompts >10,000 tokens. Page is archived and "may reference outdated models or APIs" (uses gpt-4o-mini / gpt-4o-2024-08-06, 2024-08). No dollar prices or cache-discount percentage given. Cache granularity appears to step in 1024-token (and image-token) increments per the examples.
- **Topic**: caching
