# 189 — Dynamic routes (Cloudflare AI Gateway)
- **Source**: https://developers.cloudflare.com/ai-gateway/features/routing/dynamic-routing (Cloudflare, 2026-11)
- **Claim**: Cloudflare AI Gateway's Dynamic Routing lets you compose a versioned request-routing flow (via visual editor or JSON) that evaluates conditions, enforces quotas, and picks models with fallbacks — changeable without touching application code.
- **Mechanism**: A Route is a named, versioned flow (e.g. `dynamic/support`) used in place of a model name. It is built from nodes: Start; Conditional (if/else on request body, headers, or metadata, e.g. `user_plan == "paid"`); Percentage (probabilistic split for A/B and gradual rollouts); Model (calls a provider/model); Rate Limit (request-count quota per key/period, switches to fallback when exceeded); Budget Limit (cost quota per key/period, switches to fallback); End. Custom Metadata (userId, orgId, plan) passed from the app can be referenced in conditionals. Each change is a draft version; deploy to go live with instant rollback. Requires gateway authentication plus upstream provider keys stored with BYOK.
- **Numbers**: none
- **Token-cost implication**: Route cheaper models to free/unpaid segments and premium models to paid users; add Budget Limit and Rate Limit nodes with fallbacks to a cheaper model to cap spend without code changes; use Percentage nodes to gradually roll out an expensive model. Iterate on cost policy by publishing a new route version rather than redeploying code.
- **Caveats**: Vendor doc, no cost/performance figures. Dynamic routes accept only the OpenAI chat-completions request shape (`/ai/v1/chat/completions`, Worker AI binding, or `/compat/chat/completions`); Anthropic Messages and `/ai/run` return 400. Routes are scoped to the gateway they were created on; must set `cf-aig-gateway-id` or requests resolve to the default gateway and 404.
- **Topic**: routing
