# 171 — Autoscaling (Hugging Face Inference Endpoints)
- **Source**: https://huggingface.co/docs/inference-endpoints/autoscaling (Hugging Face, n.d.)
- **Claim**: Hugging Face dedicated Inference Endpoints autoscale replica count based on accelerator utilization (or pending requests), and can scale to zero when idle, to balance cost against availability.
- **Mechanism**: Default scaling triggers on accelerator utilization — CPU: add a replica when average CPU utilization across replicas hits 80%; GPU: add a replica when average GPU utilization over a 1-minute window hits 80%. Scale-up checks run every 1 minute, scale-down every 2 minutes, with a 300-second stabilization window after scaling down. A beta alternative scales on pending requests (in-flight + processing): default threshold is >1.5 pending requests per replica over the past 20 seconds triggers adding a replica (adjustable in Endpoint settings). Scale-to-zero removes all replicas after 15 minutes of no requests (request-pattern based, not utilization), reintroducing a cold start; while a replica initializes the HTTP server returns 502 Bad Gateway, and there is no built-in request queue.
- **Numbers**: Scale-up trigger 80% average utilization (CPU; GPU over 1-min window). Scale-up evaluated every 1 min; scale-down every 2 min; 300s stabilization after scale-down. Pending-requests beta: >1.5 pending requests per replica over past 20s. Scale-to-zero after 15 minutes idle; returns HTTP 502 during cold start. Cold-start duration varies with model size.
- **Token-cost implication**: Enable scale-to-zero for spiky/low-traffic endpoints to avoid paying for idle GPUs, but budget for cold-start latency and implement a client-side request queue with 502 handling; tune the pending-requests threshold or utilization target to trade cost against throttling.
- **Caveats**: Vendor documentation, no cost figures or latency measurements; cold-start duration is unquantified ("varies depending on model size"). Pending-requests scaling is an experimental beta advised against untested production use. Long model-initialization times can cause false scale-downs. Full control over thresholds requires an Enterprise plan.
