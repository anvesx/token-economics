# 238 — Caching (Helicone advanced usage)
- **Source**: https://docs.helicone.ai/features/advanced-usage/caching (Helicone, 2026-11)
- **Claim**: Helicone's response caching stores complete LLM responses on Cloudflare's edge network to eliminate redundant identical API calls, reducing both latency and cost — distinct from provider-level prompt caching, and combinable with it.
- **Mechanism**: Enabled per request with the `Helicone-Cache-Enabled: "true"` header. Cache key is a hash of: optional cache seed, request URL, full request body (all parameters), relevant headers (auth + cache-specific), and bucket index — so any parameter change (content, temperature, etc.) creates a new entry. Responses stored in Cloudflare Workers KV across 300+ edge locations (not your infra). Config headers: `Cache-Control` max-age (duration), `Helicone-Cache-Bucket-Max-Size` (number of distinct responses stored per request, served randomly — for non-deterministic/creative prompts), `Helicone-Cache-Seed` (separate namespaces per user/context; changing it effectively clears the cache), `Helicone-Cache-Ignore-Keys` (comma-separated JSON keys excluded from key generation, e.g. request_id/timestamp/session_id; JSON bodies only). Response headers `Helicone-Cache` ("HIT"/"MISS") and `Helicone-Cache-Bucket-Idx` report status. Can combine with OpenAI/Anthropic provider prompt caching by ignoring `prompt_cache_key` so Helicone cache hits across different provider cache entries while still using provider caching.
- **Numbers**: Default cache duration `max-age=604800` (7 days). Maximum duration 365 days (`max-age=31536000`). Common durations: 1 hour (3600), 1 day (86400), 7 days (604800), 30 days (2592000). Default bucket size 1 (deterministic); maximum bucket size 20 (enterprise plans support more). Edge locations: 300+. Cache-seed/ignore-keys and headers as above. No cost-savings percentage given in this doc.
- **Token-cost implication**: During development/debugging and for genuinely identical repeated requests, enable Helicone caching (one header) to avoid paying for redundant calls and cut latency. Use `Helicone-Cache-Ignore-Keys` to drop non-semantic fields (tracking IDs, timestamps, session metadata, and `prompt_cache_key`) so legitimate cache hits are not missed. Use a cache seed per user to isolate caches; use bucket size >1 only for creative/non-deterministic prompts. This is exact-match response caching (a parameter change = miss), so it complements — does not replace — provider prefix/prompt caching; combine both for savings on each side.
- **Caveats**: Vendor documentation; no measured savings figures in this page (a linked dashboard image claims cost/time saved but no numbers). Exact-match only — any body/parameter change (including temperature) misses. Cache lives on Cloudflare KV edge, not caller infrastructure. Do not cache real-time, PII, or random/creative outputs. Ignore-Keys works only with JSON request bodies.
