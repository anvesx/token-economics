# 056 — Gain per-developer visibility into Kiro Enterprise credit usage
- **Source**: https://aws.amazon.com/blogs/aws-cloud-financial-management/gain-per-developer-visibility-into-kiro-enterprise-credit-usage (AWS, 2026-11)
- **Claim**: AWS introduces the Kiro Cost Optimizer, an open-source serverless solution that ingests Kiro Enterprise's daily per-user activity reports, accumulates month-to-date credit usage per developer, and emails tier up/downgrade recommendations to cut over- and under-provisioning waste.
- **Mechanism**: Single CloudFormation stack, three paths. (1) Daily processing: EventBridge triggers a Lambda at 3 AM UTC (1 hr after Kiro drops CSVs to S3); it discovers CSVs for the date (falls back to most recent prior report), merges credits across client types (IDE/CLI/web) per user, captures client types and models used, writes month-to-date rows to DynamoDB, renders a plain-text report with recommendations, archives to S3. (2) Scheduled SNS email on a daily/weekly/monthly cadence. (3) One-time backfill custom resource seeds DynamoDB from the 1st of the month on stack creation. Recommendation logic runs break-even analysis across all four tiers: UPGRADE recommendations always active (find cheapest higher tier whose total cost ≤ current spend, can skip tiers); DOWNGRADE only in the last 5 days of the month (when MTD is a reliable full-month proxy). DynamoDB 90-day TTL and S3 90-day lifecycle keep storage bounded. Least-privilege IAM; S3 AES-256 at rest, public access blocked; bucket policy grants s3:PutObject only to the Kiro service principal.
- **Numbers**: Kiro Enterprise tiers — Pro: 1,000 credits, $20/mo; Pro+: 2,000, $40/mo; Pro Max: 5,000, $100/mo; Power: 10,000, $200/mo. Overage rate $0.04/credit (all tiers). Example waste: Power user ($200/mo) using 800 credits = $180/mo wasted. Pro user ($20/mo) using 3,000 credits = $80 overage → $100 effective = same as Pro Max price (which gives 2,000 extra credits with zero overage). Solution cost <$ a few dollars/year for a 100-developer org. DynamoDB TTL = 90 days; S3 lifecycle = 90 days (current versions), noncurrent after 1 day. Lambda runs daily at 3 AM UTC. Sample report: 4 users, total savings $80/mo; bob@ PRO+ 7000 credits 350% usage → Upgrade to Pro Max saves $60/mo; alice@ PRO 2100 credits 210% → Upgrade to Pro+ saves $20/mo.
- **Token-cost implication**: Builders/admins of AI coding-agent fleets should treat tier-fit as a deterministic data-pipeline problem, not human judgment: accumulate per-developer month-to-date consumption and run break-even analysis against every price point, then correct tiers before the next billing cycle. A single tier correction recovers more than the tool's annual operating cost. Avoid premature downgrades by only recommending them late in the billing month.
- **Caveats**: Self-reported by AWS; it's a sample/open-source solution (aws-samples), not a managed product. Pricing "subject to change." Cost estimate (<$ a few dollars/year) is for a 100-developer org and combines S3/DynamoDB/SNS/Lambda/EventBridge. S3 lifecycle policy only auto-applies when use-existing-bucket=false. No independent measurement of savings; examples are illustrative.
