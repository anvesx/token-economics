# 040 — Bayesian Orchestration of Multi-LLM Agents for Cost-Aware Sequential Decision-Making

- **Source**: https://arxiv.org/abs/2601.01522 (arXiv / Independent Researcher — Danial Amin, 2026-01)
- **Claim**: Treating LLMs as discriminative classifiers that output p(state|evidence) and thresholding their scores is formally inadequate for cost-asymmetric sequential decisions; instead elicit likelihoods p(evidence|state) via contrastive prompting, aggregate across diverse LLMs with robust statistics, and apply Bayes' rule, which cuts total decision cost and improves fairness.
- **Mechanism**: Four impossibility theorems show discriminative posteriors can't support (1) sequential Bayesian belief updating, (2) prior correction for train/deploy base-rate mismatch, (3) cost-aware (expected-loss-minimizing) action selection, or (4) value-of-information (VOI) computation. The generative fix: for each candidate state s, prompt each LLM "assume the true state is s; how typical is this evidence?" scored 0–10, normalized to [0,1] as a likelihood estimate; query per state independently. Aggregate M models' likelihoods by the median (breakdown point 50% vs mean's 0). Apply Bayes with an explicit deployment prior π, update sequentially under conditional independence, choose the action minimizing expected cost, and gather more evidence when VOI > cost or when inter-model disagreement (coefficient of variation) exceeds τ_D=0.15. Instantiated on resume screening with a four-state quality space.
- **Numbers**: Hiring cost model — mis-hire $40,000 (30% of $130K salary), wasted interview $2,500–$3,000, phone screen $150. Cost asymmetries cited: hiring 16×, medical triage >200:1 (missed MI >$1M vs ICU $5,000/day), fraud 50× ($50 vs $2,500). Cost-optimal interview threshold derived as p(qualified) > ~5.88% (vs arbitrary 0.5/0.7). Experiments: 1,000 resumes, 5 LLMs (GPT-4o, Claude 3.5 Sonnet, Gemini Pro, Grok, DeepSeek). Results: total cost reduced by $294,000 (34% vs best single-LLM baseline); demographic parity improved 45% (max group gap 22→5 pp). Ablation contributions: multi-LLM aggregation 51% of savings, sequential updating 43%, disagreement-triggered info gathering 20%. Prior π = [0.65, 0.25, 0.08, 0.02]. Sensitivity: only 7.8% of decisions flip under ±20% cost perturbation. VOI informativeness ρ: phone screens 0.7, coding tests 0.85, reference checks 0.6. Per-iteration ~20 LLM queries ≈20 s (parallelizable to 1–2 s). Human validation: Fleiss' κ=0.79, Cohen's κ=0.83, 89% exact match. Example LLM prior mismatch inflates p(qualified|x) 0.15→0.60 (~4×). Temperature 0.7, max tokens 10; parsing failures <1%.
- **Token-cost implication**: Each decision costs K×M LLM calls (states × models), so this is expensive per decision but justified where error costs dwarf inference costs and where sequential info-gathering (VOI) can skip unnecessary follow-up steps. Use median aggregation over diverse models for robustness/fairness, set explicit deployment priors to avoid training-base-rate bias, and parallelize the K×M queries.
- **Caveats**: Self-reported by a single independent author; resumes are synthetic (GPT-4o-generated from sampled features), so labels are proxies, not real hiring outcomes. Phone screens are simulated, not real. Only one domain (resume screening) is actually evaluated despite framing around triage/fraud. Conditional-independence assumption may not hold. Ablation percentages sum to >100% (overlapping contributions). High per-decision latency limits real-time use. Some draft artifacts remain (self-corrected arithmetic, unresolved section references).
