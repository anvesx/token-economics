# 231 — Prompt caching best practices (OpenRouter)
- **Source**: https://openrouter.ai/docs/guides/best-practices/prompt-caching (OpenRouter, 2026-11)
- **Claim**: OpenRouter supports prompt caching across providers (some automatic, some requiring explicit `cache_control` breakpoints) and uses provider "sticky routing" to keep caches warm, documenting the per-provider cache-write and cache-read price multipliers so builders can predict savings.
- **Mechanism**: After a cached request, OpenRouter remembers the serving provider and routes subsequent same-model requests back to it (only when cache-read pricing is cheaper than regular prompt pricing). Stickiness is tracked per account, per model, per conversation (conversation identified by hashing the first system + first non-system message, or by an explicit `session_id` / `x-session-id` header ≤256 chars, else falling back to OpenAI `prompt_cache_key`). With `session_id`, stickiness activates on any successful request (even before a cache hit); without it, only after a cache hit. Sessions expire after 60 minutes of inactivity (reset per request). Not used when manual `provider.order` is set. Cache usage is reported in `usage.prompt_tokens_details` (`cached_tokens`, `cache_write_tokens`) and `cache_discount`. Anthropic supports automatic (top-level `cache_control`, advances breakpoint as conversation grows) or explicit per-block breakpoints (max 4). Block-level markers translate between providers (Anthropic `cache_control` ↔ OpenAI `prompt_cache_breakpoint`), but TTLs are not translated.
- **Numbers**: Cache-read / cache-write price multipliers vs original input price by provider — OpenAI: reads 0.25x or 0.50x (model dependent); writes free before GPT-5.6, 1.25x on GPT-5.6+ (explicit 30-min TTL writes 1.25x, 12-hour TTL writes 2.5x); min prompt 1024 tokens. Grok: writes free, reads 0.25x. Moonshot: writes free, reads 0.25x. Groq: writes free, reads 0.5x (Kimi K2 models). Alibaba Qwen (explicit): writes 1.25x, reads 0.1x, 5-min TTL. Anthropic: writes 1.25x (5-min TTL) or 2x (1-hour TTL), reads 0.1x; min cacheable prompt 512 / 1,024 / 2,048 / 4,096 tokens depending on Claude model. DeepSeek: writes 1x (same as input), reads 0.1x. Z.AI: writes free (limited-time), reads ~0.2x. Google Gemini (implicit, 2.5+): no write/storage cost, reads 0.25x, TTL ~3-5 min, min 1024 (2.5 Flash) / 4096 (2.5 Pro) tokens; explicit Gemini cache write = input price + storage×(5/60). Usage example: prompt_tokens 10339, cached_tokens 10318, cache_write_tokens 0. Session_id/x-session-id max 256 chars. Sticky session expiry 60 minutes.
- **Token-cost implication**: Structure prompts with the large, stable content (system prompt, RAG data, book/CSV) first and the dynamic/variable part last so the cache prefix is reused. Pass a stable `session_id` for multi-turn agentic flows to pin the provider and start caching from request one. On GPT-5.6+ a 1024+ token prompt sent only once costs MORE with caching on (1.25x write, no read benefit) — disable caching per request (explicit mode, no breakpoints) for one-off prompts. Use 1-hour (Anthropic) / 12-hour (OpenAI) TTLs for long sessions to avoid repeated write costs. In the Batch API, use shared-prefix 1h breakpoints and reuse across batches for reliable hits.
- **Caveats**: Vendor documentation; no measured savings figures, only price multipliers. Provider behavior differs (inclusive vs exclusive token counts, min token thresholds, TTL that may/may not refresh). Gemini implicit cache TTL varies (~3-5 min, not guaranteed). Negative "discount" on cache writes for some providers (Anthropic). Point-in-time prices.
