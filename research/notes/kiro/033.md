# 033 — More Agents Is All You Need

- **Source**: https://huggingface.co/papers/2402.05120 (Hugging Face paper page / authors Junyou Li, Qin Zhang, Yangbin Yu, Qiang Fu, Deheng Ye — Tencent, 2024-02)
- **Claim**: A simple sampling-and-voting method makes LLM performance scale with the number of instantiated agents (samples), and this gain is orthogonal to other enhancement methods, with the degree of improvement correlated to task difficulty.
- **Mechanism**: Sample the same LLM many times for a query, then select the final answer by majority voting across the sampled outputs ("sampling-and-voting"). Effectiveness increases with the number of agents and is complementary to existing complex prompting/ensemble methods. (This note is based on the Hugging Face paper page; the page provides the abstract and community discussion rather than full method/results tables.)
- **Numbers**: none (the Hugging Face page gives no benchmark figures beyond qualitative claims; community comments note diminishing/asymptotic returns and a possible performance ceiling around n=30 agents, but these are commenters' remarks, not measured results in the page text).
- **Token-cost implication**: You can trade inference-time compute (more sampled generations + majority vote) for accuracy without changing the model or prompt, and stack it on top of other methods — but expect diminishing returns, so pick the agent count where the accuracy gain still justifies the multiplied token cost. A community suggestion: use the voting results to generate training data (e.g., for DPO), spending ~15× inference to improve the model.
- **Caveats**: The Hugging Face page lacks the paper's quantitative results; claims here are from the abstract only. Community critiques (Onay91, MichaelBarryUK) argue "all you need" overstates it given asymptotic returns and a ceiling possibly below SOTA, likening it to crowd-wisdom / agentic tree-of-thought. Not independently verified in this document; code link given but not evaluated here.
- **Topic**: agent-cost
