# 201 — Prompt caching
- **Source**: https://developers.openai.com/api/docs/guides/prompt-caching (OpenAI, no date)
- **Claim**: OpenAI prompt caching reuses KV state for an unchanged prompt prefix, discounting cached input up to 95%; on GPT-5.6 and later it adds explicit breakpoints, paid cache writes and selectable lifetimes, so prefix design and breakpoint placement now drive cost.
- **Mechanism**: Caches KV tensors (not text) of the full rendered context (hidden system message, tools, developer message, history) and needs an exact prefix match up to a breakpoint. Settings that alter the prefix: model, tools, parallel_tool_calls, text.format, reasoning.effort, text.verbosity, context_management (compaction). GPT-5.6+: implicit mode puts a breakpoint at the end of the latest eligible message; explicit mode (`prompt_cache_options.mode: "explicit"`, `prompt_cache_breakpoint`) writes only where chosen, so changing suffixes incur no write charge; up to 4 cache writes per request (implicit uses one). `ttl` of "30m" (default) or "12h" (Responses API), overridable per breakpoint. Prewarm (`prompt_cache_options.prewarm: true`) fills the cache without output to cut time to first token. Earlier models: implicit breakpoints at model-dependent intervals (GPT-5.5: 2,048-token intervals), cached_tokens rounded down to a multiple of 128, `prompt_cache_retention` of in_memory (about 5-10 minutes inactive, up to 1 hour) or 24h; stable `prompt_cache_key` helps routing. Routing depends on load and a hash of the initial tokens; caches are per organization and region. Optimization advice: stable instructions first, dynamic content (timestamps, user data) last, append rather than rewrite history, keep tools stable (tool_choice "none", allowed_tools, defer_loading tool search), change reasoning effort via a configuration_update input item on GPT-6 models, separate prompt_cache_key per customer for accounting and to prevent cache-hit probing. Gotchas: a shared prefix is not cached unless a breakpoint ends there; switching from implicit to explicit mode can miss earlier implicit writes; extending a message after its cache endpoint breaks reuse; later developer messages are not implicit lookup boundaries; compaction lowers reuse.
- **Numbers**: Cached-input discount up to 95%. GPT-5.6+: minimum cacheable prefix 1,024 visible tokens; write 1.25x uncached input rate for 30m, 2.5x for 12h; read 0.1x (0.05x for GPT-6.1 Sol and GPT-6.1 Terra). One write plus one full reuse = 1.35x vs 2x uncached; one write plus nine reads over ten requests = 2.15x vs 10x. Explicit lookup boundaries: first 2 and latest 50 breakpoints; implicit adds up to 20 earlier message endings. Up to 4 writes per request. Overflow routing above 15 requests per minute per key. Worked example: 12,000 input tokens written, then 15,000 input with 12,000 cached and 3,000 written. Usage example: 12,000 input, 4,000 cached, 7,000 written (3,000 at 30m, 4,000 at 12h), 1,000 ordinary; at $1 per million input and $0.10 cached the cost is $0.01515. Break-even for padding a short prefix to M=1,024 with r=0.1, w=1.25: crossover 102.4 + 1,177.6/N tokens; at N=10, expanding a prefix of at least 221 tokens is cheaper; 103 tokens needs at least 1,963 requests; 102 or fewer never pays. Example deployments reported cache-hit rates of about 70% (single-turn LLM judge, explicit mode) and over 90% (multi-turn agent), stated as illustrative. Max KV retention 24 hours. Zero Data Retention default retention: 24h without ZDR, in_memory with ZDR.
- **Token-cost implication**: Cached input is 0.1x (0.05x on some models), but writes cost 1.25x or 2.5x, so cache only content that will be reused: use explicit breakpoints after stable prefixes and leave volatile tails uncached. Keep tools, model, effort, verbosity and history stable, append-only. Weigh the 12h write rate against rewriting after 30m expiry. Prefixes under 1,024 tokens get no caching; padding can pay off only above the break-even lengths. Track cached_tokens, cache_write_tokens and the cache-hit rate (cached tokens / input tokens), and compute cost with the multipliers.
- **Caveats**: Vendor documentation; hit-rate figures are examples, not guarantees. Cached tokens still count toward rate limits. Cache lifetime is a minimum, and a minimum lifetime does not guarantee lower latency. Rates differ by model; earlier models have no extra write charge but model-dependent cached rates not given here. Cache cannot be manually cleared. The file includes a lot of code samples and interactive-widget text.
