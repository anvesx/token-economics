# 167 — Full-Stack Optimizations for Agentic Inference with NVIDIA Dynamo
- **Source**: https://developer.nvidia.com/blog/full-stack-optimizations-for-agentic-inference-with-nvidia-dynamo/?linkId=100000419241070 (NVIDIA, 2026-04-17)
- **Claim**: Agentic coding workloads are write-once-read-many for KV cache, so self-hosted serving should expose harness knowledge (priority, output length, cache TTL, session lifecycle) to the router and cache manager instead of treating requests as anonymous tokens.
- **Mechanism**: (1) Frontend: serves v1/chat/completions, v1/responses, v1/messages through one internal representation; `nvext.agent_hints` = `priority`, `osl` (expected output tokens), `speculative_prefill`; `nvext.cache_control` `{type: ephemeral, ttl: 1h}` pins the prefix in the worker radix tree for the TTL. (2) Router: global Flash Indexer of KV blocks per worker; picks the worker minimizing cache-miss plus decode-load cost; priority queue (BinaryHeap by effective arrival time, only used when all workers exceed a load threshold, `--router-queue-threshold`); Python bindings (`best_worker`, `get_potential_loads`, `generate`) allow custom routers, e.g. `overlap_score_weight` 2.0 for contexts over 8192 tokens. (3) KV cache: four tiers (GPU, CPU, local NVMe, remote) with write-through and deduplication by sequence hash so subagents load shared prefixes via NIXL RDMA instead of recomputing; selective retention (priority per block range, duration; TensorRT-LLM TokenRangeRetentionConfig); planned prefetch hooks and ephemeral-session tagging so subagent KV, summarized context and closed `<think>` blocks are evicted first and not written to shared storage.
- **Numbers**: Claude Code sessions (measured on managed API): 85-97% cache hit after first call; 97.2% aggregate hit across 4 Opus teammates; read/write ratio 11.7x for lead agent's explore subagents (91.3% hit) vs 5.0x for teammates (79.4% hit). Without cache-aware routing turn 2 has ~1/N chance of landing on the same worker. ~32K-token system prompt+tools recomputed per worker; 4 subagents means 4 prefills become 1 compute + 3 loads. Context summarization ~175K to ~40K tokens. `<think>` blocks ~40% of generated tokens. Tool-call pauses of 2-30 seconds can age out prefixes under LRU. NeMo Agent Toolkit custom Thompson-Sampling router vs default Dynamo routing: 4x lower p50 TTFT, 1.5x higher p50 tokens/sec; priority tagging up to 63% p50 TTFT reduction under moderate memory pressure. Flash Indexer 170M ops/s. Cited adoption: Stripe 1,300+ agent PRs/week, Ramp 30% of merged PRs, Spotify 650+ agent PRs/month.
- **Token-cost implication**: For agent workloads, cache hit rate dominates cost: keep stable prefixes (system prompt, tools) first, route to workers with prefix overlap, pin prefixes across tool-call gaps, share prefixes across subagents, and do not cache reasoning/ephemeral blocks. When self-hosting, replicate managed-API behavior (prefix cache, TTL pinning) or expect cold-start recomputation.
- **Caveats**: NVIDIA vendor blog describing partly in-progress features (prefetch, session tagging, cross-worker retention are future work; agent_hints is a v1 API). Claude Code cache statistics are from NVIDIA's own analysis of sessions, methodology not detailed. NAT router figures are internal and "available soon".
