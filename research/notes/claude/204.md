# 204 — Prompt cache diagnostics
- **Source**: https://developers.openai.com/api/docs/guides/prompt-caching/diagnostics (OpenAI, no date)
- **Claim**: OpenAI's Responses API can explain why a request reused fewer cached tokens than expected by comparing it with an earlier response and returning a miss reason.
- **Mechanism**: Set `prompt_cache_options.comparison_response_id` to a baseline response id (same organization); read `prompt_cache_diagnostics` on the new response (in the `response.completed` event when streaming). Types: cache_hit, cache_miss (with reason, cache_missed_tokens, maybe comparison_reusable_tokens), comparison_response_not_found, unavailable. Reasons and fixes: model_changed (routing, A/B test, fallback), prompt_cache_key_changed (omit key unless separate accounting needed, keep it stable), service_tier_changed, tools_changed (keep definitions and order stable; use tool_choice "none" or allowed_tools instead of changing the list), text_format_changed, reasoning_effort_changed (on GPT-6 and later append a configuration_update input item), verbosity_changed, context_compacted (compare total input cost; fewer input tokens can still save money), input_changed (move timestamps and request IDs after the reusable prefix; append, do not edit or reorder). Setting the comparison id only requests diagnostics; it does not load the earlier conversation or alter caching. Reuse needs an exact prefix match and compatible model, service tier and tools. Verify the fix via cached_tokens, cache_write_tokens and total cost across several requests.
- **Numbers**: Minimum cacheable length 1,024 tokens for GPT-5.6 and later. Example miss: reason tools_changed, comparison_reusable_tokens 5629, cache_missed_tokens 5629 (token counts vary). Example hit: 2,500 input tokens with a 2,000-token reused prefix and 500 new tokens still reports cache_hit. Diagnostics have no extra cost and no separate rate-limit count; extra baseline or retry requests are billed normally.
- **Token-cost implication**: Cache misses silently turn cheap cached input into full-price input. Keep model, tool list and order, service tier, text format, reasoning effort, verbosity and early messages stable, put changing content late, and use diagnostics to find which change caused a miss. Switching models via routing or fallback, or compaction, can cost cache reuse; weigh against input savings.
- **Caveats**: Available only in the Responses API for GPT-5.6 and later supported models. Records expire after a short period (comparison_response_not_found). Reports only the first classified reason, is best effort, and counts can differ from usage counts; use usage fields for billing. ZDR compatible (stores metadata, estimates and hashes only). No hit-rate or savings percentages given.
- **Topic**: caching
