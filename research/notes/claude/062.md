# 062 — Inference economics of language models
- **Source**: https://arxiv.org/abs/2506.04645 (Epoch AI, Ege Erdil, arXiv, 2025-06)
- **Claim**: A theoretical model of LLM serving trades off serial token generation speed against cost per token, accounting for arithmetic, memory bandwidth, network bandwidth and latency, and optimising over parallelism and batch size. It reproduces observed API provider speeds and prices for open models within roughly a factor of 2.
- **Mechanism**: Token latency is the maximum of parameter-read time (p*N/(NGPU*B)) and arithmetic time (2N*b/(NGPU*C)), plus per-layer all-reduce latency (n_layers * n_reduce * t_reduce, with t_reduce growing with instance size, about 2 us * (NGPU^(1/2) - 1)). Cost is GPU-seconds per token times an hourly GPU rental rate. The optimal batch size b* = p*C/(B*2 FLOP) balances memory and arithmetic. Extensions model KV cache reads for long context (grouped-query attention and DeepSeek multi-head latent attention), mixture-of-experts expert parallelism, quantisation, newer GPUs, and speculative decoding. Output is a Pareto frontier of tokens/s per request versus dollars per million tokens. Code is in the authors' GitHub repository.
- **Numbers**: Assumes H100 SXM at $2/hour (V100 SXM $0.42/hr also used for comparison). Artificial Analysis 2024 (as cited): about 400 tokens/s at 20 cents per million tokens for Llama 3 8B and about 150 tokens/s at 90 cents per million tokens for Llama 3 70B (both Fireworks, Groq excluded). Providers are within a factor of 2 of the model's maximum speed, with markup over GPU rental of less than 2x. Speed scales roughly as 1/sqrt(N params): from Llama 3 8B at 400 tokens/s the model predicts 135 tokens/s for a 70B dense model and 56 tokens/s for a 405B dense model. Doubling memory bandwidth cuts token latency by about 20% or less in short context (Groq LPU 80 TB/s versus H100 3.3 TB/s gives only a 2 to 3x latency gap). Speculative decoding with Llama 3 8B at 80% acceptance: +66% throughput for Llama 3 70B and 2x for Llama 3.1 405B at a fixed cost per token. Typical acceptance rates 0.7 to 0.9. Halving weight precision reduces token latency by about 20%. Each new NVIDIA GPU generation raises tokens/s at fixed cost by about 25% and halves the Pareto instance size. Llama 3 70B at 16-bit at 100% H100 utilisation costs about $0.11 per million tokens, implying about 17% utilisation in the model's table; prefill utilisation is expected to be 50% or more; decode utilisation is 3 to 5 times lower than prefill. Long context: Mistral Large 2 has about 360 KB KV cache per token, so a 100K context costs a lower bound of $6.06 per million output tokens from KV reads alone; DeepSeek-V3 (about 60 KB per token) is about 6x cheaper at long context.
- **Token-cost implication**: Expect fast output to cost disproportionately more than slow output, and long contexts to cost much more per output token because KV cache reads dominate. Prefer providers and models with small KV caches (GQA with large groups, MLA) for long-context workloads, price input tokens below output tokens, and favour providers that use speculative decoding and quantisation when buying latency-sensitive capacity. When judging a quote, compare it to this roofline: price near GPU rental cost times utilisation is plausible for open models.
- **Caveats**: Theoretical model by one Epoch researcher, validated against third-party provider data (Artificial Analysis 2024) rather than measured by the author. Short-context focus for most results, H100-era hardware, assumes fixed context length across a batch, and neglects some scheduling optimisations. Prefill and decode are not jointly modelled in detail. Numbers are model predictions and lower bounds, not provider prices.
