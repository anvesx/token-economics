# 228 — Auto Router: Smart AI Model Selection
- **Source**: https://openrouter.ai/docs/guides/routing/auto-model-selection (OpenRouter, no date given)
- **Claim**: OpenRouter's Auto Router (openrouter/auto) picks both a model and a reasoning effort per request using a fast decision model, with no extra fee over the selected model's standard rate. Variants: Auto Code (coding agents) and Auto Beta (experimental).
- **Mechanism**: (1) Narrow the pool by guardrails, zero data retention, capabilities, provider restrictions, BYOK keys and allowed/excluded lists. (2) A fast decision model rates eleven aspects of the request in one call (task type, task change, difficulty, speed need, vision/codebase need, whether more thinking helps). (3) The policy weighs the rating against live prices, cache status and benchmark performance within the cost tier to pick model and reasoning effort. (4) Normal provider routing. (5) Later turns use session signals (struggling model, cached context). Session stickiness: switching models forces a prompt cache rebuild, so the router prefers changing reasoning effort and switches model only when worthwhile (task change, repeated error, failing tests); sessions identified by session_id or message fingerprint. Controls: allowed_models and excluded_models with wildcard patterns (exclusions win); cost_tier low | medium | high (xhigh and max route as high); provider.max_price caps endpoint price; account-level defaults with a "prevent overrides" toggle. X-OpenRouter-Metadata: enabled returns routing reasons and estimated costs per candidate. Constraints: conversational input only, global data region only, do not combine with another router model.
- **Numbers**: none (no price or savings figures). The default policy costs more per task than the previous router generation; cost_tier low keeps cost closer to the old behavior.
- **Token-cost implication**: Use a router for mixed traffic but set cost_tier explicitly and a stable session_id so cache is preserved; restrict models for compliance or cost ceilings; inspect router metadata to audit picks.
- **Caveats**: Vendor docs, no benchmark numbers in this page (a separate Model Routing Benchmarks page is referenced). The default policy raises per-task cost versus the previous generation. The page ends with a large site-config blob with no content.
