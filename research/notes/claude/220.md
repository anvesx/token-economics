# 220 — Claude API overview (batch and token counting)
- **Source**: https://platform.claude.com/docs/en/api/overview (Anthropic, no date given)
- **Claim**: Overview of the Claude API surface. Two cost-relevant endpoints: the Message Batches API (50 percent cost reduction for asynchronous processing) and the Token Counting API (count tokens before sending).
- **Mechanism**: POST /v1/messages/batches processes large volumes of Messages requests asynchronously; POST /v1/messages/count_tokens returns the token count of a message before it is sent, for managing cost and rate limits. Limits are organized in usage tiers with monthly spend limits, requests per minute and tokens per minute (token bucket algorithm). Workspaces in the Console separate environments and control spend by use case. Request size limits: Messages and Token Counting 128 MB; Message Batches 256 MB; Files 500 MB; Sessions, Agents, Environments 32 MB. Bedrock 20 MB, Google-managed Claude 30 MB.
- **Numbers**: Batch API 50 percent cost reduction. Request size limits as above (128 MB / 256 MB / 500 MB / 32 MB).
- **Token-cost implication**: Route non-interactive workloads to batch for half price; call count_tokens to pre-check cost; use per-workspace keys and spend limits to cap budgets by use case.
- **Caveats**: Reference page only; no pricing per token, turnaround time for batches or caching rules in this text. Vendor doc.
- **Topic**: pricing
