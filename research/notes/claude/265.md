# 265 — Clarifying our pricing (Cursor)
- **Source**: https://cursor.com/blog/june-2025-pricing (Cursor, 2025-07)
- **Claim**: Cursor apologizes for its unclear June 2025 Pro plan change and explains the move from request-based pricing to a $20 monthly usage pool at API prices, because hard requests cost about an order of magnitude more than simple ones.
- **Mechanism**: Pro gives unlimited Tab and Auto-mode usage plus $20/month of frontier model usage at API pricing; extra usage can be bought at cost with a spend limit. Auto routes automatically to different frontier models based on capacity. A short grace period follows exhaustion of the credit pool. Earlier scheme: 500 requests per month, Sonnet models counting as two requests.
- **Numbers**: $20 included frontier usage per month. Based on median token usage the pool covers about 225 Sonnet 4 requests, 550 Gemini requests, or 650 GPT 4.1 requests. Previous cap: 500 requests/month, Sonnet = 2 requests. Refunds for unexpected usage between June 16 and July 4, 2025.
- **Token-cost implication**: Flat per-request pricing breaks when per-request tokens vary by 10x on long-horizon agent tasks; vendors move to token-priced usage pools. Builders should budget by tokens and expect routing (Auto) to be the default cost lever.
- **Caveats**: Self-reported by Cursor; "median token usage" is not defined further; no per-token prices given.
- **Topic**: pricing
