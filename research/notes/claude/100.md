# 100 — Do All Languages Cost the Same? Tokenization in the Era of Commercial Language Models
- **Source**: https://arxiv.org/abs/2305.13707 (arXiv, University of Washington / CMU / AI2, Ahia et al., 2023-05)
- **Claim**: Because API vendors bill per token and subword tokenizers fragment non-Latin scripts into many more tokens, speakers of many languages pay more for the same content and get worse results (less room for few-shot examples and a shorter usable context).
- **Mechanism**: Tokenize the parallel FLORES-200 corpus with ChatGPT's tokenizer (gpt-3.5-turbo) and compare the average tokens per sentence by language and script; convert to estimated cost relative to English. Train byte-level BPE tokenizers on parallel text, one language per script, with vocabulary sizes from 5,000 to 50,000, to separate data-imbalance effects from script properties. Measure ChatGPT (4096-token limit) and BLOOMZ (1000-token API limit) k-shot performance on XNLI, XFACT, XQUAD, CrossSum and XLSUM (at most 500 test examples per task, English instructions). Correlate cost, utility and the Human Development Index.
- **Numbers**: Languages with their own script (for example Telugu, Georgian) need up to 5x more tokens than Latin-script languages for the same content. Mid-resourced Indic non-Latin languages show close to 5x the cost vs English. On XLSUM, prompt plus generation cost is up to 4x English for Telugu and Amharic (zero-shot costs). For Telugu and Amharic, most test examples cannot fit even one in-context example in ChatGPT's 4096-token window. Cost vs HDI correlation: Spearman -0.41 to -0.42, Pearson -0.43 to -0.60 across the three tasks (significant). Trained BBPE tokenizers could not reach uniform fragmentation across scripts even with large vocabularies. Prices were not quoted in the text I read.
- **Token-cost implication**: Budget tokens per language, not per word: measure tokens per request in each target language with the actual tokenizer before forecasting spend or choosing a model. For non-Latin-script traffic, expect fewer few-shot examples to fit and higher per-request cost, so prefer models with more efficient tokenizers (a newer vocabulary), shorter prompts and English instructions, or translate where quality allows.
- **Caveats**: 2023 paper using gpt-3.5-turbo and a 4096-token limit; newer tokenizers (larger vocabularies) may have narrowed the gaps and were not measured. Independent academic measurement, but cost is estimated from token counts, not from actual bills. The training-data assumption for ChatGPT is a hypothesis (training details are not public). BLOOMZ was accessed via a free Hugging Face API with a 1000-token limit and did not benefit from in-context examples. Most figure values were garbled in the extraction.
- **Topic**: pricing
