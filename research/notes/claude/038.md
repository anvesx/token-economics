# 038 — How NVIDIA GB200 NVL72 and NVIDIA Dynamo Boost Inference Performance for MoE Models
- **Source**: https://developer.nvidia.com/blog/how-nvidia-gb200-nvl72-and-nvidia-dynamo-boost-inference-performance-for-moe-models (NVIDIA, 2025-06-06)
- **Claim**: Splitting prefill and decode onto separate GPU pools (disaggregated serving, managed by Dynamo) plus wide expert parallelism on a 72-GPU NVLink domain raises MoE serving throughput (6x for DeepSeek R1 in simulation) and dense-model throughput (up to 3x for Llama 70B).
- **Mechanism**: Prefill (token-parallel, TTFT SLA) and decode (autoregressive, inter-token latency SLA) are run on different GPUs so each gets its own parallelism (TP/PP/DP/EP) and GPU count. For MoE decode, wide expert parallelism puts few experts per GPU, spreading compute and freeing memory for KV cache and bigger batches. Dynamo moves KV cache between prefill and decode GPUs, routes requests to decode GPUs holding the right KV cache, and its Planner uses prefill queue time, decode KV-cache utilization and SLAs to scale GPUs and rate-match prefill vs decode (Kubernetes scaling), and can fall back to aggregated serving for some requests. GB200 NVL72 provides one NVLink domain of 72 Blackwell GPUs so the all-to-all among experts avoids slower internode links.
- **Numbers**: DeepSeek R1 disaggregated vs co-located: 6x throughput in the medium latency regime (simulation). Llama 70B: up to 3x throughput in same regime. DeepSeek R1 routes each token to 8 of 256 experts; about 4 experts per GPU, 64 GPUs for decode. NVLink: 1.8 TB/s per GPU, up to 72 GPUs (vs 8 GPUs at 900 GB/s on HGX H200), 36x faster than 400 Gbps Ethernet, 130 TBps aggregate all-to-all, up to 260 TBps all-reduce. Llama 70B tensor parallelism scales from 2 to 64 GPUs as latency tightens. Results come from a data-center-scale GPU performance simulator over hundreds of thousands of design points.
- **Token-cost implication**: For self-hosted high-volume serving, throughput per GPU (hence cost per token) depends on separating prefill from decode and matching capacity to ISL/OSL mix; benefit is largest for long input (prefill-heavy) traffic. API buyers cannot act on it directly but it explains provider price/throughput differences.
- **Caveats**: Vendor blog (NVIDIA) promoting its own hardware and software; results are simulated, not measured in production; medium-latency regime only; requires NVL72-class hardware for the headline MoE gain.
- **Topic**: serving
