# 184 — DeepSeek-V3.2: Pushing the Frontier of Open Large Language Models
- **Source**: https://arxiv.org/abs/2512.02556 (DeepSeek-AI, 2025-12)
- **Claim**: DeepSeek Sparse Attention (DSA) cuts long-context attention cost from O(L^2) to O(Lk) without noticeable quality loss, and scaled RL plus synthesized agent tasks gets DeepSeek-V3.2 to roughly GPT-5 level on reasoning at lower token cost; the high-compute Speciale variant matches Gemini-3.0-Pro but spends far more tokens.
- **Mechanism**: A lightning indexer (few heads, ReLU, FP8) scores preceding tokens and a top-k selector passes only those KV entries to attention (built on MLA in MQA mode). Trained by a dense warm-up (indexer only) then sparse training. Agent thinking context management: reasoning content is discarded only when a new user message arrives; it is kept across tool-result-only turns, and tool call and result history is always kept, avoiding re-reasoning per tool call (frameworks that simulate tool calls as user messages, such as Roo Code or Terminus, do not benefit; non-thinking mode is recommended there). Search-agent context management triggered above 80% of the context window: Summary, Discard-75%, Discard-all, versus a Parallel-fewest-step baseline.
- **Numbers**: Core attention O(L^2) to O(Lk); indexer still O(L^2) but much cheaper. 2048 key-value tokens selected per query. Warm-up: 1000 steps, 2.1B tokens. Sparse stage: 15000 steps, 943.7B tokens. Base context 128K. Inference cost estimated on H800 at a rental price of 2 USD per GPU hour; Figure 3 plots cost per million tokens versus token position for V3.1-Terminus and V3.2 (prefilling axis up to 0.7$, decoding axis up to 2.4$; exact per-point values are not given in the text). RL post-training compute exceeds 10% of pre-training cost. 1,827 synthesized environments, 4,417 general-agent tasks (Table 1: code agent 24,667; search agent 50,275; general agent 4,417; code interpreter 5,908). Table 3 accuracy (output tokens in thousands) for V3.2-Thinking vs Speciale: AIME 2025 93.1 (16k) vs 96.0 (23k); HMMT Feb 2025 92.5 (19k) vs 99.2 (27k); IMOAnswerBench 78.3 (27k) vs 84.5 (45k); Codeforces 2386 (42k) vs 2701 (77k); GPQA 82.4 (7k) vs 85.7 (16k); HLE 25.1 (21k) vs 30.6 (35k). Comparators in the same table: Gemini-3.0-Pro AIME 95.0 (15k), HMMT Feb 97.5 (16k), Codeforces 2708 (22k), HLE 37.7 (15k); GPT-5 High AIME 94.6 (13k), Codeforces 2537 (29k); Kimi-K2 Thinking AIME 94.5 (24k), HMMT Feb 89.4 (31k). Agent results (V3.2 thinking): SWE Verified 73.1, Terminal Bench 2.0 46.4 (non-thinking 37.1; Terminus non-thinking 39.3), tau2-bench categories Airline 63.8, Retail 81.1, Telecom 96.2. BrowseComp 51.4 without context management, 67.6 with (Discard-all); Summary reached 60.2 with average 364 steps; over 20% of BrowseComp cases exceed the 128K limit. Context window for evals 128K, temperature 1.0.
- **Token-cost implication**: Long-context cost per token falls with DSA, especially at large token positions. For agents, keep reasoning traces across tool-only turns to avoid repaid reasoning; add an overflow strategy (Discard-all was most step-efficient) at about 80% context. Compare models on tokens spent per task, not accuracy alone: Speciale uses roughly 1.4x to 1.8x the output tokens of V3.2-Thinking on several benchmarks for gains of a few points (computed from Table 3).
- **Caveats**: Vendor paper; cost figures rest on an assumed 2 USD per H800 hour and are shown only as a chart; the authors say V3.2 still needs longer trajectories than Gemini-3.0-Pro and frequently does redundant self-verification that blows past 128K on MCP benchmarks; results depend on length-constraint reward.
