# 149 — Model router for Microsoft Foundry concepts
- **Source**: https://learn.microsoft.com/en-us/azure/ai-foundry/openai/concepts/model-router (Microsoft, page last updated 2026-10-30)
- **Claim**: Model router is a trained language model deployed like any Foundry model that picks, per request, an underlying LLM based on prompt complexity, reasoning need and task type, to cut cost and latency at comparable quality.
- **Mechanism**: Router analyses the prompt in real time (does not store it) and routes only to eligible models given access, deployment type and data zone. Modes: Balanced (default; considers models within about 1% to 2% quality of the best for that prompt and picks the cheapest), Cost (about 5% to 6% quality band, cheapest), Quality (best model, ignores cost). Model subset lets you restrict the pool (new models are not added automatically; Claude models must be deployed separately). Automatic failover to the next appropriate model; subset doubles as fallback set (use at least two). Prompt caching works only if the same model serves consecutive requests with overlapping prefixes; session affinity for stateless Chat Completions attempts the same model across turns but does not guarantee cache hits. Routing decisions use text only, even with image inputs; no audio. Effective context window is that of the smallest underlying model. Version 2025-11-18 is updated in place; 2025-08-07 and 2025-05-19 are frozen. Pool spans OpenAI, Anthropic, xAI, DeepSeek, Meta, Fireworks models.
- **Numbers**: Quality bands as above (1% to 2% Balanced, 5% to 6% Cost, "for example"). Quota GlobalStandard RPM/TPM: Tier 1 1,000 / 1,000,000; Tier 2 2,000 / 2,000,000; Tier 3 4,000 / 4,000,000; Tier 4 7,000 / 7,000,000; Tier 5 10,000 / 10,000,000; Tier 6 15,000 / 15,000,000. DataZoneStandard RPM/TPM: Tier 1 300 / 300,000; Tier 2 670 / 670,000; Tier 3 1,000 / 1,000,000; Tier 4 2,000 / 2,000,000; Tier 5 3,000 / 3,000,000; Tier 6 4,000 / 4,000,000. No savings percentages are stated.
- **Token-cost implication**: Choose Cost mode for high-volume workloads, but benchmark against your fixed-model baseline. Enable session affinity and pin a subset to protect cache hit rates; cap the subset to models with the context window you need.
- **Caveats**: Vendor documentation; no measured savings or benchmark. Doc says evaluation against your baseline is still needed. Auto-update changes the model pool and so cost and quality. Billing is at the listed per-model input rates (see pricing page; not in text).
- **Topic**: routing
