# 268 — Managing context on the Claude Developer Platform
- **Source**: https://anthropic.com/news/context-management (Anthropic, 2025-09)
- **Claim**: Anthropic introduces context editing and a memory tool for agents on the Claude Developer Platform, with Claude Sonnet 4.5, to keep long-running agents inside context limits.
- **Mechanism**: Context editing automatically clears stale tool calls and results when approaching token limits, preserving conversation flow. The memory tool is client-side: Claude creates, reads, updates and deletes files in a memory directory in the developer's infrastructure, persisting across sessions. Sonnet 4.5 has built-in context awareness (tracks available tokens). Available in public beta on the Claude Developer Platform, Amazon Bedrock and Google Vertex AI.
- **Numbers**: On an internal agentic-search eval, memory tool plus context editing improved performance 39% over baseline; context editing alone 29%. In a 100-turn web search evaluation, context editing cut token consumption by 84% and let workflows finish that would otherwise fail from context exhaustion.
- **Token-cost implication**: Clear old tool results rather than carrying them every turn; store durable findings in memory files. This cuts input tokens on long agent loops.
- **Caveats**: Self-reported by Anthropic on an internal eval; baseline and task set not described; 84% applies to the 100-turn web search test only.
- **Topic**: compression
