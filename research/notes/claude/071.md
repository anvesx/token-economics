# 071 — How Claude Code uses prompt caching
- **Source**: https://code.claude.com/docs/en/prompt-caching (Anthropic, 2026-10)
- **Claim**: Claude Code re-sends the full context every turn and relies on exact-prefix prompt caching to bill most of it at the cached token rate. The page lists which actions keep or break the cache and how to check and tune cache performance.
- **Mechanism**: The API matches the start (prefix) of each request against recently processed content; any change inside the prefix recomputes everything after it, with no per-file caching. Requests are ordered as system prompt (core instructions, tool definitions), then project context (CLAUDE.md, auto memory, unscoped rules), then conversation. Each model has its own cache, and fast mode and standard speed keep separate caches; on most models each effort level has its own cache too, but on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 (API key or subscription) effort changes keep the cache. Actions that invalidate it: switching models (including opusplan plan-mode toggles, automatic model fallback, and skills naming another model), changing effort on most models, toggling fast mode, adding or removing MCP tool definitions loaded upfront (not when tool search defers them), denying an entire tool without tool search, compaction (replaces the conversation layer, though the system prompt and project context can stay cached), removing old images and PDFs when limits are hit, and upgrading Claude Code. Actions that keep it: editing repo files (a system-reminder is appended), editing CLAUDE.md mid-session (not applied until /clear, /compact or restart), permission mode changes, output style changes, invoking skills, /recap, /rewind (truncates back to an already-cached prefix), and spawning subagents. Cache TTL is five minutes or one hour (higher cache-write rate); the main conversation gets one hour only on a Claude subscription within plan usage, otherwise five minutes. TTL is set by promptCacheTtl / CLAUDE_CODE_PROMPT_CACHE_TTL for the main conversation and subagentPromptCacheTtl / CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL for everything else (5m or 1h, Claude Code v2.1.242 or later); FORCE_PROMPT_CACHING_5M=1 and ENABLE_PROMPT_CACHING_1H=1 also exist. Cache scope is effectively one machine and directory (the system prompt embeds memory paths and the working directory). Subagents start their own cache (system prompt and tools differ), while forks, /fork copies, compaction calls and resumed subagents can read the parent's prefix; workflow fan-outs hold all but the first same-prefix agent for up to 5 seconds so they can read the first one's cache. Cache health is visible via cache_creation_input_tokens and cache_read_input_tokens, /usage (a Prompt cache (main) line with hit ratio, miss count and likely cause, v2.1.251 or later), a statusline script, and the OpenTelemetry exporter.
- **Numbers**: TTL options are 5 minutes and 1 hour (no prices in this document; cache reads bill "below the standard input rate", one-hour cache writes at a higher rate than five-minute writes). Fan-out hold: up to 5 seconds by default. Version gates: v2.1.238, v2.1.242, v2.1.246, v2.1.248, v2.1.251, v2.1.260, v2.1.265, v2.1.283, v2.1.290.
- **Token-cost implication**: Choose model and effort at the start of a session and avoid switching mid-task; turn fast mode on at session start; keep MCP servers and tool sets stable (use tool search so tools are deferred); run /compact at natural breaks, and use /rewind instead of compacting when abandoning a path. Set promptCacheTtl to 1h for API-key users who idle between turns, and monitor the read-to-creation token ratio. For gateways, confirm they forward cache_control markers and the anthropic-beta header, otherwise the whole conversation bills as uncached on every turn.
- **Caveats**: Vendor documentation describing its own product; no measured savings or dollar rates are given, so the size of the effect has to be measured with the usage fields. Behavior is tied to specific Claude Code versions and models and varies by provider (Bedrock, Foundry, Google Cloud) and gateway.
