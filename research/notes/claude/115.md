# 115 — MeanCache: A Privacy-Aware Semantic Cache for Large Language Models
- **Source**: https://arxiv.org/abs/2403.02694 (Virginia Tech / Cisco / Univ. of Minnesota, Gill et al., 2024-03; v4 Mar 2025, IPDPS 2025)
- **Claim**: A client-side semantic cache for LLM web services that matches new queries to cached ones by embedding similarity, checks conversation context chains, and fine-tunes a small embedding model with federated learning. It reports fewer false hits than the GPTCache baseline.
- **Mechanism**: Per-user local cache stores query, response, embedding, and the context chain (parent query ids). On a new query: embed with a small model (MPNet or Albert, 768 dims), find top-k cached queries by cosine similarity above a threshold tau, then on a candidate hit verify the context chain matches the new query's context. If no match, call the LLM and enroll the result. Embedding model and tau are trained across clients with federated learning (FedAvg on weights; server averages client-optimal thresholds; client treats a user re-asking as a false hit and adjusts tau to maximise F-score). Embeddings are compressed with PCA (768 to 64 dims) via an added projection layer to cut storage and search time. LRU eviction is shown in the workflow.
- **Numbers**: Reported vs GPTCache (Llama-2 baseline) on 1000 queries, 30% repeated (the GPTCache dataset): precision 0.72 (MPNet) vs 0.52; F-score 0.73 (MPNet) and 0.68 (Albert) vs 0.56; false hits 89 vs 233. Headline: about 17% higher F-score, about 20% higher precision. Contextual queries (450 synthetic GPT-4 queries; 100 should-miss): 3 false hits vs 54; over 25% higher F-score and accuracy, 32% higher precision. PCA compression 768 to 64 dims: 83% less storage, 11% faster search, small F-score drop (still above GPTCache). Llama embedding (4096 dims) is about 32.05 KB per query. Survey of real ChatGPT conversations: on average 31% of queries similar to a previous one (academic participants; paper notes this may vary elsewhere). Prior work cited: about 33% of search queries resubmitted. Responses limited to 50 tokens in the test. FL used 20 clients.
- **Token-cost implication**: Repeated or near-duplicate queries (roughly a third in the cited data) are a real saving target, but precision matters more than recall because a false hit returns a wrong answer. Use a small embedding model, tune the similarity threshold on your own data, and include conversation context in the cache key so follow-ups like "change the color to red" do not hit a stale answer. Compress embeddings if the cache is large. A client-side cache also avoids being billed for hits.
- **Caveats**: Authors' own evaluation, against one baseline (GPTCache) on its dataset. Contextual dataset is synthetic, generated with GPT-4. Only 20 FL clients, limited by dataset size. Absolute precision of 0.72 still means many false hits. Savings reported are in classification quality, storage, and search time, not dollars or measured token reduction. The 31% duplicate rate is from a small academic participant group. Figure and table values were partly garbled in extraction; numbers above are from prose.
