# 174 — Batch Processing
- **Source**: https://docs.mistral.ai/inference/batch-processing (Mistral AI, no date)
- **Claim**: Mistral's Batch API runs asynchronous inference on large request sets at a 50% discount.
- **Mechanism**: Build a JSONL file where each line has a unique `custom_id` and a `body` identical to the normal endpoint body (model optional, given at job creation instead). Upload via Studio or `client.files.upload(purpose="batch")`, then `client.batch.jobs.create(input_files=[...], model=..., endpoint=..., metadata=...)`. For under 10,000 requests, pass `requests=[...]` inline instead of a file. One model per batch. Supported endpoints: /v1/embeddings, /v1/chat/completions, /v1/fim/completions, /v1/moderations, /v1/chat/moderations, /v1/ocr, /v1/classifications, /v1/conversations, /v1/audio/transcriptions. Poll job status (QUEUED, RUNNING, SUCCESS, FAILED, TIMEOUT_EXCEEDED, CANCELLATION_REQUESTED, CANCELLED), download output and error files, cancel via API. Job stats include total, succeeded and failed requests.
- **Numbers**: 50% discount for batch workloads. Up to 1M requests per batch file; inline batching under 10k requests. (The Priority Tier doc in the same set states batch requests are processed over a 24-hour period.) The FAQ answers (pricing, rate limits, expiry, spend limits) are collapsed and absent from the text.
- **Token-cost implication**: Move non-interactive work (evals, classification, embeddings, OCR, bulk extraction) to batch for half price; design for async results matched by `custom_id`; keep batches single-model, and run the same file against several models to compare.
- **Caveats**: Vendor documentation; no latency guarantee stated on this page; whether the discount stacks with caching is not stated here.
- **Topic**: pricing
