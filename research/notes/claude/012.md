# 012 — Arch-Router-1.5B
- **Source**: https://huggingface.co/katanemo/Arch-Router-1.5B (Katanemo, 2025-06)
- **Claim**: A 1.5B-parameter model that maps a conversation to a user-defined route name (domain/action), so model selection follows explicit, editable preferences rather than benchmark-learned scores.
- **Mechanism**: You supply a route_config list of {name, description} entries (e.g., code_generation, bug_fixing, api_help) and each route is tied to a preferred model. The prompt wraps routes in <routes></routes> and the conversation in <conversation></conversation>; the model outputs JSON {"route": "<name>"} or {"route": "other"} when intent is irrelevant or already fulfilled. New routes can be added without retraining. Fine-tuned from Qwen2.5-1.5B-Instruct, runs via transformers (>=4.37.0); powers the Arch models-native proxy server.
- **Numbers**: 1.5B parameters (listed as 2B params, F16). Downloads last month: 3,334. Claims SOTA matching of queries to human preferences on conversational datasets, outperforming top proprietary models, with no figures given on the page.
- **Token-cost implication**: Routing policy can live in a small self-hosted classifier plus a config mapping routes to cheaper or stronger models; edit descriptions instead of retraining when models or prices change. The page gives no cost data, so measure router latency and accuracy on your own traffic.
- **Caveats**: Model card only; performance claims refer to an external paper (arXiv 2506.16655) and are not quantified here. Vendor-reported. Accuracy depends on route description quality; no cost savings measured.
- **Topic**: routing
