# 284 — Writing effective tools for AI agents
- **Source**: https://www.anthropic.com/research/writing-tools-for-agents (Anthropic, 2026-11)
- **Claim**: Anthropic describes an evaluation-driven process for building agent tools and principles for them: consolidate tools, namespace them, return high-signal context, and keep tool responses token-efficient.
- **Mechanism**: Prototype tools in a local MCP server, generate realistic multi-tool-call eval tasks with verifiable answers, run each as a simple agent loop via direct API calls, collect accuracy, runtime, number of tool calls, token consumption and errors, then feed transcripts to Claude Code to refactor tools. Token-efficiency levers: consolidate chained operations into one tool (for example search_logs, get_customer_context, schedule_event instead of list/read primitives); a response_format enum (concise vs detailed) so the agent chooses verbosity; replace UUIDs with semantic names or 0-indexed IDs; pagination, range selection, filtering and truncation with sensible defaults, plus steering text in truncation and error messages; clear tool descriptions (they are loaded into context).
- **Numbers**: Concise Slack tool response 72 tokens vs detailed 206 tokens (about one third). Claude Code restricts tool responses to 25,000 tokens by default. Claude Sonnet 3.5 reached state-of-the-art on SWE-bench Verified after tool description refinements (no figure given).
- **Token-cost implication**: Design tools so they return less: filter server-side, default to concise output, cap response size, and consolidate multi-step calls, which cuts both tool-response tokens and loop turns. Track tokens per task and tool calls in your evals.
- **Caveats**: Anthropic self-reported on internal Slack and Asana tool evals (charts not in the text); few absolute numbers; the 3x token saving is from one example.
- **Topic**: agent-cost
