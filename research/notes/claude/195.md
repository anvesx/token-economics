# 195 — Flex processing
- **Source**: https://developers.openai.com/api/docs/guides/flex-processing (OpenAI, no date)
- **Claim**: OpenAI Flex processing lowers the price of Responses and Chat Completions requests in exchange for slower responses and occasional resource unavailability.
- **Mechanism**: Set `service_tier: "flex"` on the request. Intended for non-production or low-priority work: model evaluations, data enrichment, asynchronous workloads. Tokens are priced at Batch API rates, with additional discounts from prompt caching. Beta, limited model availability (listed on the pricing page). Timeouts are more likely: SDK default timeout is 10 minutes (examples raise it to 15 minutes / 900 s); SDKs automatically retry 408 Request Timeout twice. When capacity is lacking the API returns 429 Resource Unavailable and you are not charged. Recovery options: retry with exponential backoff (cheapest, tolerates delay), or retry on standard processing by setting `service_tier` to `auto` or removing the parameter (costs more but ensures completion).
- **Numbers**: Price = Batch API rates (the percentage discount is not stated on this page), plus prompt-caching discounts. Default timeout 10 minutes; example timeout 15 minutes; 2 automatic retries on 408. No charge on 429. Example model in code: gpt-6-astra. The rest of the file is site navigation and SDK code samples.
- **Token-cost implication**: Route latency-tolerant jobs (evals, enrichment, bulk summarization) to Flex for batch-level pricing without batch file plumbing; build retry logic with backoff and a standard-tier fallback, and raise client timeouts so long requests are not billed-then-dropped.
- **Caveats**: Beta; availability limited to some models; no SLA or latency figures; the actual price numbers live on a different page not included here.
