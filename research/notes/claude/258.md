# 258 — GLM 5.2 Fast: Faster Serverless Inference, Same Quality
- **Source**: https://fireworks.ai/blog/glm-5-2-fast-inference (Fireworks, 2026-11; release dated Jun 30, 2026)
- **Claim**: Fireworks launches GLM 5.2 Fast, a serverless path running about 2x its Standard path throughput on the same weights, with a heavy discount on cached input and an argument that cached tokens dominate agent cost.
- **Mechanism**: Fast is selected with a model ID switch (accounts/fireworks/routers/glm-5p2-fast); Priority adds service_tier="priority" for admission precedence under congestion. Serving: expert sharding for MoE (about 98% of parameters are experts) with data-parallel attention for MLA latent KV; DeepSeek Sparse Attention with IndexShare (selects top 2,048 prior tokens per query); speculative decoding; lower-precision serving only where quality evals hold; prefill/decode separation; multi-tier prompt cache (hot KV near GPUs, colder state in cheaper tiers). Same eval suite run on Standard and Fast for tool-call validity, JSON-schema adherence and long-context behavior.
- **Numbers**: Per 1M tokens (input / cached / output): Standard $1.40 / $0.14 / $4.40; Standard + Priority $1.75 / $0.18 / $5.50; Fast $2.10 / $0.21 / $6.60. Cached input discount 90% from fresh input. Peak 446 tok/sec on Artificial Analysis; 2x to 3x faster than Standard (post says both "~2x" and "2-3x"). Average prompt length on public endpoints about 90k tokens; example workload 90k prompt, 600 turns, 500 output tokens, mostly cached. Full 1M-token context window. SWE-bench Verified 81.8% (tested on Fireworks GPUs).
- **Token-cost implication**: In long agent loops most tokens are cached prefix, so choose providers and designs that maximize cache hits (stable prefix) and compare cached-input price; pay the Fast premium (1.5x price for about 2x speed) only when latency matters.
- **Caveats**: Vendor marketing blog, self-reported speed and quality parity; third-party throughput snapshots move day to day. No cost-per-task figure was given.
