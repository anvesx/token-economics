# 267 — Cursor – Usage and limits
- **Source**: https://cursor.com/help/models-and-usage/usage-limits (Cursor, no date given)
- **Claim**: Cursor documents how included usage is pooled and billed: on The X Subscription there is one weekly pool for Cursor models, with third-party models billed at API list price from prepaid credit; legacy plans have two monthly pools (Cursor Models and Other Models).
- **Mechanism**: Cursor models are Grok 4.7, 4.6, 4.5 and Composer 2.5. Cursor Router modes: Cost mode (classic Auto) bills as a Cursor-model request from the included pool whatever model serves it; on Teams and Enterprise, Balance and Intelligence bill at the routed model's list price, so a third-party route is billed as third-party usage. Subagents can run a named third-party model and bill at list price while the picker shows Auto. Own-API-key requests on individual plans bypass the pools. Unused usage does not roll over. Prepaid credit expires 365 days after purchase.
- **Numbers**: Max Mode on legacy request-based plans: model API rate plus 20%. Cursor Token Rate $0.25 per million tokens on Teams and Enterprise (including own-key requests), where applicable; exempt for Composer 2.5, Cost mode, and third-party models whose cache-read price is strictly below $0.10 per million tokens across every tier. Prepaid credit expiry 365 days.
- **Token-cost implication**: Model selection and router mode determine which pool is drained; subagents and own keys can bill separately. Builders using routers should expect a per-token platform fee on pass-through models, and cheap cache-read prices exempt a model from it.
- **Caveats**: Vendor help doc. No per-plan dollar pool sizes in this text.
