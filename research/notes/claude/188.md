# 188 — Monitor model serving costs
- **Source**: https://docs.databricks.com/aws/en/admin/system-tables/model-serving-cost (Databricks, last updated 2026-09-11)
- **Claim**: Databricks Model Serving costs can be tracked and attributed per endpoint and tag through the system.billing.usage system table and a downloadable AI/BI dashboard.
- **Mechanism**: Costs appear in system.billing.usage under sku_name `<tier>_SERVERLESS_REAL_TIME_INFERENCE_<region>` (all serving costs) and `..._LAUNCH_<region>` (DBUs accrued when an endpoint starts after scaling to zero). Batch inference is isolated by billing_origin_product = MODEL_SERVING and offering_type = BATCH_INFERENCE. Custom tags on endpoints propagate to the custom_citations-free `custom_tags` column for grouping by business unit or use case. Example SQL sums usage_quantity (DBUs) by day, endpoint_name or tag. The dashboard charts include top endpoint consumption, daily DBU usage, cost by endpoint type (pay-per-token, CPU/GPU, foundation model), top 10 costly endpoints and LLM fine-tuning spend. Budgets can be used for alerts, and workspace default limits guard against runaway spend.
- **Numbers**: none (no prices or DBU rates; queries use 30-day windows and top-30 limits only).
- **Token-cost implication**: Tag every serving endpoint at creation so spend can be attributed per use case; watch the LAUNCH SKU to see the cost of scale-to-zero cold starts; split batch from real-time spend.
- **Caveats**: Databricks-specific; costs are in DBUs, not tokens or dollars; no per-token metrics shown.
- **Topic**: observability
