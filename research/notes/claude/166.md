# 166 — How NVIDIA Dynamo 1.0 Powers Multi-Node Inference at Production Scale
- **Source**: https://developer.nvidia.com/blog/nvidia-dynamo-1-production-ready/?trk=article-ssr-frontend-pulse_little-text-block (NVIDIA, 2026-03-16)
- **Claim**: Dynamo 1.0 is a production multi-node inference framework adding agent-aware routing and KV caching, multimodal embedding caching, faster replica startup, and SLO-driven zero-config deployment.
- **Mechanism**: Agent hints (latency sensitivity, expected output length, cache control) go through the frontend API to a KV-aware router (queue ordering so user-facing turns precede background work; expected OSL for balancing) and a KV cache manager with experimental pinning (pinned blocks resist eviction for a set duration and move to host memory instead of being deleted). Multimodal: disaggregated encode/prefill/decode, CPU-backed LRU image-embedding cache, multimodal KV routing. ModelExpress: checkpoint restore (run init once, restore new replicas) and weight streaming over NIXL/NVLink. KVBM adds S3/Azure-blob object storage, global KV event emission to the router indexer, pip-installable module. DGDR: specify model, hardware, traffic goals in YAML; AIConfigurator (simulation) or planner (on-cluster profiling) produces a deployment. Fault tolerance: canary health checks, request cancellation and migration.
- **Numbers**: Up to 7x more requests served on Blackwell (SemiAnalysis InferenceX, 2026-03-03; DeepSeek R1-0528, FP4, 1k/1k, ~50 tok/sec/user, disaggregated serving with wide expert parallel on GB200 NVL72). Up to 4x lower TTFT and 1.5x higher throughput with NeMo Agent Toolkit (Llama 3.1, Hopper). Embedding cache: up to 30% TTFT and up to 25% throughput gain on image requests (Qwen3-VL-30B-A3B-Instruct-FP8, GB200). Weight streaming: up to 7x faster model loading for large MoE such as DeepSeek v3 on H200. Failed worker removed from routing for about five seconds. 5-second video in ~40 seconds on one Hopper GPU (Wan2.1, SGLang Diffusion).
- **Token-cost implication**: For self-hosted agent workloads, tag requests with priority/expected length and pin shared prefixes so multi-turn agents do not recompute evicted KV; cache image embeddings for repeated images; stream weights to cut scale-up time; use disaggregated serving to raise requests per GPU.
- **Caveats**: NVIDIA's own announcement; figures are "up to" and tied to specific models, hardware and workloads. The 7x is against a baseline defined in the InferenceX figure, not described in text. Cache pinning is experimental.
