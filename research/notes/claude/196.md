# 196 — Latency optimization
- **Source**: https://developers.openai.com/api/docs/guides/latency-optimization (OpenAI, no date)
- **Claim**: LLM latency is mostly set by output token count and request count, not input size; OpenAI lists seven principles and a worked customer-service-bot example that also cut tokens and calls.
- **Mechanism**: Seven principles: process tokens faster (smaller models, with longer prompts, few-shot examples or fine-tuning/distillation; Predicted Outputs when most output is known, e.g. code edits); generate fewer tokens (be concise, shorten structured-output field names, max_tokens or stop tokens); use fewer input tokens (fine-tune to drop long instructions, filter/prune RAG context, put dynamic content late to maximize the shared prefix for KV/prompt caching); make fewer requests (combine sequential steps into one prompt with JSON fields); parallelize (including speculative execution, e.g. run moderation and generation together and cancel if the guess fails); make users wait less (streaming, chunking, showing steps); do not default to an LLM (hard-code, pre-compute, use UI, classical algorithms). Example: merged query-contextualization and retrieval-check into one call, moved it to fine-tuned GPT-3.5, split the assistant prompt so a fine-tuned GPT-3.5 produces reasoning fields in parallel with retrieval while GPT-4 writes only the final response, and shortened JSON field names.
- **Numbers**: Cutting 50% of output tokens may cut about 50% of latency; cutting 50% of the prompt may only give a 1-5% latency improvement. Renaming JSON fields in the example removed 19 output tokens, worth a few milliseconds on GPT-3.5 and up to about a second on GPT-4.
- **Token-cost implication**: Output tokens dominate both latency and (typically) price, so terse structured output, early stop, and smaller fine-tuned models for well-defined subtasks reduce cost as well as latency. Placing static content first keeps the cacheable prefix long. Merging calls avoids repeating shared input tokens per request.
- **Caveats**: Guide is about latency; cost effects are inferred, not quantified (the 50% and 1-5% figures are described as heuristics). Example uses older models (GPT-4, GPT-3.5) and is hypothetical; the tradeoff between fewer requests and faster tokens must be tested per case.
