# 157 — Prompt caching for faster model inference
- **Source**: https://docs.aws.amazon.com/us_en/bedrock/latest/userguide/prompt-caching.html (Amazon Web Services, no date)
- **Claim**: Amazon Bedrock supports implicit (best-effort prefix reuse) and explicit (checkpoint/breakpoint) prompt caching across Claude, OpenAI GPT and Nova models, with per-model minimums, TTLs and billing rules.
- **Mechanism**: Prompt order is tools, then system, then messages; changing an earlier section invalidates later ones. Explicit caching uses `cachePoint` (Converse) or `cache_control` (InvokeModel/Messages); a checkpoint only caches if the cumulative prefix meets the model minimum, otherwise the call succeeds uncached. Claude: up to 4 checkpoints, lookback checks only about 20 content blocks before a checkpoint, optional top-level `cache_control` "automatic caching" moves the checkpoint forward as the conversation grows (uses one slot), `ttl: "1h"` option (longer TTL entries must precede shorter ones; omitting ttl gives 5 minutes; sending ttl to 5-minute-only models can raise ValidationException). OpenAI GPT-5.6 and later: `prompt_cache_breakpoint: {"mode":"explicit"}` on content blocks, `prompt_cache_options.mode` implicit (default, auto breakpoint on latest message) or explicit (no auto breakpoint; no breakpoints means no caching or write charges), `prompt_cache_key`, ttl `30m` only. GPT-5.5 and earlier: automatic caching of prefixes of 1,024+ tokens. Nova: implicit caching on text prompts, not reported or billed as cache reads. Response fields: Converse `cacheReadInputTokens`, `cacheWriteInputTokens`, `cacheDetails`; total input = inputTokens + cacheRead + cacheWrite. OpenAI: `cached_tokens`, `cache_write_tokens`.
- **Numbers**: Min tokens per checkpoint: 512 (Claude Haiku/Sonnet/Opus/Fable/Mythos 5 and 5.5 series, 5.1), 1,024 (Opus 4.8, Sonnet 5, Sonnet 4.6, GPT-5.6/6 models, Nova ~1K), 4,096 (Opus 4.7, 4.6, 4.5, Haiku 4.5). Max 4 checkpoints (Claude, Nova) or 4 cache writes (GPT). Nova max 20K cacheable tokens. Claude TTL 5 minutes or 1 hour; GPT-5.6+ 30 minutes; Nova 5 minutes. GPT-5.6+ cache writes billed at 1.25x uncached input rate; GPT-5.5 and earlier have no write fee. Cached reads do not count against input-tokens-per-minute quota (OpenAI models; also stated for the Claude 1-hour cache use case). Example response: input_tokens 2,048, cached_tokens 1,920, cache_write_tokens 0.
- **Token-cost implication**: Put static content (tools, system, reference docs) first and variable content last; place checkpoints after stable content; use the 5-minute cache for prompts reused more often than every 5 minutes (refreshes free) and 1-hour for gaps over 5 minutes (e.g. side-agents); use explicit mode for agent loops on GPT-5.6+; monitor cache-write vs cache-read tokens; do not assume a hit, check usage fields. Caching is not available for batch inference.
- **Caveats**: AWS documentation; no measured savings or discount percentages for reads (refers to the pricing page). Model names reflect the doc as written. Hits depend on the same server handling the request; cross-region inference can cause more writes; concurrent identical requests write rather than read.
- **Topic**: caching
