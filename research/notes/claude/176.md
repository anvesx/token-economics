# 176 — Priority Tier
- **Source**: https://docs.mistral.ai/inference/priority-tier (Mistral AI, no date)
- **Claim**: Mistral's Priority Tier gives eligible requests priority queueing at a 1.75x premium over Standard Tier pricing, with automatic fallback to Standard when limits are exceeded.
- **Mechanism**: Requires an enterprise account setup with custom per-model Priority limits (requests/min, tokens/min). Set `service_tier` on the request: `auto` uses Priority if eligible and falls back to Standard; `standard_only` (default if omitted) never consumes Priority limits. The response `usage.service_tier` returns `priority` or `standard`, which lets you detect fallback or downgrades. Eligibility needs entitlement, a configured model, being within limits, and available regional capacity.
- **Numbers**: Billing multiplier 1.75x standard list price (75% premium) on input, output and cached tokens. Prompt caching discount of up to 90% on cached input tokens still applies, with the 1.75x applied after the cache discount. 99.5% uptime SLA for Priority (none for Batch or Standard). Latency: Batch queued over 24 hours, Standard "seconds to minutes", Priority "seconds".
- **Token-cost implication**: Tag only latency-critical traffic as `auto`; keep everything else `standard_only` or batch. Log `usage.service_tier` to measure fallback rate and effective premium paid. Maximize cache hits since the premium applies to the discounted cached price.
- **Caveats**: Vendor doc; requires sales engagement, capacity increases may need advance notice; no latency numbers beyond qualitative.
- **Topic**: pricing
