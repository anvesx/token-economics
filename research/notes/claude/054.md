# 054 — An update on Claude Code quality reports
- **Source**: https://www.anthropic.com/research/april-23-postmortem (Anthropic, 2026-04)
- **Claim**: Three separate Claude Code changes (lower default reasoning effort, a thinking-clearing bug on idle sessions, and a verbosity system-prompt line) caused perceived quality degradation; the API was unaffected and all were resolved by April 20 (v2.1.116).
- **Mechanism**: (1) Mar 4: default effort changed high to medium to cut latency; reverted Apr 7 (Opus 4.7 default xhigh, others high). Effort is a product-layer default sent to the Messages API as the effort parameter, adjustable with /effort. (2) Mar 26: to cut cost of resuming sessions idle >1 hour (prompt cache already evicted), old thinking was cleared using the clear_thinking_20251015 header with keep:1; a bug re-applied it every turn for the rest of the session, dropping reasoning history, causing forgetfulness and repeated cache misses that likely drained usage limits faster. Fixed Apr 10 (v2.1.101). (3) Apr 16: system prompt line "keep text between tool calls to <=25 words, final responses <=100 words" hurt coding quality; reverted Apr 20.
- **Numbers**: Default effort high to medium on Mar 4 (Sonnet 4.6, Opus 4.6), reverted Apr 7. Idle threshold 1 hour; keep:1 thinking block. Ablation showed a 3% drop on one evaluation for both Opus 4.6 and 4.7 from the verbosity prompt. Usage limits reset for all subscribers on Apr 23. Medium effort gave "slightly lower intelligence with significantly less latency" (no figures).
- **Token-cost implication**: Pruning reasoning or history to save tokens can invalidate prompt-cache prefixes and cost more than it saves; make context-trimming changes once and idempotently. Cutting output length by prompt instruction trades against quality, so evaluate per model. Lower reasoning effort is a real lever but users preferred high default and opt-down for simple tasks.
- **Caveats**: Self-reported postmortem by the vendor; the cache-miss to usage-limit link is stated as "we believe". Not a controlled cost measurement; concerns Claude Code, Agent SDK and Cowork, not the API.
