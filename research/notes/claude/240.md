# 240 — Simple and semantic cache (Portkey)
- **Source**: https://portkey.ai/docs/product/ai-gateway/cache-simple-and-semantic (Portkey, 2026-10)
- **Claim**: Portkey's gateway offers response-level caching: simple (exact match, all plans) and semantic (similarity match, select Enterprise plans), advertised as serving requests "up to 20x faster and cheaper".
- **Mechanism**: Config {"cache": {"mode": "simple"|"semantic", "max_age": seconds}}. Simple hit requires an identical full request body (messages, model, temperature, max_tokens, all parameters), same x-portkey-metadata and x-portkey-cache-namespace, and unexpired entry. Semantic is a superset: exact match first, then cosine similarity above threshold (default 0.95) on user text, with all other body parameters matching exactly; the system prompt is ignored; works only for requests under 8,191 tokens and at most 4 messages; needs at least one user message; supported on /chat/completions and /completions; response model must be OpenAI-compatible. Self-hosted setup needs an embedding provider (openai, azure-openai, google, vertex-ai; example text-embedding-3-small, 1536 dimensions) and a vector store (Milvus or Pinecone, cosine). Per-request force refresh (x-portkey-cache-force-refresh) and namespace (x-portkey-cache-namespace, for per-user partitioning). Target-level cache config overrides top-level. Analytics shows hit rate, latency savings and cost savings; logs mark Cache Hit, Cache Semantic Hit, Cache Miss, Cache Refreshed, Cache Disabled. Caching does not work if x-portkey-debug: "false" is sent.
- **Numbers**: TTL minimum 60 seconds, maximum 90 days (7,776,000 s), default 7 days (604,800 s); a max_age below 60 falls back to the 7-day default rather than 60. Org-level max TTL 25,923,000 s. Semantic similarity threshold default 0.95. Semantic limits: under 8,191 tokens, up to 4 messages. "Up to 20x faster and cheaper" is the vendor's claim.
- **Token-cost implication**: Gateway response caches avoid the model call entirely for repeated or near-identical user questions; partition with namespaces for per-user data, and note the system prompt is ignored in semantic matching, so do not rely on it to separate behaviors.
- **Caveats**: Vendor docs, no measured hit rates. Semantic cache can return a wrong answer when wording differs in a meaningful way (threshold-dependent); only simple caching is on all plans.
