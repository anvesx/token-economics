# 109 — Orca: A Distributed Serving System for Transformer-Based Generative Models
- **Source**: https://www.usenix.org/conference/osdi22/presentation/yu (USENIX OSDI '22 page; listed as arXiv paper, 2022-07)
- **Claim**: Existing serving systems batch at request granularity, so finished requests wait for the whole batch and new requests wait for the batch to end. Orca schedules per iteration and batches only selected operations, giving large throughput gains on GPT-3 175B.
- **Mechanism**: (1) Iteration-level scheduling: the scheduler invokes the execution engine for a single model iteration (one token per request) on the current batch, so finished requests return immediately and new requests join at the next iteration. (2) Selective batching: batching is applied only to a selected set of operations so that iteration-level scheduling and batching work together on Transformer models. (3) A distributed implementation designed to scale to models with hundreds of billions of parameters. Only the abstract/landing page is in the file; internals beyond this are not given.
- **Numbers**: 36.9x throughput improvement over NVIDIA FasterTransformer at the same level of latency, on a GPT-3 175B model (abstract writes "36:9x").
- **Token-cost implication**: Serve generative models with continuous (iteration-level) batching rather than static request-level batching; it raises tokens per GPU-hour and so lowers cost per token for self-hosted inference.
- **Caveats**: Authors' own evaluation; file has only the abstract and citation, no methodology or workload details. Compared against FasterTransformer only. Authors are affiliated with FriendliAI.
- **Topic**: serving
