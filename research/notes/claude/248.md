# 248 — Provider Options (Vercel AI Gateway)
- **Source**: https://examples.vercel.com/docs/ai-gateway/provider-options (Vercel, 2026-02; page last updated October 2, 2026)
- **Claim**: Vercel AI Gateway routes requests across model providers with ordering, filtering, sorting, fallbacks, session affinity and automatic caching controlled via providerOptions.gateway.
- **Mechanism**: Default routing orders providers by default priority adjusted for recent uptime and latency and fails over. providerOptions.gateway.order prefers providers but permits fallback; only is a hard filter with no failover; sort ranks providers by cost, latency (ttft) or throughput (tps). caching: 'auto' applies the right cache strategy per provider (for Anthropic and MiniMax, which need explicit cache markers). On the Responses API, top-level cache_anchor_items pins a cache marker at a stable prefix position and cache_ttl selects five-minute or one-hour cache lifetime. sessionId (or x-session-id header) with sessionAffinity (default true) keeps a conversation on the provider holding its prompt cache. Also per-provider timeouts for fast failover, model fallbacks, decision fallbacks, request-scoped BYOK, and reasoning options (for example OpenAI reasoningEffort 'low', 'medium', 'high', 'xhigh', 'max'; Anthropic thinking type 'adaptive').
- **Numbers**: none (cache TTL options five minutes or one hour only).
- **Token-cost implication**: Set a stable sessionId per conversation or agent run so cache hits are not lost to provider switching, use caching: 'auto' for providers needing explicit markers, and use sort: 'cost' where quality is equal.
- **Caveats**: Vendor docs, no measured savings. Provider rates not given on this page.
- **Topic**: routing
