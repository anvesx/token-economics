# 056 — Claude Code Cost Optimization: A Benchmark-Backed Playbook for Cutting Token Spend
- **Source**: https://blog.traversaal.ai/claude-code-cost-optimization-benchmark-playbook (Traversaal.ai, 2026-04)
- **Claim**: Combining prompt caching, per-task model routing, CLAUDE.md/.claudeignore trimming, hard output caps and per-task cost attribution cuts Claude Code/API spend 50-80% (headline) or 50-70% in two weeks (body).
- **Mechanism**: (1) Keep a versioned, immutable, consistently ordered system block (~8k tokens) and pass only the task delta as the user turn; anchor file refs by git blob SHA; check `cache_read_input_tokens` per response, treat under 80% hit rate as a prefix-instability signal; auto-compaction can break cached prefixes. (2) Router keyed by task taxonomy: Haiku for deterministic tasks (lint fix, stubs), Sonnet for multi-file refactor, Opus only on an allowlist for architecture RFCs; auto-escalate low-confidence Haiku output. (3) Trim CLAUDE.md under 800 tokens; exclude node_modules, build, dist, vendor, generated, lockfiles etc. via .claudeignore. (4) Per-task max_tokens and USD SLO in CI; tag every call with repo, task_type, pipeline_stage; export to Helicone/LangFuse/Datadog.
- **Numbers**: Cache hits about 10% of standard input cost (up to 90% input savings). Haiku about 1/12th Sonnet cost (also stated 10-20x cheaper). Multi-file refactor pass rate Sonnet 91% vs Haiku 63% at about 4x cost. CLAUDE.md 3,200 to 600 tokens = about 80% lower per-call floor. Excluding vendor/generated files cuts retrieval about 60%. Example caps: lint_fix 512 max_tokens/$0.05 SLO; refactor 3000/$0.40; RFC 5000/$1.00. Merge-check linter stage about $2,400/month to about $190/month (labelled illustrative). Anecdote of a CI task 200 runs/day at Sonnet prices = about $2,000/month; an "$18k bill" is mentioned but not detailed in text.
- **Token-cost implication**: Stabilize the prompt prefix, route by task type with escalation, set per-task output caps, and tag spend per pipeline stage before optimizing.
- **Caveats**: Vendor/consultancy blog (self-promoting); benchmark pass rates and savings not accompanied by method or dataset; examples explicitly illustrative; headline range (50-80%) differs from body (50-70%); contains `.claudeignore` guidance not verified here.
