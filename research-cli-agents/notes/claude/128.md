# 128 — How to Measure AI Agent Token Usage
- **Source**: https://tokenade.net/en/articles/measure-agent-token-usage (Tokenade, 2026-06-29, updated 2026-10-16)
- **Claim**: Measure agent token cost from the API usage object, attribute it to four drivers (file reads, tool output, MCP tools, transcript replay), and convert to dollars by token class. Input dominates agent cost because the full transcript is re-sent every turn.
- **Mechanism**: Read per-call usage (Anthropic: input_tokens, output_tokens, cache_creation_input_tokens, cache_read_input_tokens; OpenAI: prompt_tokens, completion_tokens, total_tokens). Log with session/step labels, group by turn type. Formula: cost = input x in_price + cache_read x in_price x 0.10 + output x out_price (per MTok). Spot MCP manifest cost on turns where the agent only thinks; plot per-turn input to see replay. Escalate from daily dashboard, to per-session, to per-category logging.
- **Numbers**: Prices per MTok input/output: Opus 5 $5/$25; Opus 4.8 $5/$25; Sonnet 5 $2/$10; Haiku 4.5 $1/$5; GPT-5.5 $5/$30. Cache reads ~10% of input rate; sessions with same input tokens can differ 9x in cost by cache-hit rate. Output sometimes 5x price per token. 500-line file ~5,000-7,000 tokens; failed npm test can dump ~15,000 tokens versus ~50 needed. Worked example (Sonnet 5, 18 turns): 2.4M input (1.6M cached), 40K output = $1.60 + $0.32 + $0.40 = $2.32.
- **Token-cost implication**: Install per-call usage logging before optimising; filter tool output, read less via search, trim MCP, watch cache-hit rate, and never judge by output tokens alone.
- **Caveats**: Vendor blog for Tokenade (author sells the tool); the worked example is hypothetical; "for most agents I've profiled" is unquantified; cache write premium omitted from the formula.
- **Topic**: observability
