# 021 — Tool Attention: Dynamic Tool Gating and Lazy Schema Loading to Eliminate the MCP/Tools Tax
- **Source**: https://arxiv.org/abs/2604.21816 (arXiv 2604.21816v1, Sadani and Kumar, Infrrd.ai, April 2026)
- **Claim**: MCP re-sends every tool schema each turn (the "Tools Tax"); a middleware that gates tools by embedding similarity and lazily loads full schemas only for the top-k cuts per-turn tool tokens 95.0% (47.3k to 2.4k) in a simulation.
- **Mechanism**: Tool Attention has three parts. (1) Intent-Schema Overlap (ISO): cosine similarity between the query embedding and a short tool summary embedding (all-MiniLM-L6-v2, 384-d). (2) State-aware gating: threshold theta plus preconditions (auth, prior tool output, milestone), top-k by score. (3) Two-phase lazy loading: Phase 1 keeps all summaries (about 40 tokens each, N=120 is about 4.8k tokens) always resident and cacheable; Phase 2 promotes full JSON schemas only for the active top-k, placed right before the user message. A hallucination gate rejects calls to tools not promoted this turn. Theta calibrated on 100-200 labelled queries (typically 0.22-0.32); recommended k=8-12. Built as LangGraph before_model/after_model middleware.
- **Numbers**: Practitioner-reported tax 10k-60k tokens/turn (15k-55k typical for 4-6 servers, over 150k with sprawl); 4-server host 15k-20k; GitHub full (93 tools) about 55,000 tokens (27.5% of 200k); enterprise DB (106 tools) about 54,600. Formula Ttax = K * sum(tau_i), alpha 200-500 tokens/tool; N=120, K=30, alpha=395 gives about 1.42M tokens. Cited: CLI $3.20 vs MCP $55.20 for 10,000 operations; schema tokens 40-60% of agent API spend; Anthropic code-execution pattern up to 98.7% token reduction. Testbed: 120 tools, six servers, about 394 tokens/schema, 500 synthetic tasks, 3 seeds. Table 3 tokens/turn: Full-Schema 47,312; Static Pruning 11,865; Simple Retrieval 4,082; CLI Lazy 480; Tool Attention 2,368. Context utilization rho at turn 30: 0.24 to 0.91 (3.8x). Projected (dagger) values: success 72% to 94%, P50 4.2s to 2.0s (about 52%), $/task 0.21 to 0.03 (about 86%). Cache hit rate 84% over 30 turns vs 22% for naive injection. Hallucination gate fired on 2.3% of turns; 78% recovered next turn, 22% asked for clarification. Ablation: removing lazy loading -10.3 pp, preconditions -3.6, gate -3.2, TF-IDF -8.1, theta 0.40 -6.0. Full-Schema ISO crosses the 70% fracture point at N of about 50. 29 failed tasks (5.8%). Poisoned descriptions excluded 46/50 (projected TPA success 38% to 6%).
- **Token-cost implication**: Fixed per-turn tool-definition tokens are a recurring input cost multiplied by turns; cutting them via lazy schema loading and keeping the stable summary prefix cacheable reduces both uncached input tokens and context pressure. Static pruning without a recovery path can hurt success.
- **Caveats**: Only token counts and context utilization are measured (tiktoken, synthetic 120-tool testbed). Success, latency, cost and quality are explicit projections from published telemetry, not live-agent runs. Authors state this; tax figures come from practitioner blogs. The 84% vs 22% cache hit rate is described as empirical but within the simulation harness. Depends on tool summary quality; adversarial paraphrase can still get a poisoned tool gated in.
