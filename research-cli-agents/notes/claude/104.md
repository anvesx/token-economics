# 104 — Codex configuration reference
- **Source**: https://developers.openai.com/codex/config-file/config-reference.md (OpenAI, no date)
- **Claim**: The Codex config-file reference lists many settings that directly bound or shape token consumption: tool-output limits, skills catalog budget, MCP schema compaction, project-doc size, reasoning effort, verbosity, compaction and rollout/goal token budgets.
- **Mechanism**: Per-key settings in the config file. `tool_output_token_limit` is the token budget for storing individual tool/function outputs in history. `mcp_servers.<id>.tools.<tool>.output_token_limit` sets a per-MCP-tool output budget before a 20% serialization allowance. `mcp_servers.<id>.tool_input_schema_max_bytes` compacts an MCP tool's input schema above a byte threshold. `skills.max_context_tokens` caps the available-skills catalog. `project_doc_max_bytes` caps bytes read from AGENTS.md. `compact_prompt` and `experimental_compact_prompt_file` override the history compaction prompt. `model_providers.<id>.capabilities.remote_compaction` selects `unsupported` (local compaction) or `v2` (compaction triggers through Responses). `features.rollout_budget.*` (under development, off by default) tracks a weighted token budget with reminders as remaining tokens cross thresholds, using separate sampling and prefill token weights. `goals.max_goal_token_budget` sets the default and maximum token budget for goals. `model_reasoning_effort` (low, medium, high, xhigh, max, ultra; availability depends on model and client), `plan_mode_reasoning_effort`, `agents.default_subagent_reasoning_effort`, `model_reasoning_summary`, `model_verbosity` (GPT-5 Responses API). Hooks can save oversized `additionalContext` to disk and show a preview. `service_tier` and `memories.consolidation_service_tier` exist. Memory generation waits for a minimum remaining percentage in rate-limit windows.
- **Numbers**: `skills.max_context_tokens` default is 2% of the model's context window, explicit values capped at 10000 tokens. `tool_input_schema_max_bytes` default 5,000 bytes. Hook `additionalContext` token threshold default 2500 (0 passes full context). `features.rollout_budget.sampling_token_weight` and `prefill_token_weight` default 1.0. Memory generation minimum remaining rate-limit percentage default 25 (clamped 0-100). `agents.enabled` default true. `background_terminal_max_timeout` default 300000 ms. Web search default mode "cached".
- **Token-cost implication**: These keys are the levers for capping context growth in Codex: truncate tool outputs, shrink MCP schemas and skill catalogs, trim AGENTS.md, and lower reasoning effort or verbosity. Rollout and goal budgets give explicit token ceilings with reminders. Subagent concurrency and default subagent effort control fan-out cost.
- **Caveats**: Reference only; no defaults given for `tool_output_token_limit`, `project_doc_max_bytes` or `agents.max_concurrent_threads_per_session` (Codex chooses when unset). Rollout budget is marked under development. No measured savings. Read via keyword grep of key names plus targeted ranges, not every table row.
