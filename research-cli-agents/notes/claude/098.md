# 098 — Codex best practices
- **Source**: https://developers.openai.com/codex/learn/best-practices (OpenAI, date not given)
- **Claim**: A workflow guide for Codex (CLI, IDE, desktop app): scoped prompts, planning, AGENTS.md, config, tests/review, MCP, skills, scheduled tasks and chat hygiene produce better results; it is mostly quality guidance with only indirect cost content.
- **Mechanism**: Prompt = Goal/Context/Constraints/Done-when. Plan mode (/plan, Shift+Tab) before complex work. AGENTS.md (global ~/.codex, repo, subdirectory; closer file wins) holds durable rules and is kept short, with task-specific markdown referenced. config.toml at ~/.codex and .codex for model, reasoning effort, sandbox, approvals, MCP. Reasoning effort guidance: Low for well-scoped fast tasks, Medium/High for complex changes or debugging, Extra High for long agentic reasoning tasks; start with High for GPT-6 Luna or Light for GPT-6 Astra. Add MCP tools only for real workflows (one or two first). Skills (SKILL.md) scoped to one job; scheduled tasks run stable workflows in worktrees. Chats: one per coherent unit of work, /compact when long (auto-compaction also happens), /fork only when work branches, /status to inspect, subagents to offload bounded work (exploration, tests, triage) from the main thread.
- **Numbers**: none (OpenAI states Codex reviews 100% of its PRs; no cost figures).
- **Token-cost implication**: Keep AGENTS.md short and move one-off rules out of prompts, add few MCP tools, use lower reasoning effort for scoped tasks, use one chat per outcome to avoid bloated context, and offload exploration to subagents. These are cost-relevant only implicitly.
- **Caveats**: Vendor guidance, no measurements; does not quantify any token or dollar savings; page content is navigation-heavy and cost is not its stated aim.
- **Topic**: reasoning-budget
