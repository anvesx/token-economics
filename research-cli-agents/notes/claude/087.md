# 087 — Checkpointing
- **Source**: https://code.claude.com/docs/en/checkpointing (Anthropic, date not given)
- **Claim**: Claude Code snapshots file state before each prompt so edits can be rewound with /rewind. The same menu offers "Summarize from here" and "Summarize up to here" to compress part of the conversation and free context window space.
- **Mechanism**: A checkpoint is created per prompt that starts a turn; snapshots are kept for the 100 most recent checkpoints and saved with the conversation. /rewind (or Esc twice on empty input) offers restore code and conversation, restore conversation, restore code, summarize from here, summarize up to here, never mind. Summarize works like a targeted /compact: it compresses messages from (or before) the chosen point into a summary, leaves files untouched, and the original messages stay in the transcript. Optional instructions can steer the summary. /branch or claude --continue --fork-session branches instead of compressing. Rewinding the code does not track Bash-only file changes, most subagent edits, external edits, or symlinked/hard-linked files.
- **Numbers**: 100 most recent checkpoints retained per session; snapshots deleted in the retention sweep about 30 days after the session last saved one (cleanupPeriodDays changes this). No token figures.
- **Token-cost implication**: Use partial summarization ("Summarize from here") on a verbose debugging stretch while keeping the initial instructions intact, instead of a full /compact or restarting. Rewinding to before a failed approach removes its tokens from context, which is cheaper than correcting in-thread.
- **Caveats**: Vendor docs; no measurement of tokens saved or summary quality. Checkpoints are not a substitute for git.
