# 055 — How Claude Code uses prompt caching
- **Source**: https://docs.claude.com/en/docs/claude-code/prompt-caching (Anthropic docs, 2026-10)
- **Claim**: Without caching the API would reprocess the full history every turn. With caching it bills the re-read at the cached token rate and fully processes only what changed. Some actions invalidate the cache and make the next turn slower and more expensive.
- **Mechanism**: Exact-prefix matching; any change in the prefix recomputes everything after it. Request order: system prompt (core instructions, tool definitions), project context (CLAUDE.md, auto memory, unscoped rules), then conversation. Each model has its own cache; fast mode and standard speed have separate caches; on most models each effort level has its own cache (kept intact by default on Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.1 with API key or subscription). Invalidators: model switch (incl. opusplan plan-mode toggles, automatic model fallback, skills naming another model), effort change, fast mode toggle, adding/removing MCP tool definitions or denying a whole tool when tool search is off, compaction, many images (oldest images removed in batches), Claude Code upgrade. Cache-safe: file edits, mid-session CLAUDE.md edits (also not applied until /clear, /compact or restart), permission mode, output style, skills/commands, /recap, /rewind, spawning a subagent. Compaction sends a separate request that reuses the cached prefix while warm, so it is cheap when warm and costs most when resuming an old session after TTL expiry. Subagents have their own system prompt and so do not read the parent's cache; forks inherit the parent's prefix and do. Cache is effectively per machine and directory. Gateways that strip cache_control markers cause full history to bill as uncached on every turn.
- **Numbers**: Two TTLs: 5 minutes, and 1 hour at a higher cache-write rate. Defaults: main conversation gets 1 hour only on a Claude subscription within plan usage; 5 minutes on usage credits, API key or cloud provider; subagents, workflows, compaction and titles get 5 minutes. Fan-out of same-prefix agents: all but the first held up to 5 seconds so they read the first agent's cache. Controls: promptCacheTtl / CLAUDE_CODE_PROMPT_CACHE_TTL, subagentPromptCacheTtl / CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL (v2.1.242+), FORCE_PROMPT_CACHING_5M=1, ENABLE_PROMPT_CACHING_1H=1. Metrics: cache_creation_input_tokens (cache write rate), cache_read_input_tokens (below standard input rate); /usage shows "Prompt cache (main)" hit ratio (v2.1.251+). No dollar rates given.
- **Token-cost implication**: Set model and effort at session start, avoid mid-task model/fast/MCP changes, and run /compact at natural breaks while the cache is warm. Prefer /rewind over compaction to abandon a path (hits an already-cached prefix). Subagents pay their own cold cache, so many short-lived subagents repay prefix writes at 5-minute TTL. On API-key or cloud billing set promptCacheTtl to 1h if you idle between turns; on short bursts the higher write rate is wasted. Watch read-to-creation ratio to spot prefix churn.
- **Caveats**: Doc gives no price ratios (points to API pricing page). Behaviour depends on version, provider and gateway. Page tail is site config only.
