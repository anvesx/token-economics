# 078 — Claude Code Docs: Common workflows
- **Source**: https://code.claude.com/docs/en/common-workflows (Anthropic docs; no date given)
- **Claim**: A recipe page for everyday Claude Code tasks. Its cost-relevant parts are a handful of context-hygiene mechanisms: delegating exploration to subagents, plan mode, resuming sessions, @ file references, and non-interactive piping.
- **Mechanism**: (1) Subagents: "Exploring a large codebase fills your context with file reads"; a subagent reads files in its own context window and returns only a summary. (2) Plan mode (`--permission-mode plan` or Shift+Tab): Claude reads and proposes with no edits until approved. (3) `claude --continue` / `--resume` / `/resume` restore saved local sessions instead of re-explaining context. (4) `@file` includes the file content when it fits the Read tool token limit; directory references list files only; `@` adds CLAUDE.md from the file's directory and parents; MCP resources via `@server:resource`. (5) `claude --worktree <name>` for isolated parallel sessions. (6) `claude -p` pipes stdin/stdout for CI and batch. (7) Scheduling options: cloud scheduled tasks, desktop scheduled tasks, GitHub Actions, `/loop`. (8) Setting CLAUDE_CODE_DISABLE_FILE_MENTIONS=1 (v2.1.299+) stops @ references inlining contents.
- **Numbers**: @ file inclusion limit: Read tool token limit 25,000 tokens by default; a text file larger than 256KB is not included. CLAUDE_CODE_DISABLE_FILE_MENTIONS requires v2.1.299 or later. No dollar or percentage figures. The remainder of the file is page-rendering JS and config duplicating the same text.
- **Token-cost implication**: Offloading wide exploration to a subagent keeps the main context (re-sent each turn, billed as input) small; plan mode avoids expensive edit-and-revert cycles; resume avoids re-priming context. @ references inline up to 25k tokens at once, so referencing big files can inflate context.
- **Caveats**: Documentation, qualitative; no measured savings. Cost effects above are inferences from the described behavior, not claims on the page. The page defers to a separate Best practices page for context guidance.
