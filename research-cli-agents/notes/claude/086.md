# 086 — Speed up responses with fast mode (Claude Code Docs)
- **Source**: https://code.claude.com/docs/en/fast-mode (Anthropic official documentation, undated)
- **Claim**: Fast mode is a high-speed API configuration of Claude Opus, up to 2.5x faster at a higher per-token price, with identical quality. It is not a different model and is not available on Sonnet, Haiku or other models.
- **Mechanism**: Toggle with /fast (or "fastMode": true in settings; -p mode via --settings). Supported on Opus 5.5 (default from v2.1.280), Opus 5 and Opus 4.8. Fast and standard speed keep separate prompt caches. On a rate limit, fast mode falls back to standard speed and pricing with a cooldown, then re-enables. If usage credits run out, each rejected request is retried at standard speed with no cooldown. Subscription plans (Pro, Max, Ultra, Team, Enterprise) pay for fast mode from usage credits only, not from included rate limits. Team and Enterprise need an Owner to enable it. Not available on Bedrock, Google Cloud, Foundry or Claude Platform on AWS. Setting fastModePerSessionOptIn: true makes every session start with fast mode off. CLAUDE_CODE_DISABLE_FAST_MODE=1 disables it entirely.
- **Numbers**: Fast mode price per MTok input/output: Opus 5.5 $8/$40; Opus 5 and Opus 4.8 $10/$50. Pricing is flat across the full 1M-token context window. Speed up to 2.5x. Opus 4.8 fast mode deprecated 2026-10-30 and rejected by the API after 2026-11-30. Opus 4.7 fast mode deprecated 2026-06-25, removed 2026-07-24. Fast mode in cloud sessions needs v2.1.271 or later; -p form needs v2.1.205 or later. Standard Opus rates for comparison are not on this page.
- **Token-cost implication**: Turning fast mode on mid-conversation charges the full fast uncached input price for the entire context, and each later switch rereads part or all of the context uncached. So enable it at session start or not at all, and avoid toggling. Use it for interactive latency-sensitive work; keep long autonomous tasks, batch and CI on standard speed. Fast mode can combine with a lower effort level for maximum speed on easy tasks. On multi-session teams, fastModePerSessionOptIn limits runaway spend. Spend is not broken out for subscription users; Console users can group by Speed.
- **Caveats**: Vendor docs, no benchmarks; "up to 2.5x" is a ceiling, not a measured average. Opus 5 and 4.8 fast mode are a research preview, so price and availability may change. Fast-mode pricing for Opus 5.5 also depends on organization usage tier. The tail of the file is site navigation JSON with no content.
