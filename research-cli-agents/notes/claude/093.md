# 093 — Choosing a Claude model and effort level in Claude Code
- **Source**: https://www.claude.com/blog/claude-model-and-effort-level-in-claude-code (Anthropic, no date; related-article list runs to Oct 27, 2026; author Lydia Hallie)
- **Claim**: Model choice sets capability and per-token price; effort sets how much work Claude does per turn (thinking, files read, verification, steps before check-in). Use defaults, pick bigger models for hard or ambiguous work and smaller for routine, and raise effort only when Claude skipped steps.
- **Mechanism**: Effort is sent in the request as an input the frozen weights were trained to respond to; thinking, tool calls and text are all ordinary output tokens at the same rate, and thinking stays in context for the turn. Effort shapes token use but does not cap it; the only hard cap is max_tokens (truncates mid-stream); task budgets or brevity prompts are soft guidance. Heuristic: knew enough but wrong -> larger model; skipped files/tests/refactor -> higher effort. Smaller model on routine work saves money; on hard multi-step work a larger model can cost less per task by needing fewer iterations. Fable is described as costing the most per token.
- **Numbers**: Illustrative: same prompt at high vs low effort generates roughly 7x more tokens (diagram, not benchmark data). Claimed: Opus 4.8 at default effort gives better results for about the same tokens as Opus 4.7 at default. No prices given.
- **Token-cost implication**: Keep default effort, set it as a standing preference not per task, drop to a smaller model for routine stretches, reserve the top model for hard tasks, and fix context/CLAUDE.md before turning up effort.
- **Caveats**: Vendor guidance; curves are explicitly illustrative, no measured benchmarks; the 4.8 vs 4.7 claim is unquantified.
