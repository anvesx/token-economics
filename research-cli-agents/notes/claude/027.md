# 027 — Can your AI agent be cheaper? Effects of task specifications on token spend in agentic coding
- **Source**: https://arxiv.org/abs/2608.25399 (arXiv 2608.25399v1, Jakub Smekal, Stanford, 2026-08-26)
- **Claim**: Cutting a full task spec to a bare user story raises token spend 29.7% (turns +16.4%) with no credible solve-rate change, while run-to-run variance is unaffected by the prompt; a single cheap probe run predicts spend for an unseen task far better than no measurement.
- **Mechanism**: Five SWE-bench Verified tasks x 12 specifications (10 variants of a GitHub Spec Kit 8-section template, plus a raw failing-test anchor and an oracle anchor that states the fix) x 3 thinking efforts (low, high, max) x 15 repeats = 2,700 runs. Model Kimi K3 via Modal at temperature 1.0, scaffold mini-swe-agent, no network. Bayesian hierarchical model (posterior median, 90% credible interval). Predictor: learn a shared cost shape over the spec x effort grid from other tasks, then calibrate the task-level offset with k probe runs at one config (full spec, low effort).
- **Numbers**: Bare user story: +29.7% cost, +16.4% turns, positive on all five tasks; on xarray-7393 +115% (task range 13% to 115%). Single-section removals change cost by -5.4% to -2.4%, turns -1.6% to -0.4%; only acceptance scenarios matter in isolation (+7.0% turns). Oracle spec costs 0.05-0.19x the full spec. Raw failing-test spec is 0.73x-1.10x the full spec and cheapest at low effort on 4 of 5 tasks. Most/least expensive spec ratio: x2.13 low, x1.67 high, x1.61 max; acceptance-scenario removal +20.1% turns (low), 4.5% (high), 2.1% (max). Geometric-mean spend 0.117 USD/run (low) to 0.561 USD (max). Run-to-run geometric SD x1.34 (range x1.29-x1.40 by spec); spread vs mean cost log-log slope 1.08, r=0.95. Cited prior work: identical runs differ up to 30x. Token vs dollar split at Kimi K3 list prices with 96.3% cache hit: output 2.7% of tokens but 51.1% of dollars; fresh input 13.4% of spend; cached input 94% of tokens, 35% of dollars. Prediction: no probe median 161% off (25% of settings within +-50%); 1 probe ($0.11) 36% off (67% within +-50%); 3 probes ($0.34) 29%; 10 probes ($1.13) 25%; budget multiplier for 90% coverage 1.9x with one probe. Per-run correlation r=0.08 without probe, 0.72 with one probe (prior work 0.04-0.39). Log turns vs log cost r=0.953. Solve rates: four tasks 98%+, django-15503 86.3%.
- **Token-cost implication**: Output tokens/turns, not input, dominate dollars at high cache hit rates, so input compression addresses little; reducing turns matters. Concrete specs (named failing test, concrete acceptance cases) cut discovery turns. Large packaged instruction sets cost on every run and buy less at high thinking effort. Cost is predictable cheaply: run one probe and budget with a roughly 1.9x multiplier.
- **Caveats**: Single model (Kimi K3), only five tasks, 98%+ solve rates on most so success effects are barely testable; dollar split depends on price schedule and cache hit rate; specs drafted by an LLM; the probe needs a real run. Figure 6 text says "typically 38% off" vs 36% elsewhere.
