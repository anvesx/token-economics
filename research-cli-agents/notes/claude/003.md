# 003 — How to Track Claude Code Usage in 2026: Built-in Commands, ccusage, and Desktop Dashboards Compared
- **Source**: https://dev.to/pederaa/how-to-track-claude-code-usage-in-2026-built-in-commands-ccusage-and-desktop-dashboards-compared-1kk1 (dev.to, 2026-08)
- **Claim**: Compares ways to monitor Claude Code usage: built-in /usage and /cost, the ccusage log reporter, Claude Code Usage Monitor, and the author's own Blume app.
- **Mechanism**: Claude subscriptions enforce a 5-hour rolling window plus a weekly cap, shared across Claude Code, claude.ai chat and Cowork. /usage shows window and weekly usage with reset times (subscription); /cost shows session API spend; /context shows context fullness. ccusage reads local JSONL agent logs for daily/weekly/monthly/session and 5-hour block reports with per-model and cache token breakdowns, JSON export. Usage Monitor gives live burn rate and predictions, plan-aware (Pro, Max5, Max20, P90 auto-detect).
- **Numbers**: ccusage supports 15+ agent CLIs; Claude retention noted as 30 days; TokenBar commenter price $15 lifetime. No cost savings figures.
- **Token-cost implication**: Instrument usage by workflow shape (exploration, implementation, review, failed attempts, rework) rather than total spend (per commenters); use local-log tools for history since built-ins have none.
- **Caveats**: Author works on Blume (disclosed) and comments include vendor promotion; no measurements, tool comparison is qualitative.
- **Topic**: observability
