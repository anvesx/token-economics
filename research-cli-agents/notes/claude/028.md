# 028 — Experience-Driven Black-Box Cost Control for Coding Agents (TokenEconomizer)
- **Source**: https://arxiv.org/ (project page tokeneconomizer.github.io; code github.com/microsoft/TokenEconomizer) (Microsoft, date not stated in file)
- **Claim**: Coding-agent token costs are repository-specific and recur across tasks, so an external controller that learns from completed traces cuts mean per-task cost by 18.4-30.9% on SWE-Bench with comparable task success, including all controller overhead.
- **Mechanism**: Black-box controller acts only via the instruction prefix, loaded tools and the event stream. Three meta-strategies: (1) micro-skills, one-line operational facts distilled from traces by an LLM proposer, with regex detectors; activated only when confirmed on several non-overlapping tasks and a need rate threshold holds; retired when decayed support q_i(f) < 0 (a contradiction outweighs a confirmation, since a stale skill is re-billed on every prefix); (2) tool pruning: keep shell/read/write/edit, drop tools left uncalled for a number of tasks or judged irrelevant by an LLM, periodically restore the full catalog to re-audit; (3) failure-loop guard using a repository-specific turn budget derived from earlier trajectories, redirecting before terminating. Controller LLM calls are charged to the triggering task. Evaluated with Claude Code, Codex and GitHub Copilot CLI.
- **Numbers**: Profiling over 60 SWE-Bench tasks, 6 repos: recurring actions are 12-28% of tool-call bytes; calls matching an earlier task's action rise from 14% (tasks 2-3) to 30% (5+ prior tasks), only 7% against another repo's history. Agent is shown 23 tool schemas every turn, no repo uses more than 7, 16 are never called, 3 account for 98% of calls. 10 failed runs are 17% of tasks but 32% of spend; 51% of spend falls after a trajectory's first repeated failure signature; Matplotlib failures 45 vs 20 turns. Results: 277 SWE-Bench tasks (6 repos), 102 Web-Bench tasks, 200 security-audit tasks; SWE-Bench cost -18.4 to -30.9% in all five agent-model settings, Pass@1 up in 4 of 5; savings in all 30 repo-setting cells (-5.2 to -40.1%); RTK alone raised cost in 12 cells, RepoMap alone in 15; Web-Bench -16.0 to -21.2%; security -6.4 to -19.6%; cumulative savings 16.9-32.0% per repo, cheaper by the sixth task. Claude Code with Opus 4.8: 30.9% saving, 33.2% with RTK. Ablation on Claude Code: tool pruning -13.2% and -17.7%, micro-skills -11.8% and -14.3%, failure-loop guard single digits; one Sonnet 5 combined result -23.6%. Lower reasoning effort saves a lot but with substantial Pass@1 loss (no exact figure recorded here).
- **Token-cost implication**: Prune unused tool schemas (paid every turn), inject only repository-proven facts, and cap or redirect loops using per-repo turn budgets. Fixed compressors (RTK, Serena, RepoMap) help some repos and hurt others, so measure per repo. Expect an initial cost increase for the first few tasks.
- **Caveats**: Authors' own evaluation on SWE-Bench-style streams of related but independent fixes, not real user sessions; three agents only (no minimal harnesses). A pruned tool or stale skill can hurt until re-audit or retirement. Std devs over three seeds.
