# 083 — Set up Claude Code in a monorepo or large codebase
- **Source**: https://code.claude.com/docs/en/large-codebases (Anthropic docs, no date)
- **Claim**: In a large codebase the small-project defaults fill the context window with instructions and file reads unrelated to the task, "costing tokens and degrading Claude's performance". The fix is to scope Claude to the part of the tree a task touches.
- **Mechanism**: (1) Per-directory CLAUDE.md: starting at the repo root loads only the root file at launch (subdirectory files load on demand); starting in a subdirectory loads that directory's file plus every ancestor's. (2) claudeMdExcludes globs skip other teams' or legacy CLAUDE.md/rules files (static list, merged across scopes). (3) permissions.deny Read rules block committed generated/vendored paths; .gitignore paths are already excluded from searches by default. Deny covers built-in file tools and recognised Bash file commands, not subprocesses or a Bash grep -r over a directory. (4) Code intelligence (LSP) plugins replace many file reads and greps with definition/reference lookups. (5) worktree.sparsePaths plus symlinkDirectories for lighter worktrees and subagent isolation. (6) Per-directory skills load on demand; Claude reads every skill's name and description and loads only the chosen skill's full content. (7) Move conventions out of always-loaded CLAUDE.md into skills, plugins, or an MCP code-search tool. (8) Plan mode writes the plan to a file that is re-injected after each compaction.
- **Numbers**: No measured token or dollar figures. Skills discovered from the repo root can "accumulate into the hundreds"; with many skills some lose their descriptions entirely, names always load. Docs cite /context all to see loaded Memory files and /doctor to trim CLAUDE.md.
- **Token-cost implication**: Start sessions from the package directory, keep the root CLAUDE.md to repo-wide rules, deny-read build output, install an LSP plugin, and keep skill descriptions short so always-loaded context stays small. Each avoided irrelevant instruction or file read is a saving repeated on every turn. Revisit CLAUDE.md rules after model releases, since workarounds become overhead.
- **Caveats**: Configuration guidance with no quantified savings; the cost link is the doc's assertion. Project settings are not inherited from parent directories, and worktree sessions need deny rules duplicated at the root. Sparse checkout saves disk and startup time, not tokens. Points to "Manage costs effectively" for spend data.
- **Topic**: context
