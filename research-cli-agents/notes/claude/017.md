# 017 — Cursor's new pricing structure explained
- **Source**: https://tessl.io/blog/cursor-new-pricing-structure-explained (Tessl, Paul Sawers, 2025-08-20)
- **Claim**: Journalistic explainer on Cursor's shift from 500 fast requests to a $20 credit pool, new Pro Plus and Ultra tiers, community backlash, and how this contrasts with Anthropic's weekly caps on Claude Code.
- **Mechanism**: Credits are pegged to underlying inference costs at API rates; all requests draw from one pool; Auto mode stays "unlimited". Pro Plus and Ultra include multiples of Pro's allowance. Cursor passes through third-party model costs; Anthropic instead caps heavy users with weekly limits on its own compute.
- **Numbers**: Old Pro $20/month = 500 fast requests plus unlimited slow. Pro $20 usage; Pro Plus about $60/month (user-reported, not listed officially) with $70 API usage; Ultra $200/month with $400 API usage (20x Pro). Median-user equivalents: Pro about 225 Sonnet 4, 550 Gemini, 500 GPT-5 requests; Pro Plus about 675, 1,650, 1,500. Typical monthly usage per Cursor: daily Agent users $60-$100, power users over $200. Free tier about 2,000 completions and 50 slower premium requests. Reported Cursor funding $900M at $9.9B valuation (from HN commenter).
- **Token-cost implication**: Agent-heavy daily use typically exceeds a $20 seat allowance by 3-5x; plan for $60-$200/month per heavy developer or route to Auto/cheaper models.
- **Caveats**: Secondary reporting; Pro Plus price from user reports; anecdotes (Reddit, forum) not measurements.
