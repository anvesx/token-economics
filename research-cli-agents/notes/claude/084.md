# 084 — Measure plugin cost and usage
- **Source**: https://code.claude.com/docs/en/plugins/measure (Anthropic, no date)
- **Claim**: Every session with a plugin enabled carries the names and descriptions of its skills, agents and commands in context, and those tokens count against usage whether or not the plugin is used. The page shows how to measure that figure, reduce it, and check whether a plugin is used.
- **Mechanism**: `claude plugin details <name>` (run in a shell) prints a component inventory and projected token cost: an always-on figure (name plus description and when_to_use frontmatter of skills, agents, commands) and a per-component always-on vs on-invoke split (on-invoke is the body that loads when the component fires). Hooks are harness-only with no model context cost; MCP tool schemas are resolved at runtime and not counted (use /context to see MCP tools). To reduce: shorten descriptions, split large plugins; check triggering still works with an eval grader. Usage checks: /plugin "Not used recently" header, /skill-doctor, /doctor, /usage share; fleet-level via OpenTelemetry events (plugin_installed, plugin_loaded, skill_activated, plugin.name and marketplace.name on the cost counter) and the Enterprise Analytics API GET /v1/organizations/analytics/plugins. Non-official plugin names are redacted unless OTEL_LOG_TOOL_DETAILS=1.
- **Numbers**: Example plugin "formatter": always-on ~146 tok per session; per-component always-on ~40, ~50, ~40, <20 tok and on-invoke ~30, ~30, ~40, ~30 tok. Official-marketplace "Every turn:" line is highlighted at 2,000 tokens or more of always-on. "Not used recently" after at least 14 days and 10 sessions unused.
- **Token-cost implication**: Treat plugin descriptions as a per-turn tax: audit with `claude plugin details`, keep descriptions short, split big plugins, disable or uninstall unused ones, and watch /usage and plugin.name cost attribution.
- **Caveats**: Token counts are estimates and "may differ from actual usage". Example figures come from an illustrative plugin, not a measured population. Shortening descriptions can stop skills triggering. Vendor doc.
