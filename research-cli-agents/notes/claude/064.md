# 064 — Acting Less is Reasoning More! Teaching Model to Act Efficiently (OTC-PO)
- **Source**: https://arxiv.org/abs/2504.14870 (arXiv 2504.14870, Wang et al.)
- **Claim**: Adding a tool-use penalty to the RL reward (OTC-PO: Optimal Tool Call-controlled Policy Optimization) cuts tool calls by up to 68.3% and raises tool productivity by up to 215.4% with comparable accuracy, because models without a penalty over-use tools ("cognitive offloading").
- **Mechanism**: RL with a multiplicative tool-integrated reward r = alpha * r_tool * r_correct (multiplicative to avoid reward hacking). r_tool is cosine-based for OTC-PPO and sine-based for OTC-GRPO, with the optimal call count n approximated by the minimum tool calls among correct trajectories. Metric: tool productivity TP = correct answers / total tool calls. Search setting follows Search-R1 (Qwen2.5-3B/7B-Base, NQ and HotpotQA training); code setting follows ToRL (Qwen2.5-Math-1.5B/7B-Base). 8 A100-80G, alpha=1, c = max turns; max tool calls 3 (ToRL) and 4 (Search-R1).
- **Numbers**: Table 1, 7B NQ: Search-R1-PPO TC 3.282 vs OTC-PPO 1.040 (-68.3%), TP +215.4%. ToRL 7B AIME24: TC 0.7 (-66.7%), TP +199.4%. Out-of-domain 7B (TC, Search-R1-PPO vs OTC-PPO): TriviaQA 3.353 vs 1.066, PopQA 3.315 vs 1.083, 2Wiki 4.116 vs 1.868, Musique 4.294 vs 1.942, Bamboogle 3.641 vs 1.828; OTC-PPO EM higher on all with 7B (e.g. TriviaQA 0.623 vs 0.596). Same answers with fewer calls in over 80% of cases on larger model; efficient-case share of "more accurate" cases about 81% (3B) and over 95% (7B). In 42.54% of HotpotQA cases on 3B, OTC-GRPO and Search-R1-PPO matched with the same calls.
- **Token-cost implication**: Tool calls (each adds a round trip plus re-sent context and result tokens) are a trainable cost lever; penalizing redundant calls also shortened responses and sped up training. For agent design, an explicit per-call cost signal reduces redundant searches/commands, so cost per correct answer falls.
- **Caveats**: Tool-call count is the cost proxy, not tokens or dollars. Small open models on QA/math benchmarks, not coding agents. Training-time method (needs RL access), not usable on closed APIs. Cognitive-offloading worsens with model size per the paper. GRPO less stable than PPO.
