# 126 — How to Monitor and Optimize Token Usage in Cline
- **Source**: https://fast.io/resources/cline-token-usage (Fast.io, no date; sources accessed Sep 8, 2026)
- **Claim**: Cline token cost grows because every turn re-sends the cumulative history, tool schemas and file snapshots; monitoring via Cline's Task Header and Task History plus context hygiene (new tasks per milestone, ignore files, checkpoints) controls it.
- **Mechanism**: Cline tracks tokensIn, tokensOut, cacheWrites, cacheReads. Task Header shows cumulative tokens, cost from provider pricing, and context-limit progress; Task History (clock icon) sorts by tokens or cost. Remedies: /newtask (clean session carrying only essentials) vs /smol or /compact (in-place summary); .clineignore exclusions; Plan mode before coding; stable prompt prefix for caching; external MCP doc search instead of pasting docs; milestone decomposition (interfaces, tests, implementation, refactor) each in a fresh session; Checkpoints to roll back tangents and context; lightweight Memory Bank (projectbrief.md, activeContext.md); pause a task that reaches a cost threshold without passing tests. Note: the corpus file itself contains an "[8164 characters truncated]" gap in the middle, so the repetitive-file-read section is not fully visible.
- **Numbers**: none
- **Token-cost implication**: Watch the task header, sort history by cost to catch runaway tasks, exclude build and dependency folders, split work into fresh sessions, and roll back instead of correcting through more prompts.
- **Caveats**: Vendor content marketing (Fast.io MCP workspace), no measurements, partly truncated source text; claims are qualitative.
- **Topic**: observability
