# 044 — Retrieval-Augmented Code Generation: A Survey with Focus on Repository-Level Approaches
- **Source**: https://arxiv.org/abs/2510.04905 (arXiv, Carnegie Mellon / CUHK / SUSTech authors, 2025-10; v3 dated 20 May 2026)
- **Claim**: Survey of retrieval-augmented code generation at repository level, organized by retrieval substrate (graph vs non-graph), control regime (Level 0 fixed pipeline to Level 2 fully autonomous agents) and evaluation setting. It flags scalability, efficiency and the boundary between RAG and long-context LLMs as open issues.
- **Mechanism**: Surveys context construction (structure-aware chunking, hierarchy, compression), retrieval optimization (hybrid, adaptive, policy learning), context selection under length limits (HCP structural-reachability pruning, RepoMinCoder, RepoShapley Shapley-value selection, LongCodeZip function- and block-level pruning, RepoFuse/RAMBO compact prompts), speculative decoding (FastCoder) and precomputed speculative contexts (SpecAgent). Agent levels: Level 0 e.g. Agentless (localize repo, file, lines; patch; regression validation); Level 2 planning/search (MCTS, OrcaLoca action scheduling and context pruning, ARCS). Notes Claude Code replaces static embeddings with grep, ls and cat in a Plan-Act-Observe loop ("agentic search").
- **Numbers**: Agentless reaches 32% on SWE-bench Lite at "low computational cost". Table 6 of proprietary model context windows and per-1M-token input/output prices (no cache, USD) is present, but the values are garbled in the extracted text so none are recorded here. Otherwise no cost figures.
- **Token-cost implication**: Prune and compress retrieved context rather than stuffing it, prefer fixed pipelines (Level 0) when cost matters and use autonomous agents only where needed, and for small well-structured repos consider full long-context input, which the survey says simplifies pipelines but "incur[s] higher cost and latency".
- **Caveats**: Survey of other people's work, no new measurements. Table 6 values unreadable in this copy. Efficiency claims are qualitative. Mentions retrieval-poisoning and verbose-output (DrainCode) denial-of-service attacks as cost-relevant risks.
- **Topic**: context
