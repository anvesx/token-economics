# 111 — The Context Window Gap: Codex CLI caps GPT-5.6 at 272K
- **Source**: https://codex.danielvaughan.com/2026/07/20/context-window-gap-codex-cli-gpt56-advertised-vs-effective-budget-compaction-strategy (Daniel Vaughan, Codex Knowledge Base, 2026-07-20)
- **Claim**: Codex CLI limits GPT-5.6 Sol's advertised 1,050,000-token window to a 272K input budget; the author argues this is sound engineering (lost-in-the-middle, cost, compaction reliability) and explains how to manage the budget.
- **Mechanism**: 400K session cap = 272K input + 128K output reserve; a 5% headroom buffer leaves about 258,400 usable input. Auto-compaction fires around 200K by default: the whole conversation goes to the model to write a lossy "handoff summary" replacing history. Baseline tax before first prompt: system prompt, MCP tool schemas (reloaded every turn), AGENTS.md. Controls: `/status`, `/statusline`, manual `/compact` and `/new`, custom `compact_prompt`, disable MCP servers or use `enabled_tools`, tool search (default since v0.142.2) defers schemas, `model_context_window`/`model_auto_compact_token_limit` overrides (reported to break auto-compaction in some versions). Compared: Claude Code three-tier (trim tool results, cache optimisation, 9-section summary); OpenCode timestamp hiding plus 5-heading summary.
- **Numbers**: GPT-5.6 Sol $5 input / $30 output per 1M tokens (so a 1M-token prompt = $5 input). Effective input cut from 353,400 (372K raw x 95%) to 258,400 (272K raw) on 13 July 2026, -26.9%; v0.144.6 (18 July 2026) aligned metadata. System prompt ~5,000 tokens; tool schemas 2,000 to 100,000+ tokens; AGENTS.md up to 32,768 tokens (project_doc_max_bytes). Cited: 10-25% mid-context accuracy degradation; 78% of production requests under 16K tokens; GPT-5.5 MRCRv2 87.5 at 128-256K.
- **Token-cost implication**: Trim MCP servers/schemas, compact manually at task boundaries, keep rules in AGENTS.md rather than history, and operate on curated 150K contexts rather than filling the window.
- **Caveats**: Blog by an independent author with an affiliated book; most claims (quadratic cost, degradation figures) are secondhand citations; "oscillation reflects server-side cost tuning" is speculation; quadratic memory claim is a simplification.
- **Topic**: context
