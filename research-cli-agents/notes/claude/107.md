# 107 — Codex CLI Performance Optimisation: Token Overhead, Hidden Costs and Tuning Tactics
- **Source**: https://codex.danielvaughan.com/2026/04/08/codex-cli-performance-optimization (Daniel Vaughan, 2026-04, updated May 2026)
- **Claim**: Most Codex CLI token spend is invisible overhead (system prompt, tool/MCP schemas, file reads, reasoning, retries and compaction), and config keys can cut it. Treat token budget as a quality indicator, since long compacted sessions degrade accuracy.
- **Mechanism**: Compaction fires above model_auto_compact_token_limit: full history plus a summarisation prompt goes to the model; new history = initial context + recent user messages (~20K) + summary. Keys: model_context_window, model_auto_compact_token_limit, tool_output_token_limit, compact_prompt, model_reasoning_effort, plan_mode_reasoning_effort, model_reasoning_summary, model_verbosity, [history] max_bytes. Profiles (--profile quick/deep via [permission_profiles.*], v0.134.0+). codex exec for batch/CI; /compact manually at ~60% context; keep system prompt and tool config stable for cache hits; /status for diagnostics. Retries resend the full context and can trigger compaction.
- **Numbers**: GitHub MCP server with 93 tools about 55,000 tokens per turn. System prompt+AGENTS.md 2,000-5,000 tokens/turn; built-in tool ~500 tokens each; MCP server 200-500 each; MCP tool definition 550-1,400 each; four-server setup ~7,000/turn; 500-line file ~15,000 input tokens. xhigh uses 3-5x more tokens than medium. Cached input ~10% of uncached (6.25 vs 62.50 credits/1M for GPT-5.4). GPT-5.4-mini uses 30% of GPT-5.4 quota. Windows: GPT-5.5/5.4 1M, 5.4-mini 400K, 5.3-Codex 272K input/400K total. Example config model_auto_compact_token_limit=64000, tool_output_token_limit=12000. Per task at GPT-5.4: explain 500-line module ~15K in/2K out ~$0.25; refactor 10 files ~120K/30K ~$2.25; repo audit ~200K/20K ~$3.00. Plus $20/mo, Pro $200/mo.
- **Token-cost implication**: Audit and disable idle MCP servers, set tool output cap and earlier compaction, use mini/low effort profiles for routine work, reserve xhigh, keep prompts stable for caching, start new threads per phase.
- **Caveats**: Secondary blog compiling other sources (BSWEN, gists); figures are estimates not measurements by the author; no built-in per-source token breakdown (issue #13222).
