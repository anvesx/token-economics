# 035 — Context Management Across Codex Surfaces
- **Source**: https://developertoolkit.ai/en/codex/build/context-patterns (Developer Toolkit, 2026-11; page updated 2026-10-03)
- **Claim**: Keep a Codex thread's fixed prefix small and chain short threads via a handoff file instead of relying on compaction; larger windows delay compaction but make every turn costlier.
- **Mechanism**: Each turn sends a fixed prefix (Codex instructions, AGENTS.md chain, skills, MCP tool definitions) plus a growing conversation. Measure with /status, /mcp verbose, and codex debug prompt-input. Disable unneeded MCP servers (enabled=false, enabled_tools). Use /compact within a phase, /new between phases, /side for side questions, subagents for exploration (read in own thread, return short report), codex exec clean start vs resume. Tune model_auto_compact_token_limit and model_post_turn_compact_threshold_percent. Enforce constraints via CI checks, per-phase tests, fresh-context /review.
- **Numbers**: Default window 272K tokens, configurable via model_context_window up to catalog ceiling 872K; example auto_compact limit 180000 and post-turn threshold 70%; project_doc_max_bytes 32,768; handoff file under 60 lines; subagent report max 30 lines. Codex CLI 0.157.1. Codex warns multiple compactions reduce accuracy.
- **Token-cost implication**: Trim AGENTS.md and MCP tools (paid every turn), ask subagents to explore, request symbols not files, start a new thread per phase, resume only to finish interrupted work (resume reloads whole transcript).
- **Caveats**: Vendor guide (sells a toolkit), no measured savings; page says per-component token tables are repo-specific and gives none. Codex-only.
- **Topic**: context
