# 102 — Subagents in ChatGPT and Codex
- **Source**: https://learn.chatgpt.com/docs/agent-configuration/subagents.md (OpenAI, date not stated)
- **Claim**: ChatGPT Work and Codex can spawn parallel subagents that return summaries to a main thread; this protects the main context from noisy output but consumes more tokens than comparable single-agent runs.
- **Mechanism**: Subagents are spawned when the user asks directly, when AGENTS.md or skill instructions request it, or (Ultra intelligence level in ChatGPT Work) proactively. The main thread waits for all results and consolidates. Model and reasoning resolution order: explicit spawn value, then `[agents]` default (`default_subagent_model`, `default_subagent_reasoning_effort`), then the parent's value; a custom agent file's `model`/`model_reasoning_effort` takes precedence over these. If a model is chosen without an effort, that model's default effort is used. Custom agents are TOML files in `~/.codex/agents/` or `.codex/agents/` with required `name`, `description`, `developer_instructions`; they can disable `features.shell_tool`, `apps`, `plugins`, `memories`, `request_permissions_tool`, skills, and `skills.include_instructions`. They inherit sandbox, approval policy, provider and MCP servers from the parent and cannot override them. Built-in agents: default, worker, explorer. `agents.max_concurrent_threads_per_session` caps parallel threads; `agents.enabled` defaults true.
- **Numbers**: No cost figures. Example configs: max_concurrent_threads_per_session 8 (PR review) and 6 (frontend debugging); model split gpt-6-luna (fast, lower-cost, high effort) for exploration/docs/fix agents, gpt-6.1-sol with medium effort for reviewer/browser-debugger. Suggested starting efforts: `high` for GPT-6 Luna, `low` for GPT-6 Astra. Reasoning levels: low, medium, high, xhigh, max, ultra.
- **Token-cost implication**: Delegation trades tokens for context hygiene and speed; use it for read-heavy parallel work (exploration, tests, triage), be careful with parallel write-heavy work, cap concurrency, and assign cheaper models and lower effort to narrow subagents while reserving the stronger model for review and ambiguous work.
- **Caveats**: Vendor doc with no measurements; it states only qualitatively that subagent runs cost more; model recommendations are guidance, not benchmarked; custom-agent instructions to avoid edits do not create a read-only sandbox.
- **Topic**: agent-cost
