# 065 — Context editing on the Claude Developer Platform
- **Source**: https://platform.claude.com/docs/en/build-with-claude/context-editing (Anthropic, 2025-06)
- **Claim**: The Messages API (beta header context-management-2025-06-27) can server-side clear old tool results and thinking blocks to keep context small; server-side compaction (compact_20260112) is the primary recommended strategy, with SDK client-side compaction deprecated.
- **Mechanism**: clear_tool_uses_20250919 triggers when input exceeds a threshold, clears oldest tool results chronologically (placeholder text), keeping the N most recent; options trigger, keep, clear_at_least, exclude_tools, clear_tool_inputs. clear_thinking_20251015 with keep thinking_turns N or "all"; must be listed first when combined. Applied server-side before the prompt reaches Claude; the client keeps full history. Clearing tool results invalidates the cached prefix (use clear_at_least to make it worthwhile); keeping thinking preserves the cache, clearing it invalidates at that point. Response field context_management.applied_edits reports cleared tokens; the token counting endpoint previews post-edit counts. Pairs with the memory tool (Claude warned before clearing). Client compaction (TS/Ruby tool_runner) sums input + cache_creation + cache_read + output tokens, injects a summary prompt, replaces history; it can miscount with server-side tools (cache_read accumulates internal calls).
- **Numbers**: Defaults: trigger 100,000 input tokens; keep 3 tool uses; thinking keep 1 turn when strategy is present; clear_at_least none. Examples: trigger 30,000, keep 3, clear_at_least 5,000; count_tokens example 70,000 original to 25,000 after. Compaction brings ~100k history to ~2-3k tokens (illustrative). SDK compaction_control default threshold 100,000. Model-default thinking retention varies (e.g. Opus 4.5 and later keep all prior thinking). On Claude 5.1+ server-side management never invalidates thinking blocks.
- **Token-cost implication**: Use tool-result clearing with clear_at_least so cache rewrites pay off, exclude persistent tools, preview with count_tokens, and prefer server-side compaction for long agent loops.
- **Caveats**: Vendor docs, beta; no measured savings; cleared content is not recoverable by the model, so tasks needing exact early recall are poor fits; not HIPAA eligible, ZDR eligible.
