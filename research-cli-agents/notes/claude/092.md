# 092 — Claude Code Week 16 (April 13-17, 2026) release notes
- **Source**: https://code.claude.com/docs/en/whats-new/2026-w16 (Anthropic, 2026-04)
- **Claim**: Weekly changelog for Claude Code v2.1.105 to v2.1.113. Items relevant to cost: new xhigh effort level on Opus 4.7, a /usage breakdown of what drives limits, an opt-in 1-hour prompt cache TTL for API-key and cloud-provider users, and PreCompact hooks that can block compaction.
- **Mechanism**: Opus 4.7 adds an xhigh effort level between high and max, applied as the default when you first switch to 4.7; /effort without arguments opens an arrow-key slider. /usage shows parallel sessions, subagents, cache misses and long context, each as a percentage of the last 24 hours with an optimization tip (d or w toggles day or week). ENABLE_PROMPT_CACHING_1H opts API key, Amazon Bedrock, Google Cloud Agent Platform and Microsoft Foundry users into a 1-hour cache TTL. PreCompact hooks block compaction by exiting with code 2 or returning "decision":"block". /fewer-permission-prompts proposes an allowlist from transcripts. Routines are cloud agents triggered by schedule, GitHub event or API. Native per-platform binary replaces bundled JavaScript in v2.1.113.
- **Numbers**: Prompt cache TTL option: 1 hour (default for these users is not stated on this page). /usage windows: last 24 hours, with day and week views. No prices or savings figures.
- **Token-cost implication**: Run /usage to see which of parallel sessions, subagents, cache misses or long context dominates, then fix that. API-key and cloud users with sessions that pause longer than the default cache window can set ENABLE_PROMPT_CACHING_1H to avoid cache-miss repricing. xhigh is a new middle-high setting to test before max.
- **Caveats**: Changelog only, vendor self-reported, no measurements; the effort levels' token usage is not given. Default cache TTL for API-key users is not on this page.
- **Topic**: limits-billing
