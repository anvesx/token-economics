# 005 — Track Claude Code Usage and Spend Across Your Company
- **Source**: https://langwatch.ai/blog/track-claude-code-usage-and-spend-across-your-company (LangWatch, 2026-10-27)
- **Claim**: Company-wide Claude Code cost tracking is best done by exporting Claude Code's built-in OpenTelemetry data to one backend (LangWatch, via `npx langwatch claude`), giving cost per person, session, repo and pull request. The post also argues compaction timing and cache lifetime dominate spend.
- **Mechanism**: Claude Code emits OTel metrics (claude_code.cost.usage, claude_code.token.usage by model and token type) and events (claude_code.compaction). LangWatch ingests them; personal project by default, `--project` pins to a team project, ingest keys for CI/headless, managed settings for fleets. Branches map to PRs via GitHub for per-PR cost. Cost is cache-aware (cache reads at read rate); subscription usage shown as API-equivalent dollars. /usage (aliases /cost, /stats) is local, list-price, resets on /clear. Diagnosis order: spend by model, top sessions by cost, then a cost-check skill. Admin access to personal sessions is audited; content can be dropped, keeping only metadata.
- **Numbers**: Cache reads and writes are about four fifths of Claude Code spend across LangWatch orgs. Cache read is ~a tenth of input price on many models. In the author's sessions each doubling of context cost about 6x more; best compaction point 250k-450k tokens; guide recommends "autoCompactWindow": 400000. One controlled run: compacting at 150k halved a long reading session's cost but the agent could not answer questions about early-read files. Cache TTL 5 minutes on API key/cloud, 1 hour on subscription main conversation; "promptCacheTtl": "1h" for pay-per-token. Anthropic docs enterprise average about $13 per developer per active day. Moving off an older model version: estimated median saving about a quarter of spend.
- **Token-cost implication**: Export OTel per developer, compact around 400k rather than letting context grow, set 1h cache TTL, avoid sub-agents or defaults on the top model, and review per-PR and per-session cost.
- **Caveats**: Vendor blog selling the tool; the compaction analysis is the author's own sessions, and the 150k run was a single controlled run. The "four fifths" figure is from LangWatch customers. Savings estimates are unaudited.
