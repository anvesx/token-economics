# 012 — Orchestrator pattern: big models for planning, small models for execution
- **Source**: https://platform.claude.com/cookbook/managed-agents-cma-plan-big-execute-small (Anthropic, 2026-05)
- **Claim**: In read-heavy agent workloads, a frontier orchestrator that only plans/synthesizes, with cheap worker models doing the token-heavy reading in their own contexts, beats a rigor-matched solo frontier agent on cost (and wall-clock).
- **Mechanism**: Managed Agents `multiagent_20261001` block: orchestrator (claude-fable-5-1, no tools) lists a worker (claude-sonnet-5-5, tools scoped to web_search + web_fetch) in `subagents.predefined_agents`; it gets create_agent/send_to_agent/list_agents automatically; inline agents and workflows set to disabled so all work goes to the listed worker. Workers run in parallel session threads and return distilled reports via send_to_parent, so raw pages never enter the orchestrator context. Cost metering via per-thread cumulative `usage.list_cost` (server-side at list rates); session `budget` (type limit, max_list_cost; amounts in cents, "1000" = $10) pauses runaway fan-out. Control arm: solo frontier agent forced to verify each fact from two independent fetches.
- **Numbers**: On the authors' runs 84-98% of the team's input tokens billed at the worker rate; task = 20 facts (10 parks x 2 attributes). Rate table in code ($/MTok input/output/cache-read): Fable 5.1 $10/$50/$0.25; Sonnet 5.5 $2/$10/$0.20; 5-minute cache write = 1.25x input, 1-hour = 2x. No specific total dollar bills or cost ratio are given in the text (script prints them).
- **Token-cost implication**: Move bulk reading/scanning (doc review, log analysis, codebase sweeps) to cheap parallel workers; give the planner no tools; set a session budget cap; meter per thread to attribute spend. Do not over-split: each worker thread has a fixed setup overhead.
- **Caveats**: Vendor cookbook; results from the authors' own runs before moving to the current multiagent type; single question type (coverage, not discovery tasks); splitting into more, narrower briefs raised cost; solo agent without matched rigor is cheaper but lower quality; premise (park list) was not verified and was wrong in one run; orchestrator cannot see worker prompts; no gain on narrow questions or when raw-material judgment needs a frontier model.
