# 034 — How to Reduce Codex CLI Token Usage: 7 Proven Optimization Strategies
- **Source**: https://docs.bswen.com/blog/2026-03-02-reduce-codex-cli-token-usage (bswen, 2026-03)
- **Claim**: A developer blog says seven changes cut their CLI agent token consumption by roughly 60%+, led by a settings.json change (cheaper model, thinking cap, earlier compaction, cheap subagent model). The post mixes Codex CLI and Claude Code settings.
- **Mechanism**: (1) ~/.claude/settings.json with model "sonnet", env MAX_THINKING_TOKENS=10000, CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50, CLAUDE_CODE_SUBAGENT_MODEL=haiku. (2) AGENTS.md "incremental narrowing" (scan -> read -> slice), capped shell output, summaries over dumps. (3) Disable unused MCP servers; prefer skills/CLI over MCP (Playwright CLI vs Playwright MCP). (4) Budget helpers: log viewer defaults to 50 lines, --full gives 1000; targeted rg with head limits. (5) New thread per phase (investigate, fix, verify), carrying a summary. (6) Opt out of notification methods thread/tokenUsage/updated and item/agentMessage/delta. (7) Loki/Grafana log monitoring to catch spikes.
- **Numbers**: Extended thinking reserves up to 31,999 tokens per request; auto-compaction default at 95% judged too late. Author-claimed impacts: sonnet ~60% cost reduction; MAX_THINKING_TOKENS 10000 ~70% hidden-cost reduction; subagent haiku ~80% subagent savings; overall ~60% reduction. Weekly usage was bouncing 59-62%. Codex CLI 0.106.0.
- **Token-cost implication**: Cap thinking tokens, compact at ~50% rather than 95%, route subagents to the cheapest model, trim MCP servers, cap tool output, and reset threads between phases.
- **Caveats**: Single-author, self-reported, no methodology or baseline measurement; per-setting percentages are unsupported. Conflates Codex CLI with Claude Code config paths and env vars, so applicability to Codex is unclear.
