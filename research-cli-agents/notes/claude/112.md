# 112 — Context Compaction Showdown: Codex CLI, Claude Code and 5 Other Agents
- **Source**: https://codex.danielvaughan.com/2026/04/10/context-compaction-showdown-coding-agents (Daniel Vaughan, 2026-04)
- **Claim**: Seven coding agents compact full context windows in two patterns (Extract: summarise-and-replace in six; Event Store in OpenHands), and every compaction destroys the KV/prompt cache, so compaction timing is a cost decision as well as a quality one.
- **Mechanism**: Extract: an LLM summary replaces older messages (destructive, cumulative loss across rounds). OpenHands: append-only event log with suppression markers, reversible. Thresholds: Gemini CLI ~50%; Roo Code ~86-92% (contextWindow x 0.9 - maxOutputTokens); Claude Code ~89% (contextWindow - min(maxOutput,20k) - 13k); Codex CLI ~90% (configurable downward only; model_auto_compact_token_limit e.g. 180000, varies 180k-244k by model); Pi ~92% (window - 16,384); OpenCode ~96-99%; OpenHands event-based (100 events or agent-triggered). Codex has two paths: local LLM summary for non-Codex models, and encrypted remote compact() endpoint (POST /v1/responses/compact) for Codex models. Claude Code: microcompact (no-LLM, removes redundant tool output), tool-output clearing, full summarisation, cross-session cache reuse, Compact Instructions in CLAUDE.md or `/compact focus on ...`, plus thrashing detection that stops auto-compacting after a few attempts. Gemini CLI summarises then self-critiques and keeps 30% of the tail verbatim. OpenCode protects the last 40,000 tokens of tool output, 20,000 minimum prunable, OPENCODE_DISABLE_AUTOCOMPACT. Roo Code tags segments with condenseParent and uses tree-sitter signatures. Pi accumulates file-operation tracking in XML.
- **Numbers**: Anthropic cache read ~92% cheaper than cold read: $0.019 vs $0.23 for 60,000 tokens. One compaction on a 125,000-token context costs $0.40, about 21 follow-up cached turns (wasnotwas.com analysis). Pre-compaction checklist (7 categories) raised summary length from 1,643 to 2,455 tokens (the article calls it a 49% improvement) at $0.0131 extra cost. Three or more compactions deep suggests restarting. MIT/Harvard Feb 2026 Fast KV Compaction via Attention Matching, reported 50x memory reduction (headline cited), still research.
- **Token-cost implication**: Delay compaction while the cache is warm, add Compact Instructions or a preservation checklist, prefer fresh subagents over extending long sessions, track compaction count (`/context`), and treat three successive compactions as a signal to restart with a structured handoff.
- **Caveats**: Secondary synthesis of others' work (mostly wasnotwas.com and a GitHub gist), not the author's own measurements; "49% improvement" is increase in summary length, not a measured quality gain; pricing and dollar figures are one analysis's example; the encryption-motive explanation is speculation.
