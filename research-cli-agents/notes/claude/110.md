# 110 — Where Do Your Tokens Go: Empirical Token Consumption in Coding Agents
- **Source**: https://codex.danielvaughan.com/2026/07/03/where-do-your-tokens-go-empirical-token-consumption-coding-agents-codex-cli-budget-control (Daniel Vaughan, 2026-07)
- **Claim**: Two cited studies show agent token cost is structural: input/re-reading dominates, spend is highly variable, models cannot predict it, and extra spend saturates. The post maps this onto Codex CLI controls (rollout budget, compaction, tool-output cap, profile routing, reasoning effort).
- **Mechanism**: Each turn re-ingests history plus tool outputs (context snowball). Codex config: [features.rollout_budget] limit_tokens with reminder_interval_tokens aborts the turn when exhausted; model_auto_compact_token_limit triggers compaction; tool_output_token_limit caps stored tokens per tool output; profiles pick model/effort/service_tier (flex trades latency for lower cost). SWE-Pruner (0.6B neural pruner) proposed as a PostToolUse hook, not integrated.
- **Numbers**: Bai et al. (arXiv:2604.22750, 8 frontier models, SWE-bench Verified): agentic coding ~1,000x more tokens than code chat/reasoning; same task same model differs up to 30x; self-estimate vs actual correlation at most 0.39 with underestimation; Kimi-K2 and Claude Sonnet 4.5 use over 1.5M more tokens than GPT-5 on same tasks without accuracy gains. Salim et al. (arXiv:2601.14470, ChatDev with GPT-5): code review 59.4% of tokens, input tokens 53.9%. Read operations 76.1% (ResearchGate cite). Config examples: model_context_window 272000, auto_compact 64000, tool_output_token_limit 12000 (suggest 8000), rollout limit 100000 (150000 interactive/50000 CI in diagram). SWE-Pruner: 23-54% token reduction, up to 14.84x compression, claimed 20-40% cost savings on Claude Code. Reports: Microsoft ~ $2,000 per engineer per month; Uber spent 2026 AI budget in four months; Goldman projects 24x token growth by 2030 (120 quadrillion/month).
- **Token-cost implication**: Set hard per-run token budgets for automated workflows, cap tool output, compact early, use cheaper model/low effort and flex tier for background and subagents, and measure via trace logs before tuning.
- **Caveats**: Secondary blog summarizing papers; pie chart split other than 59.4% looks illustrative (not in cited text); the 8000 cap and budget values are suggestions, not measured; "without measurable accuracy loss" is asserted, not shown; news figures second-hand.
