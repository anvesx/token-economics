# 052 — Your cache hit rate is lying to you. It's the caller mix.
- **Source**: https://dev.to/theagentloop/your-cache-hit-rate-is-lying-to-you-its-the-caller-mix-ec1 (dev.to, The Agent Loop, 2026-10)
- **Claim**: An account-level cache hit rate hides very different per-caller behavior (main loop, subagents, forks, compaction, cron); cache TTL should be chosen per write and hit rate tracked per caller.
- **Mechanism**: Caching multipliers: 5-minute write 1.25x, 1-hour write 2x, read 0.1x on most models. One read pays off the 5-minute write (1.35x vs 2x uncached). Every hit refreshes the TTL; keepalive crossover 62.5 min (5 x 1.25/0.10). Claude Code TTL by bucket: main conversation 1h on subscription within plan usage, else 5m; everything else (subagents, workflows, forks, compaction, titles) 5m. Settings: promptCacheTtl, subagentPromptCacheTtl, ENABLE_PROMPT_CACHING_1H (v2.1.242+). A subagent cannot read its parent's cache (prefixes diverge); a fork inherits the exact prefix and hits at once. Parent waiting on a subagent sends no requests, so its cache expires after 5 minutes. Silent failure modes: token floors (512 min on current-gen; 4,096 for Opus 4.6/4.5 and Haiku 4.5), 20-block lookback limit, compaction using a different system prompt, cron runs starting fresh sessions. Recommended: log caller x TTL tier, read usage.cache_creation.ephemeral_5m/1h and cache_read, put stable head behind cache_control and date/cwd/branch after, use ttl 1h only on the dispatch turn and shared static prefixes.
- **Numbers**: One deployment 77% hit rate while cron tasks ~0%: 672 runs/day x ~30K token static prefix, roughly 20M input tokens daily uncached. Opus 5.5 at $4/MTok input: 5m write $5.00, 1h write $8.00, read $0.20 (0.05x on Opus 5.5, 0.025x on Fable 5.1). Median subagent child runtime ~9 min; 96% of those waits ended in true cache death (at least half the prefix rewritten). Blanket 1h TTL made the bill 8.6% worse; 98% of reuse within ~34 s of the write (median 7 s). Fixes: 1h write on dispatch turn -6.0%; persistent per-type static prefix -1.0%; dynamic content after stable prefix -7.6%; all three -13.6%. One agent run: 3.5M input vs 271K output tokens. A user's blocks hit the lookback at 23 blocks.
- **Token-cost implication**: Do not enable 1h TTL blanket-wide; set it only where a gap of 5-60 minutes is expected (dispatch turns, shared prefixes), place volatile content after the cached prefix, reuse the parent's exact prefix in compaction, and expect near-zero caching for cron/fresh sessions.
- **Caveats**: Independent blog, not affiliated with Anthropic; figures come from public docs and GitHub issues (#74318, #84289), not its own experiments; docs and observed subagent TTL conflict, per the author; the 8.6% and 13.6% results are from one operator's data.
