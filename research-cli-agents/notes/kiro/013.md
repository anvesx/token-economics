# 013 — How to Use a Smart Orchestrator Model to Direct Cheaper Sub-Agent Models in Claude Code
- **Source**: https://www.mindstudio.ai/blog/smart-orchestrator-cheaper-sub-agent-models-claude-code (MindStudio, 2026-04)
- **Claim**: A two-tier orchestrator-subagent pattern — an expensive frontier model for planning/review, cheap models for execution — can cut coding-workflow token costs by 5–10x with little quality loss, and Claude Code supports it natively via the Task tool.
- **Mechanism**: Orchestrator (e.g. Claude Opus) reads the goal, decomposes into subtasks, delegates, reviews outputs, and decides retry/accept. Sub-agents (Claude Haiku, DeepSeek Coder, Gemma 3, Qwen2.5-Coder) execute bounded tasks (code gen, file reads, tests, searches) in isolated contexts receiving only what they're told. Claude Code's Task tool spawns isolated sub-agent instances; model selection is configurable per role (orchestrator via `claude --model claude-opus-4-5` or config; sub-agents via `--model` flag or SDK calls). A CLAUDE.md system prompt positions the primary model as an orchestrator that delegates rather than writes code. Rule of thumb: tasks a junior dev could do reliably go to sub-agents; judgment/architecture/ambiguity stays with the orchestrator. Non-Anthropic models routed via OpenAI-compatible endpoints or LiteLLM proxy.
- **Numbers**: Claimed 5–10x total token-cost reduction. In a well-designed workflow 80–90% of token usage moves to cheaper models. Claude Haiku costs "roughly 25x less than Claude Opus per token as of mid-2025." Example auth-module refactor: ~2,000–3,000 Opus tokens (planning + review) + 15,000–25,000 Haiku/DeepSeek tokens (execution). Install: `npm install -g @anthropic-ai/claude-code`.
- **Token-cost implication**: Route planning/review/judgment to an expensive model and bulk execution (code gen, file reads, tests, boilerplate, reformatting) to cheap models; keep sub-agent contexts minimal by having the orchestrator extract only relevant context before delegating; build explicit review checkpoints to catch cheap-model errors; match model to task complexity (bump a hard sub-task up to Sonnet). Even a simple two-call setup (plan with Opus, generate with Haiku) saves money.
- **Caveats**: Vendor blog (MindStudio, promotes its Agent Skills Plugin and "Remy" product); figures (5–10x, 80–90%, 25x) are self-reported/illustrative with no benchmark or methodology. Token counts in the refactor example are rough ranges. Quality-loss claim ("minimal" for well-scoped tasks) is asserted, not measured. Model names/prices (claude-opus-4-5, claude-haiku-4-5) reflect the article's date.
