# 004 — Monitoring Claude Code Usage with OpenObserve and MCP
- **Source**: https://openobserve.ai/blog/monitor-claude-code-usage-openobserve-mcp (OpenObserve, 2025-06)
- **Claim**: Setting `CLAUDE_CODE_ENABLE_TELEMETRY=1` and pointing Claude Code's OTLP exporter at OpenObserve ships token counts, cost, sessions, tool decisions, and per-prompt events as standard OpenTelemetry signals; you can then attribute spend by developer/repo/team, build a productivity dashboard, and query the same telemetry in natural language via OpenObserve's MCP server.
- **Mechanism**: Claude Code exports three OTel signal types. Metrics (8): session.count, lines_of_code.count, pull_request.count, commit.count, cost.usage (USD), token.usage, code_edit_tool.decision (accept/reject + language), active_time.total. Cost/token counters carry attributes: model, type (input/output/cacheRead/cacheCreation), query_source (main/subagent/auxiliary), effort, agent.name, skill.name, mcp_server.name. Events: user_prompt, api_request (model, cost_usd, duration_ms, input/output/cache_read/cache_creation tokens), api_error (status_code), api_refusal, tool_result, tool_decision — each carries a prompt.id UUID linking a prompt to all its API calls and tool runs. Traces (beta, needs CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1): interaction → llm_request (ttft_ms, stop_reason) / hook / tool (blocked_on_user vs execution). OTLP endpoint = https://<host>/api/<org> (no trailing slash; SDK appends /v1/metrics etc.). Route team traffic through an OTel Collector to batch/redact/tag/fan-out. Attribute org structure via OTEL_RESOURCE_ATTRIBUTES (team.id, cost_center, repo.name); roll out via managed-settings.json pushed by MDM. cost_usd is Claude Code's own *client-side estimate* (token counts × per-model prices, cache-aware), close to invoice. Recompute with your own rates via an enrichment table joined on exact model ID. Part 2: enable MCP server (O2_AI_ENABLED, O2_TOOL_API_URL), `claude mcp add` the /mcp endpoint, then ask NL questions that the agent answers by running SearchSQL/PromQL (server front-lists a few tools, exposes ~120 via tool_search).
- **Numbers**: 8 metrics. Anthropic guidance: average ~$13 per developer per active day and $150-250 per developer per month, with costs below $30/active day for 90% of users. Default export intervals: 60s metrics, 5s logs. OTLP gRPC port 5081; MCP API default port 5080. Cache pricing (per 1M tokens, example enrichment table): claude-opus input 5.00 / output 25.00 / cache-write 6.25 / cache-read 0.50; claude-sonnet 3.00 / 15.00 / 3.75 / 0.30; claude-haiku 1.00 / 5.00 / 1.25 / 0.10. 5-minute cache write = 1.25× input rate; cache read = 0.1× input rate. MCP server default 1,000-row result cap + query timeout.
- **Token-cost implication**: You can't govern Claude Code spend until its telemetry leaves the laptop — enable OTel, tag by team/repo/cost_center, and dashboard spend split by developer, model, and tool. Watch the type attribute: cache reads are priced far below fresh input, so a cache-miss spike is a direct cost signal. On Bedrock/Vertex/Foundry Claude Code does NOT emit cost, so price spend at the gateway instead. Keep your own pricing enrichment table (join on exact model ID incl. date suffix or rows drop silently).
- **Caveats**: Vendor blog (OpenObserve); instructions are self-reported setup, not a cost study. cost_usd is a client-side estimate, not billed; cross-check against SUM(cost_usd) and your own rates. Traces are beta. Rates "current as of writing" — confirm Anthropic pricing. MCP token = a database credential: use least-privilege read-only RBAC (Enterprise), rate limits, audit logging, and beware prompt/raw-body logging surfacing sensitive content.
- **Topic**: observability
