# 033 — LLMRouter: Unified Infrastructure for Developing, Evaluating, and Deploying LLM Routers
- **Source**: https://arxiv.org/abs/2608.06867 (arXiv, 2026-08)
- **Claim**: Presents a unified formulation of LLM routing as a sequential decision process (five components), an automated supervision/evaluation pipeline, a multi-scenario benchmark (xRouteBench), and an open-source library (16+ routers); learned routers beat the strongest fixed-model baseline by 14.6% relative while costing less.
- **Mechanism**: Routing cast as policy π maximizing E[perf(y|q) − λ·c(τ)]. A router = context encoder E_q (embedding- or text-based over query/persona/history), model encoder E_m (static metadata, historical profiles, learned embeddings, or verbalized names), scoring function g, decision rule d, and learning signal L (supervised pointwise, preference/pairwise, or trajectory RL). Three families: single-turn, multi-turn (incl. agentic), personalized. Data engine: sample queries → dispatch each to all 18 candidate models → score with task metric + record token cost → dense query–model performance/cost matrix that serves as both supervision and test bed. Adding a router = subclass MetaRouter + implement route_single/route_batch and a loss_func. Deployable as OpenAI-compatible server (OpenClaw/Slack/Discord) or ComfyUI canvas.
- **Numbers**: xRouteBench = 4,767 instances across 5 tracks (Generic LLM Tasks 3,729; Memory: LoCoMo 314 + LongMemEval 101; TimeSeries 127; Vision: Geometry3K 61 + MathVista 100 + Charades-Ego 27; Personalized 308). 18 open-weight candidate models, 7B–671B, two providers; input price spans ~25x ($0.05 to $1.25 per 1M tokens). Learned routers: +14.6% relative over strongest fixed-model baseline. Performance-first (α,β)=(1.0,0.0): GraphRouter best average; RouterDC best on Generic LLM Tasks (80.56); SVMRouter best LoCoMo (74.21). Multi-turn routers much weaker (Router-R1 avg 22.30). Personalized track persona-judge: GMTRouter 68.78 > PersonalizedRouter 67.86 > EloRouter 66.40. Real-user Slack study (15 users, 40 sessions, 234 pairwise records, 8 test sessions): PersonalizedRouter 83.05 acc, CausalLM last 27.97; GMTRouter drops to 6th (70.70). Multi-agent (5 topologies): 6/7 learned routers beat always-largest; MFRouter best avg 76.48 vs largest 71.48. Memory track retrieves top-5 via Contriever, scored token-level F1.
- **Token-cost implication**: No single router dominates — pick the router matching the deployment's performance–cost operating point; rankings reverse toward lightweight routers (e.g. MLPRouter) under tighter cost weight β. Always calling the largest model is dominated: it costs most yet only mediocre, because many queries it fails are solved by smaller cheaper models. Multi-turn decomposition/aggregation often adds cost and redundant information with no consistent gain, so prefer a single well-chosen route unless sufficiency estimation/early stopping is in place. Personalization pays only when user context is modeled well, and simulated persona rankings don't fully transfer to real users — validate on real feedback. In multi-agent systems, route each node independently.
- **Caveats**: Candidate pool is open-weight only (18 models); costs are per-token list prices, not realized API spend. Personalized supervision uses a persona-conditioned LLM judge (DeepSeek-V3.1) whose cost is excluded from reported cost, and judge preferences are synthetic personas (PersonaHub). Real-user study is small (15 users / 234 records). Multi-turn routers use a fixed small base model (Qwen2.5-3B-Instruct), so their weak results are partly base-model-limited. Authors from UIUC et al.; self-reported.
- **Topic**: routing
