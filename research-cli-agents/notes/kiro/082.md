# 082 — Code Review costs and usage
- **Source**: https://code.claude.com/docs/en/code-review-costs.md (Anthropic, doc, undated)
- **Claim**: Claude Code Review has no flat per-review price; it is billed on token usage through usage credits, and total spend is the per-review cost times the number of reviews. Admins estimate, cap, and monitor spend through the admin console.
- **Mechanism**: Each review's cost scales with the review level, the size of the change, the complexity of surrounding code, and how many candidate issues need verification. Number of reviews is set per repository by the "Review runs" setting: "Once after PR creation", "After every push" (multiplies cost by pushes per PR), or "Manual (@claude review)". Comment commands modify counts: `@claude review always` opts a PR into push-triggered reviews; `@claude review` runs one review without subscribing; drafts and fork PRs skip automatic reviews. Reviews bill to the organization (not the PR author), appearing on the Anthropic bill regardless of Bedrock/Google/Microsoft Foundry use for other features. Spend is capped via a monthly Code Review spend limit, the org spend limit, and usage-credit balance; reviews skip when any runs out or when remaining budget is less than the expected cost of one review. Estimate via a pilot: set a spend limit, enable a few repos at "Once after PR creation"/"Manual", read the "Average cost" column per repo, multiply by monthly PR count (and pushes per PR for "After every push").
- **Numbers**: Default "Review runs" for a newly added repo is "After every push" (runs the most reviews). Reviews skip once remaining budget < expected cost of one review. No explicit dollar figures, no price-per-1M-token, no percentage savings — costs are per-org and shown as estimated averages in the admin dashboard. Analytics at claude.ai/analytics/code-review (repository-breakdown costs estimated at list price, before discounts/credits).
- **Token-cost implication**: To control Code Review spend, set repos to "Once after PR creation" or "Manual (@claude review)" rather than the default "After every push", lower the review level, and keep PRs small — cost scales with change size, code complexity, and review level. Run a pilot to get your own per-repo average before a wide rollout, and set a monthly Code Review spend limit.
- **Caveats**: Vendor doc; no absolute prices given. Analytics/repository-breakdown cost figures are estimates at list price and can differ from the invoice; only reviews Claude actually posted are counted. For invoice-accurate spend, refer to the Anthropic bill.
