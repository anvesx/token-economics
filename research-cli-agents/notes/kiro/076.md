# 076 — Customize your status line
- **Source**: https://code.claude.com/docs/en/statusline (Anthropic, doc, undated)
- **Claim**: The Claude Code status line is a user-configured shell script fed JSON session data on stdin; it can surface live context-window usage, session cost, cache performance, and rate-limit/spend data at a glance. Useful for monitoring token/cost state while working.
- **Mechanism**: Configure `statusLine` in settings with `type: "command"` and a script path or inline command (e.g. piping JSON through `jq`). The script receives a JSON object on stdin with session fields and prints to stdout (runs locally, consumes no API tokens). Updates are event-driven (new assistant message, `/compact` finish, permission-mode change, vim toggle) plus optional `refreshInterval`. Key cost/token fields: `context_window.used_percentage` / `remaining_percentage` / `context_window_size` / `total_input_tokens` / `total_output_tokens` / `current_usage` (input, output, cache_creation, cache_read); `cost.total_cost_usd` (client-side list-price estimate), `total_duration_ms`, `total_api_duration_ms`, `total_lines_added/removed`; `rate_limits.five_hour` / `seven_day` / `spend_limit` (used_percentage, resets_at, used_usd, limit_usd, period); `prompt_cache` (warm, hit_ratio, requests, misses, cache_write_tokens, miss_recache_tokens, last_miss_cause, miss_causes). `used_percentage` is computed from input tokens only (input + cache_creation + cache_read), excluding output.
- **Numbers**: context_window_size default 200000, or 1000000 for extended-context models. `exceeds_200k_tokens` is a fixed 200k threshold. A miss is counted when a request re-processes >5% and at least 2,000 tokens of cacheable content with no compaction/clearing to explain it. Cache TTL values "5m" or "1h". Debounce 300ms. Example `expires_at`/`resets_at` are Unix epoch seconds. Spend-limit dollar fields refresh ~every 5 minutes, so can lag `used_percentage`. `last_miss_cause` requires v2.1.260+; `prompt_cache`/`spend_limit` require v2.1.251+; dollar spend fields require v2.1.284+ (both CLI and gateway). Output over 10,000 chars from a hook preview behavior noted. No price-per-1M-token figures.
- **Token-cost implication**: Build a status line showing `used_percentage` and `prompt_cache.hit_ratio`/`warm` to watch context fill and cache health in real time, so you can `/compact` or `/clear` before cost spikes and detect cache-busting changes (tools_changed, system_prompt_changed). Track `cost.total_cost_usd` and `rate_limits.spend_limit` to stay within budget. Cache slow git operations in the script (keyed by `session_id`) to avoid lag.
- **Caveats**: `cost.total_cost_usd` and spend figures are client-side estimates at list price (unless a `modelPricing` table is set) and may differ from the actual bill. Many fields are null before the first API response or absent depending on plan/provider/version. `rate_limits` only present for claude.ai Pro/Max/Ultra or behind a gateway with spend limits. Vendor doc; no independent measurement.
- **Topic**: observability
