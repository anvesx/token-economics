# 073 — Model configuration and effort levels
- **Source**: https://code.claude.com/docs/en/model-config (Anthropic, doc, undated)
- **Claim**: Reference doc for configuring which Claude model and which reasoning effort level Claude Code uses, plus context-window sizing, auto-compaction thresholds, fallback chains, and admin allowlists. Effort level is the primary lever for how much the model thinks (and thus token spend) on adaptive-reasoning models.
- **Mechanism**: Models are selected by alias (`opus`, `sonnet`, `haiku`, `fable`, `opusplan`, `default`) or full ID, with precedence: session `/model` > `--model`/`ANTHROPIC_MODEL` > settings `model` > org default > `ANTHROPIC_DEFAULT_MODEL`. `opusplan` uses Opus in plan mode then switches to Sonnet for execution. Effort levels (low/medium/high/xhigh/max) control adaptive reasoning — the model decides per-step whether to think, scaling token use with task complexity. Effort resolves in order: `CLAUDE_CODE_EFFORT_LEVEL` env > in-session pick > `--effort` > settings (per-model `modelSettings` or `effortLevel`) > model default. Context auto-compacts near the window limit; `/autocompact <size>`, `--autocompact`, `autoCompactWindow`, or `CLAUDE_CODE_AUTO_COMPACT_WINDOW` set the threshold (100K–1M, capped at model window). Fallback chains (`--fallback-model`, `fallbackModel`) switch models on overload; capped at 3 after dedup; won't fall back to a smaller context window during compaction. Admins cap spend with `maxEffortLevel`, `availableModels`, `enforceAvailableModels`, per-role effort limits, and org default model.
- **Numbers**: Effort levels: low, medium, high, xhigh, max. Defaults: high on most effort-supporting models; Opus 5.5 / Sonnet 5.5 / Haiku 5.5 default to medium; Opus 4.7 defaults to xhigh. Context window: 200,000 tokens default, 1,000,000 (1M) for extended-context models. 1M-native models auto-compact at ~967K tokens by default. Auto-compact window settable 100K–1M. `ultrathink` can raise one turn to xhigh. Haiku 5.5 costs more per token on prompts longer than 100K tokens; runs 1M context on every plan. 1M context: no premium for tokens beyond 200K on Anthropic API except Haiku 5.5 (>100K). dialogExpiry default 5 minutes. Claim: Opus 5.5 at medium matches or exceeds Opus 5 at high on coding/knowledge-work evals (Anthropic testing). Piped stdin cap elsewhere; here no price-per-1M figures given.
- **Token-cost implication**: Choose effort deliberately — lower effort (low/medium) is faster and cheaper for routine work; reserve high/xhigh/max for debugging, edge cases, security work. On Opus 5.5 start at medium rather than carrying over Opus 5's high. Use `opusplan` to pay Opus rates only for planning and Sonnet rates for execution. Set a smaller auto-compact window to compact earlier (trades context for lower per-request token cost); switch models to smaller/cheaper ones via aliases; cap team spend with `maxEffortLevel` and `availableModels`.
- **Caveats**: Vendor (Anthropic) self-documentation, not independent measurement. The "Opus 5.5 medium ≥ Opus 5 high" claim is Anthropic's own testing. Effort scale is calibrated per model, so the same level name is not comparable across models. Behavior varies heavily by Claude Code version and by provider (Anthropic API vs Bedrock/Google/Microsoft Foundry). No explicit dollar prices per 1M tokens in this doc.
