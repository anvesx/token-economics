# 097 — Codex local config (config.toml)
- **Source**: https://developers.openai.com/codex/local-config (OpenAI, undated)
- **Claim**: Official reference for Codex's config.toml layering — where config lives, how precedence resolves across CLI flags, project, profile, user, cloud-managed, and system layers, and the most commonly changed options.
- **Mechanism**: User config at ~/.codex/config.toml; project overrides via .codex/config.toml (loaded only for trusted projects). Precedence highest→lowest: CLI flags and --config overrides; project config files (root→cwd, closest wins, trusted only); profile files (~/.codex/profile-name.config.toml via --profile); user config; cloud-managed defaults; system config (/etc/codex/config.toml on Unix); built-in defaults. Untrusted projects skip project-scoped .codex/ layers (config, hooks, rules) but still load user/system. Managed machines can enforce requirements.toml constraints (e.g. disallow approval_policy="never" or sandbox_mode="danger-full-access"). Common keys: model, approval_policy ("on-request"), sandbox_mode ("workspace-write"), permission profiles (:read-only, :workspace, :danger-full-access), Windows sandbox ([windows] sandbox, [features] prefer_mxc), web_search mode, model_reasoning_effort, personality="none", tui.keymap, shell_environment_policy filters, log_dir, and the [features] table. Web search defaults to a cached OpenAI-maintained index (reduces prompt-injection exposure); treat web results as untrusted; --yolo/full-access defaults to live results.
- **Numbers**: web_search modes: "cached" (default), "indexed", "live", "disabled". model_reasoning_effort default example "medium". shell_environment_policy ignore_default_excludes defaults true (skips auto-filtering of var names containing KEY/SECRET/TOKEN). [features] defaults shown: apps true, goals true, hooks true, fast_mode true, memories false, multi_agent true, remote_plugin true, shell_snapshot true, shell_tool true, unified_exec true; web_search/web_search_cached/web_search_request deprecated. Example model = "gpt-6.1-sol".
- **Token-cost implication**: Put shared defaults in config.toml and keep per-task profile files to the values that differ (e.g. cheaper model + lower reasoning for routine work); set model_reasoning_effort per layer to avoid paying deep-reasoning tokens on routine tasks; disable unneeded [features] (fewer tool definitions / web search) to trim per-turn tokens; use cached web_search to avoid live fetches.
- **Caveats**: Official doc but undated and is a configuration reference, not a benchmark — it lists keys/precedence, not token savings or prices. Model names (gpt-6.1-sol) are a later-generation snapshot. No per-key cost figures. Some behaviors are managed/enterprise-gated (requirements.toml, Windows MXC).
