# 030 — TwinRouterBench: Fast Static and Live Dynamic Evaluation for Realistic Agentic LLM Routing
- **Source**: https://arxiv.org/abs/2605.18859 (arXiv, 2026-05)
- **Claim**: A step-level LLM-routing benchmark with two tracks (a deterministic static track and a live SWE-bench execution track) that exposes the router-visible prefix before each intermediate LLM call and verifies labels by end-to-end execution; a logistic router trained on the static labels cuts API cost ~53% at matched resolve rate.
- **Mechanism**: Routing is framed per-call: at step i the router sees the full prefix (chat history, tool outputs, shell traces, code diffs) and picks a tier in {low, mid, mid_high, high}, each tier backed by a pool of models. Static labels are built by seeding from a successful strong-model trajectory, then a greedy sequential-locking downgrade search (Algorithm A1) that drops each step to the cheapest tier whose 3-model cascade still passes end-to-end without increasing step count — reducing the naive |T|^N grid to O(|T|·N). Open-ended workloads (mtRAG, QMSum) use a hardened LLM judge; a ~10% manual audit (64 steps) confirms tightness. Static scoring is deterministic arithmetic over four metrics (RowPass, RowExact, TrajPass, CostSave) with four-bucket cache-aware token pricing; no online judge. Dynamic track runs mini-swe-agent on SWE-bench Verified, selecting a concrete model per call, scored by official resolution + realized OpenRouter spend + a flat $0.60 per-unresolved-instance penalty.
- **Numbers**: 970 step-level rows from 520 instances across 5 workloads (SWE-bench, BFCL, mtRAG, QMSum, PinchBench). Tier distribution: 689 low, 62 mid, 49 mid_high, 170 high. Fixed 11-model pool, 4 tiers. High tier 10–50x more expensive than lower three (e.g. high input $5/1M vs low $0.26/1M; high output $25/1M). Dynamic leaderboard = locked 100 instances (18 Astropy, 82 Django). Trained UncommonRoute: 75/100 resolved, $25.66 API cost, $40.66 leaderboard bill — 53.1% API-cost cut vs unrouted Opus ($54.73) at comparable resolve (Opus 74/100), and 6.7x cheaper than rule-based UncommonRoute ($172.56). Static diagnostic: SR-KNN (in-sample UB) Combined 77.89; UncommonRoute rule-based 56.96; ClawRouter 52.76; Opus-always-high Combined 54.38 (CostSave 0 by construction). Opus-4.6 as LLM-router predicts high for only 7/147 verified-high SWE steps and fails all 40 SWE trajectories. Cascade verification recovered 28/33 downgradeable labels vs 15/33 single-model. Median prefix tokens: SWE ~5,300, PinchBench ~10,500, BFCL ~1,600. Cache TTL 5 min (Anthropic default). γ=$0.60 (set above unrouted Opus avg $0.55/instance).
- **Token-cost implication**: Cheapest-sufficient routing must be per-step and prefix-conditioned, not one-model-per-query; a cheap, trainable static label set can produce a router that roughly halves API spend without losing task resolution. Use failure-aware cost accounting (charge, don't credit, cheap calls on failed trajectories) so conservative over-routers aren't falsely rewarded. A frontier model prompted as a router is unreliable and no substitute for execution-verified supervision. Price mid-trajectory model switches in (cache writes at the incoming tier's rate).
- **Caveats**: Corpus small (970 steps / 520 instances), not exhaustive across workloads/domains; labels tied to a fixed 11-model pool, cascade protocol, and price snapshot and would need re-labeling if a cheap-and-capable model appears. Dynamic track covers SWE-bench Verified only; the 100-case list is a locked, non-random subset (Astropy+Django). Greedy downgrade may miss cross-step interaction effects (guarded only by ~10% audit). Seed/sampling variance: one trajectory per sample-arm, no CIs. Static and dynamic scores are never averaged. Authors from Gradient et al.
