# 106 — Mastering Context Compaction in Codex CLI
- **Source**: https://codex.danielvaughan.com/2026/04/16/codex-cli-context-compaction-tuning-long-sessions (Daniel Vaughan, 2026-04)
- **Claim**: Codex CLI uses context compaction to keep long sessions alive by replacing full history with a compressed handoff summary; tuning its config knobs avoids the agent "forgetting" mid-task and avoids costly reread loops.
- **Mechanism**: Two code paths selected by model: local path (compact.rs) calls an LLM to make a plaintext handoff summary (works on any provider); remote path (compact_remote.rs) for OpenAI Codex models calls POST /responses/compact and gets an opaque encrypted blob passed into the next responses.create() call. The local handoff summary has 4 parts: progress/key decisions, constraints/user preferences, remaining TODOs, critical data (file paths, variable names, API endpoints). It replaces all assistant replies and tool outputs but keeps user messages verbatim; if space is still insufficient it falls back to head trimming (chopping earliest messages). Since v0.100.0 a hard 90% clamp applies: effective_limit = min(user_config_limit, context_window × 0.90). Config lives in ~/.codex/config.toml: model_context_window, model_auto_compact_token_limit, tool_output_token_limit, compact_prompt, experimental_compact_prompt_file. Profiles switch behavior per task; /compact triggers manual compaction, /status shows context consumption. Compaction drops all tool outputs, causing re-reads that can cascade into more frequent compaction.
- **Numbers**: 90% clamp → e.g. 250,000 limit on 256k window triggers at 230,400 tokens. Per-model defaults (context window / ~90% threshold): gpt-5.4 1,000,000/~900,000; gpt-5.4-mini 1,000,000/~900,000; gpt-5.3-codex 256,000/~230,400; gpt-5.3-codex-spark 128,000/~115,200; gpt-5.2 legacy 256,000/~230,400 (thresholds derived from the clamp, not published by OpenAI). Default tool_output_token_limit 12,000; example tightened to 8,000. Recent-message preservation across tools: Codex ~20k tokens, Claude Code last 2 user turns, OpenCode last 40k tokens. Layers: Codex 1, Claude Code 3, OpenCode 2. Issue #16812 reread loop driven by 93 KB analysis + 58 KB plan + 610 KB OpenAPI spec. Sessions up to 7 hours. Medium tasks recommended: model_auto_compact_token_limit 200000, tool_output_token_limit 10000. Marathon: 1,000,000 window, limit 750,000. CI: limit 80000, tool_output 6000. SDK compact_threshold example 100000.
- **Token-cost implication**: Set tool_output_token_limit aggressively, put durable facts in AGENTS.md (re-read after compaction) rather than conversation history, manually /compact at phase breakpoints before large file reads, and split unrelated tasks into separate sessions to avoid reread cascades that trigger premature (billed) compaction LLM calls. Every Codex compaction always incurs an LLM/API call, unlike Claude Code which defers it.
- **Caveats**: Author is an independent blogger (book author), not OpenAI; exact default thresholds are explicitly not published by OpenAI and are derived from the clamp formula. Compaction is irreversible; multiple compactions degrade accuracy (OpenAI warning). The 90% clamp cannot be overridden. No selective preservation (issue #16839). experimental_compact_prompt_file may change. Cross-tool comparison sourced from a third-party gist/blog.
