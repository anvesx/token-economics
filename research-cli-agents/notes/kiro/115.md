# 115 — Codex CLI Usage & Rate Limits: 5-Hour vs Weekly Windows
- **Source**: https://inventivehq.com/blog/codex-cli-usage-rate-limits (Inventive HQ, 2026-05-26)
- **Claim**: Codex CLI enforces two stacked usage limits (rolling 5-hour + cumulative weekly), measured in credits not messages and shared across CLI/IDE/cloud; the article explains how to check status and what levers exist at the cap.
- **Mechanism**: A rolling 5-hour window (resets continuously 5h after usage) and a 7-day weekly window run simultaneously; either can trip independently. Limits are credit/token-based — longer reasoning burns more budget, so message count can't predict lockout. The 5-hour pool is shared across local CLI, IDE extension, and delegated cloud tasks. Check with /status inside an active session (shows % remaining for both windows, model, plan); also Codex Settings > Usage and platform.openai.com/usage (lags minutes, no live 5-hour position). At the cap Codex blocks new turns but can usually finish the active turn. Levers in order of effort: (1) switch to mini model; (2) buy credits (Settings > Usage > Credits); (3) enable Auto Top-up; (4) save/spend a rate-limit reset; (5) use an API key (no rolling cap, pure pay-per-token) or point Codex base URL at a local-first gateway that serves from own machines and fails over to cloud.
- **Numbers**: 5-hour message ranges (top / mid / mini): Plus ~15–80 / ~20–100 / ~60–350; Pro 5x ~80–400 / ~100–500 / ~300–1,750; Pro 20x ~300–1,600 / ~400–2,000 / ~1,200–7,000. Pro from $100/mo, 20x tier commonly $200/mo. Credit rate-card per 1M tokens (input / output): top ~125 / ~750; mid ~62.5 / ~375; mini ~18.75 / ~113. Output costs ~6–10x input; cached input ~10% of uncached. Mini input ~3.3x cheaper than mid and ~6.7x cheaper than top. Pro 2x promo capacity boost expired 31 May 2026 (reverted $100 Pro to standard 5x). Saved rate-limit resets added 12 June 2026: one free reset for Go/Plus/Pro/Business, expire 30 days after credit. User reports (not official): Plus/Business hit weekly caps after ~1.5–2 days heavy coding (~2M tokens); Pro lasts longer. Example /status: "5h 96%, Weekly 94%" (percentages are remaining).
- **Token-cost implication**: Default routine edits/tests/boilerplate to the mini model and reserve the top model for hard reasoning; keep prompts tight and reuse context to exploit the ~10% cached-input rate and avoid output-token blowup; monitor both windows with /status but cross-check the dashboard; for heavy/uncapped workloads move to API-key billing or a local-first gateway.
- **Caveats**: Independent blog; message ranges are OpenAI's published approximations ("rough planning numbers, not contracts"). Several figures are explicitly user-reported, not official (weekly depletion rates, Sunday resets, mini cost multipliers). Known bug class where /status, warning banner, and error state disagree on remaining quota. Whether a saved reset clears the weekly window or only the 5-hour is unspecified by OpenAI (author assumes 5-hour only). Products fast-moving; verify against OpenAI pricing page.
