# 002 — Claude Code OpenTelemetry: Track Cost and Tool Use
- **Source**: https://dev.to/nixonperinchery/claude-code-opentelemetry-track-cost-and-tool-use-c83 (dev.to, 2026-10)
- **Claim**: Claude Code can export usage metrics, events, and (beta) traces via OpenTelemetry once `CLAUDE_CODE_ENABLE_TELEMETRY=1` and an exporter are set, giving a team one place to see tokens, estimated cost, and tool behavior attributed by model/subagent/skill/plugin/MCP server. The emitted dollar figures are local list-price estimates, not a bill.
- **Mechanism**: Set environment variables before launch: `CLAUDE_CODE_ENABLE_TELEMETRY=1` (required), `OTEL_METRICS_EXPORTER` (otlp/prometheus/console/none), `OTEL_LOGS_EXPORTER`, `OTEL_EXPORTER_OTLP_PROTOCOL` (grpc/http/json/http/protobuf — no default), `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_HEADERS`. Metrics include session.count, lines_of_code.count, pull_request.count, commit.count, cost.usage (est USD per API request), token.usage (input/output/cacheRead/cacheCreation), code_edit_tool.decision, active_time.total (user vs cli seconds). Cost/token metrics also carry model, query_source (main/subagent/auxiliary), speed, effort, agent.name, skill.name, plugin.name, mcp_server.name, mcp_tool.name. Events (logs exporter, `claude_code.` prefix) include api_request (model, cost_usd, duration_ms, tokens, request_id), api_error, tool_result, tool_decision, user_prompt/assistant_response; `prompt.id` links events from one prompt and you sort by `event.timestamp` (event.sequence is per-process). Traces (beta, `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1`) span claude_code.interaction → llm_request → tool, with a blocked_on_user span measuring permission-wait time. Team rollout goes in the managed settings file (repo-level `.claude/settings.json` OTEL_* exporter vars are ignored for safety).
- **Numbers**: Metrics export interval default 60,000 ms (OTEL_METRIC_EXPORT_INTERVAL); logs export every 5 s (OTEL_LOGS_EXPORT_INTERVAL). Content attributes truncated at 60 KB default (CLAUDE_CODE_OTEL_CONTENT_MAX_LENGTH). Prometheus endpoint http://localhost:9464/metrics; default OTLP endpoint http://localhost:4317. Version gates: locking exporter selectors needs v2.1.223+; OTEL_METRICS_INCLUDE_REPOSITORY added v2.1.269+; modelPricing managed setting v2.1.242+. Metric cardinality defaults: INCLUDE_SESSION_ID true, INCLUDE_ACCOUNT_UUID true, INCLUDE_RESOURCE_ATTRIBUTES true, INCLUDE_VERSION false, INCLUDE_ENTRYPOINT false, INCLUDE_REPOSITORY false. Metric temporality defaults to delta.
- **Token-cost implication**: Export telemetry (not per-machine `/usage`) to attribute spend by model, subagent, skill, and MCP server and find what drives cost; a high cacheCreation share next to low cacheRead means sessions keep rebuilding context (e.g., after idle gaps) and should be restructured. Use cost.usage split by model and effort to A/B a change (moving a task type to a smaller model / lower effort) with data rather than by feeling. Watch MCP servers/hooks that run per tool call — they can silently multiply token spend. Drop session ID from metrics to control backend cardinality cost.
- **Caveats**: Vendor/blog documentation (dev.to post by the author of "Atlas," a Claude-Code-based product promoted at the end — promotional). Dollar figures are local estimates at list price (or configured rates), not billing numbers; on Pro/Max plans usage is included in the subscription so cost figures are for comparison only; the Console usage page is authoritative for API users. Contracted/negotiated rates are not reflected unless an admin sets modelPricing. Content capture (prompts, assistant responses, tool details, raw API bodies) is off by default and each is a separate opt-in; raw API bodies are sensitive. OTEL_* vars are not passed to subprocesses (Bash tool, hooks, MCP servers, language servers). Traces are beta; some features need org allowlisting. No independent benchmarking in the piece.
