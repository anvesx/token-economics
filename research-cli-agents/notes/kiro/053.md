# 053 — Inference Economics of Enterprise Coding Agents: A Case Study of Cloud vs. On-Premise LLMs
- **Source**: https://arxiv.org/abs/2607.13080 (arXiv, 2026-07)
- **Claim**: A single-developer, two-period (2×28-day) production case study finds that prompt caching makes a frontier API (Claude Opus 4.7/4.8 via Claude Code) cheaper per processed token than a self-hosted NVFP4-quantized GLM-5.1/5.2 cluster, while the local configuration carries a much higher defect-repair burden; which deployment wins on true TCO depends entirely on GPU allocation regime.
- **Mechanism**: Period A ran Claude Code against the hosted Claude API; Period B ran Opencode against on-prem vLLM serving NVFP4-quantized GLM on a 4×B200 (one GB200 NVL72) tray. Cost/quality measured by triangulating deduplicated LLM telemetry (Langfuse/ClickHouse for A, vLLM Prometheus counters for B) with Git repository mining. Code quality = Fix Commit Ratio (FCR = fix commits / total commits, regex /(fix|bug|issue|patch|correct)/i). Commits difficulty-tiered by change footprint (High ≥3 packages/≥5 files/>200 net lines; Medium 2 pkgs/2–4 files; Low single-file). Defect-repair association computed as Mantel–Haenszel odds ratio stratified by tier. Economic model: TC = M×(Ccompute + Cops + Titer×Rdev), with a symmetric 15-min per-fix review time so labor differences come only from counted fix-commit volume. A hybrid routing gateway evaluated by offline counterfactual replay over 613 pooled commits with per-tier fix rates, plus a two-stage bootstrap (10,000 resamples) for CIs.
- **Numbers**:
  - Prompt cache hit rate: 99.3% (Claude/Period A), 86.4% (GLM/Period B vLLM prefix cache).
  - Caching cut realized API cost by 88.6%; effective $0.57/M processed tokens (vs nominal Opus 4.8 $5.00 input / $25.00 output per M; cache write $6.25/M, cache read $0.50/M).
  - On-prem unit cost: $2.83/M (shared allocation), $11.87/M (dedicated reservation).
  - Realized API bill total: $8,785.21 (Input $4.90, Cache Write $675.38, Cache Read $7,601.01, Output $503.92). Without caching the same volume = $77,059.
  - API processed 16.9× more tokens than local. Period A total tokens 15,331,217,051 (≈480k prompt tokens/request, 99.3% cache reads); output 20.2M (A) vs 5.06M (B), a 4.0× difference. Period B total tokens 905,590,759 (778M of 900M as cache hits).
  - GPU cost basis: $16.00/hour per 4×B200 tray ($4.00/GPU-hour; June–July 2026 market $3.70–$5.90/B200-hour). Scenario I (dedicated, 672h) = $10,752.00; Scenario II (shared, 160h seat) = $2,560.00.
  - FCR: 45.93% (A, 113/246 commits) vs 74.93% (B, 275/367 commits). Effective Productivity Ratio Enet = 1−FCR: 54.07% (A) vs 25.07% (B).
  - Mantel–Haenszel OR = 3.61 (per-tier ORs: High 4.88 [46.5% vs 15.1%], Medium 2.63 [80.6% vs 61.2%], Low 3.81 [86.9% vs 63.4%]); unadjusted OR 3.52 [2.49, 4.96]; aggregate χ²(1)=53.30, p<0.0001, ϕ=0.295. Daily-FCR difference p=0.0002, Cliff's Δ=−0.66.
  - Defect taxonomy (A vs B): Syntax/Type 1.8% vs 7.3%; API/Package misuse 2.7% (3) vs 10.5% (29, ~10×); Logical 54.0% (61) vs 71.3% (196); Test/CI 41.6% (47) vs 10.9% (30).
  - Per-language FCR: TypeScript 41.7%→63.3%; Python 48.4%→86.8% (deployment effect dwarfs language effect).
  - Throughput: Opus 4.8/4.7 = 66.0/56.6 tok/s; hosted GLM-5.2 = 214.9 tok/s (GLM-5.1 76.4); local NVFP4 GLM-5.2 ≈185 tok/s (≈2.8× Opus 4.8). AA Intelligence Index: Opus 4.8=56, 4.7=54, GLM-5.2=51, GLM-5.1=40. SWE-bench Pro: 69.2% / 64.3% / 62.1% / 58.4%.
  - Model footprint: GLM-5.2 = 753B total / 40B active MoE; NVFP4 weights ≈465 GB (4.5 bits/param) on ~750 GB HBM tray; BF16 would be ~1.5 TB.
  - True TCO: A = $9,773.96 (compute $8,785 + labor $988.75, 28.25h). B shared = $5,859.25 (tray $2,560 + ops $893 + labor $2,406.25, 68.75h) = 40.1% saving; B dedicated = $14,051.25 = 43.8% more than API. Cops breakdown: power ≈$813 (6.0 kW, 672h, NT$4.3/kWh=$0.134/kWh, PUE 1.5), MLOps ≈$30/dev, facilities $50/dev.
  - Wage Rdev = $35/hr (NT$1,120); 32 NTD/USD. 100-dev extrapolation: ~$879,000/mo pure API vs ~$256,000/mo shared on-prem.
  - Routing replay (613 commits): Pure API TCO $11,419 (FCR 49.1%); Pure Local $7,388 (35.3% saving, FCR 73.4%); High→Claude $8,412 (26.3% saving, FCR 64.6%); High+Med→Claude $9,890 (13.4% saving, FCR 57.9%).
  - Sensitivity sweep: wage $27–45/hr, GPU $3–6/GPU-hr, review 10–25 min; shared-allocation saving 9%–56%; shared saving survives attribution up to ≈405 of 672 tray-hours; ~45% committed-use API discount would equalize shared TCO.
  - Workload indicators (A vs B): debugging-spiral share 35.0%→69.8% (2.0×); longest repair run 18→58 (3.2×); median inter-commit interval 5.9→12.7 min (2.2×); daily active span 6.6→12.4 h; rework multiplicity 1.61→2.32.
- **Token-cost implication**: In cache-heavy multi-turn agentic workflows, measure realized cost (cache-read-dominated effective $/M), not nominal price-sheet rates — prompt caching can invert the cloud-vs-on-prem per-token comparison (up-to-90% input discount, 88.6% realized saving here). Budget by total realized spend and TCO including differential defect-repair labor, not raw tokens or LOC. On-prem only wins when the GPU tray is shared/highly utilized; dedicated reservation of an under-utilized tray is dominated. A quantized open-weights model's larger benchmark-gap compounds into a far larger end-to-end defect/rework cost, so route highest-stakes (High-difficulty) tasks to the frontier model.
- **Caveats**: Single developer, single production monorepo, non-randomized, two contiguous periods (not a controlled between-subjects experiment); days/commits are autocorrelated, so p-values/CIs do not license population inference. The gap is the joint effect of a deployable bundle (base model + NVFP4 quantization + vLLM serving + agent harness Claude Code vs Opencode + fixed period order) and cannot be attributed to "the model" alone; no FP16/FP8 GLM baseline, so quantization degradation is not separated from intrinsic capability gap. Periods differ in task-difficulty mix (A harder, 35.0% vs 23.4% High) — but that imbalance is conservative (harder period had lower FCR). Fix classification by deterministic keyword rules, manually reviewed by a non-blind first author (blind second rater recommended). Per-developer cost attribution is a billing convention, not a measurement; sessions ran unattended. Period A Test/CI repair is partly infrastructure churn unrelated to model output, so raw FCR likely understates the model-attributable gap. Wall-clock completion time not instrumented (cadence is an upper-bound proxy). Routing replay assumes per-tier fix rates are transportable across periods — a first-order projection, not a deployed-system measurement. Claude bill uses public list rates only.
