# 026 — Prompt-Induced Waste in Coding Agents: Reasoning, Effort, Harness Design, and End-to-End Cost
- **Source**: https://arxiv.org/abs/2608.01347 (arXiv, 2026-08)
- **Claim**: Coding-agent efficiency can't be judged by token count or model price alone; prompt semantics, inference effort, and harness policy interact to determine the agent trajectory, whose terminal efficiency metric is cost per successful task. Prompt wording changes reasoning/verification without changing the task, extra effort sometimes helps and sometimes just adds cost, and an intervention's value flips when the harness changes.
- **Mechanism**: Preregistered, paired, task-clustered-bootstrap benchmark. 6 open-weight ≥500B reasoning models (via Together AI) + Claude Sonnet 5 on 24 deterministic coding tasks (visible + hidden tests) under two production harnesses: PI.DEV (direct OpenAI chat-completions) and Claude Code (Anthropic Messages via a pinned LiteLLM gateway). 18 frozen prompt variants manipulate only the user instruction (9 semantically-controlled preserving objective/criteria/test verbatim, SHA-256-verified; plus stress variants that break equivalence). A condition-blind judge annotated reasoning traces under a frozen rubric (mechanisms: unused branches, redundant verification, unsupported assumptions, etc.) with mandatory evidence quotes. Separate SWE-bench hard-task campaign varies effort level. Post-registration DeepSeek Harness (dsh) extension holds Sonnet 5/tasks/prompts fixed, varying only harness. Cost model: trajectory τ induces billed cost C(τ)=Σ(pU·Uk+pR·Rk+pW·Wk+pO·Ok)+Ctool; terminal metric CPS = E[cost]/Pr(success); log-CPS expansion with pairwise interaction terms (H×E, H×P, T×E, M×E). Proposes a state-conditioned adaptive controller (small action set: effort/prompt/tool/context/verification/stop) minimizing expected remaining cost under a success non-inferiority floor.
- **Numbers**: 4,644 valid runs + 2,801 condition-blind trace annotations (core program); SWE-bench campaign 150 paired model-task-effort cells; dsh extension 75 valid runs (5 tasks × 5 arms × 3 reps). "Multiple approaches" prompt: +2.4-7.4× reasoning tokens across all 6 open models at comparable success (holdout-replicated); adds ~3.5 candidate strategies, ~3 discarded, exactly +1 implemented. Deep thinking: 1.6-2.2× reasoning (2.2× text, zero new functional units). Certainty wording: 1.3-1.9×, +1.75 post-success tool calls (6/6 models), +4s latency, worst case re-ran green suite 6×. Misleading hints: 4.2× pre-edit deliberation, 2.61× reasoning, unsupported assumptions ρ=−0.19 with success. Branching: 878 runs / 225 blocks, no credible success benefit (96.5% baseline vs 95.2% branching; easy cells dropped 98.8%→96.4%, scope violations ~3×). Redundant verification cost by level: 1.00× / 1.48× / 2.36× / 18.25× median (level 3+ = 18× clean, 2.5× tool calls, 3× wall-clock, 6→15 calls). Unused branch: ~1.9× cost, tool calls 7→8. Harness gap: Claude Code transmits 12-15× larger fixed prefix (15,983-20,330 vs 1,147-1,642 tokens; ~6.7KB system prompt + 24 vs 4 tool schemas), 2-7× more turns, 5-30× higher cost/success (e.g. Nemotron ~18×); ~52% of Claude Code calls are test executions vs 22% PI.DEV. dsh extension (Sonnet 5): baseline $0.2753/run; effort arm −74.7% ($0.0696), full −82.2% ($0.0490) — vs the same controller's effort arm reducing cost only ~19% (full ~27%) under Claude Code. Caching reduces ~61% of would-be bill (billed ≈39% of no-cache). Tool-induced model cost 4-12% of run. Judge agreement: ±1 on 84.9% of fields, κ=0.44 same-model / 0.28 cross-model (0.55-0.68 on critical fields).
- **Token-cost implication**: Measure cost-per-successful-task, not tokens, and log the system variables (prompt variant, effort, harness/version, fixed-prefix size, tool-schema surface, turns, tool calls by type, cache writes/reads, compaction, retries, latency, intervention-activation evidence) — a token-only report can't tell a real saving from early failure, a cache-price effect, or work shifted to another channel. Avoid "multiple approaches," "max certainty," and unverified architectural hints unless genuinely needed; use bounded-efficiency wording (scope + smallest-sufficient-change + stop rule) — it's neutral-or-better and cut one model's reasoning to 0.48× — but keep an explicit "inspect repo evidence when spec is ambiguous" clause (stop-early framing caused 3/5 hidden-test failures on an ambiguous spec). Harness/gateway design is the single largest cost factor; a bloated fixed prefix + verification-heavy tool policy + extra turns dominate, and the value of effort control is conditional on the harness default (same control = 19% vs 75% savings).
- **Caveats**: Preregistered academic benchmark (PointFive). Visible reasoning traces may be unfaithful/incomplete (cites Baherwani et al.); semantic labels describe observable text, not hidden cognition. Claude Sonnet 5 excluded from all trace-level claims (empty thinking blocks, reasoning billed in output). Tasks are small (≤4 files) with high success ceilings — branch-waste's token-borne character may weaken on repo-scale tasks; findings may not transfer to long-horizon production agents. Exact per-turn cost attribution impossible (tool-induced cost is a 4-12% bounded estimate). dsh extension: one closed model, 5 fixtures all solved (demonstrates over-provisioned effort, not optimal hard-task policy). Effect sizes are from the specific controlled regimes, not SWE-bench; no extrapolation to production without a workload model. Adaptive controller is a design proposal, not evaluated.
