# 023 — How Do AI Agents Spend Your Money? Analyzing and Predicting Token Consumption in Agentic Coding Tasks
- **Source**: https://arxiv.org/abs/2604.22750 (arXiv, 2026-04)
- **Claim**: First systematic study of token consumption in agentic coding tasks: agentic coding is orders of magnitude more expensive than chat/reasoning (driven by *input* tokens, dominated by cache reads), usage is highly variable and stochastic, more tokens do not yield higher accuracy, models differ substantially in token efficiency, human-rated difficulty weakly predicts cost, and frontier models fail to predict their own token usage (systematically underestimating).
- **Mechanism**: Collected OpenHands agent trajectories on SWE-bench Verified (500 problems, 4 independent runs each) across 8 frontier LLMs (Claude Sonnet 3.7/4/4.5, GPT-5, GPT-5.2, Qwen3-Coder-480B, Kimi-K2, Gemini-3-Pro). Full conversation history carried forward unchanged every round, so context (hence input tokens) compounds. Parsed structured JSON to extract per-type token cost, monetary cost, action types. Phase model (Setup/Explore/Fix/Validate/Closeout) and round-level cost decomposition into 4 separately-priced categories (non-cached input, output, cache creation @5-min write rate, cache read). Prediction task: the same coding agent is repurposed as a self-predictor — it explores the repo with full tools but outputs a JSON token estimate (phase breakdown + confidence) instead of fixing. Evaluated with Pearson r; overhead = prediction cost / task cost.
- **Numbers**: Agentic coding consumes ~1000× more tokens than code reasoning/chat (specifically ~3500× a single-round reasoning task, ~1200× a multi-round chat task). Input/output ratio 153.85 for agentic vs 1.33/0.16 for the others. Agentic avg 4.17M tokens, $1.857/task vs $0.016 / $0.023. Same-task runs differ up to 30× in total tokens. Most expensive problem ~7M more tokens than cheapest; most expensive run ~2× the cheapest on the same problem. Kimi-K2 and Claude Sonnet-4.5 consume on avg >1.5M more tokens than GPT-5. Shared success n=230, shared failure n=100; on failure Kimi-K2 rises ~2M tokens vs GPT-5/5.2 <0.5M. Human difficulty vs cost: Kendall τb=0.32 (95% CI [0.25,0.38]); 6.7% of "<15 min" tasks exceed avg ">1 hr" cost, 11.1% of ">1 hr" below avg "<15 min". Phase round shares: Setup 9.98%, Explore 30.37%, Fix 33.53%, Validate 16.59%, Closeout 9.53%. Output tokens priced ~80× higher than cache reads, yet cache reads dominate cost by volume. Higher-cost models do ~50% repeated file actions. Self-prediction Pearson r up to 0.39 (Sonnet-4.5 output), Kimi-K2 best input r=0.38; overhead ranges from <6% (GPT-5.2) to >2× task cost (Sonnet 3.7/4); Sonnet-4.5 r=0.32× task cost. GPT-5 implicit cache pricing: input $1.25/1M, cached input $0.125/1M, output $10.00/1M.
- **Token-cost implication**: Input-context accumulation — not output generation — is the cost driver in agentic coding, and cache reads dominate the bill despite being cheapest per token, so aggressive context management and caching matter most. Don't equate more tokens with better results: accuracy peaks at intermediate cost and high cost often signals unproductive repeated file views/edits. Pick models for token efficiency (GPT-5/5.2 strong accuracy at low cost; Kimi-K2 worst). Don't trust human difficulty labels or model self-estimates for budgeting; consumption-based pricing stays the practical option, but coarse self-prediction can power early budget alerts / request-approval before expensive runs.
- **Caveats**: Academic study (University of Michigan/Stanford/UT Austin et al.). Only 8 models, one agent framework (OpenHands), one benchmark (SWE-bench Verified); trajectory collection is expensive, limiting scope. Phase/round cost case study uses only Claude Sonnet-4.5. Self-prediction results noisy at instance level; underestimation persists even without in-context example (correlations degrade further). Trace-based; authors note qualitative patterns need validation on wider architectures.
