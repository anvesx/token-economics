# 020 — MCP Tool Overload: Why More Tools Make Your Agent Worse
- **Source**: https://dev.to/thedailyagent/mcp-tool-overload-why-more-tools-make-your-agent-worse-5a49 (dev.to, 2026-03)
- **Claim**: Loading many MCP tool definitions into an agent's context window burns a large share of the token budget and degrades tool-selection accuracy; a small focused toolset outperforms a large one on accuracy, latency, cost, and reliability.
- **Mechanism**: Every MCP tool definition (name, description, JSON schema) is read by the LLM before it can choose a tool, consuming tokens up front. Degradation comes via three routes: attention dilution ("lost in the middle"), tool collision (semantically similar tools blur under load), and prompt-budget starvation (tool schemas crowd out the system prompt). Four fixes: (1) dynamic tool loading — a cheap classifier picks which tool groups to load per task; (2) tighter tool descriptions — cut to interface only (params/types/hard constraints); (3) tool namespacing (e.g. `github__create_issue`) so the model skips whole clusters; (4) task-specific sub-agents with minimal toolsets coordinated by a tool-less orchestrator. An audit function uses tiktoken (cl100k_base) to count per-tool token cost and flag if tools exceed ~20% of the budget.
- **Numbers**: GitHub official MCP ~42,000 tokens; Slack MCP ~8,000; Notion ~6,500; Postgres ~3,200; Linear ~5,800. Stacking 4–5 servers = 60,000+ tokens. Frontier models cap 128K–200K tokens, so tools can take 30–50% of budget. Benchmarked tool-selection accuracy: ~95% with a focused ~4-tool toolset (~1,200 tokens) vs ~71% with full GitHub MCP (~46 tools, ~42,000 tokens) — a 24-point drop from context bloat alone. create_issue description example trimmed from 340 tokens to 47 tokens. Dynamic loading "pays for itself within 2-3 turns." Threshold: >20% of context budget = bloat problem; author observes many agents at 40–60% before the first message.
- **Token-cost implication**: Don't load all MCP tools at startup. Scope tools to the task (dynamic loading), trim descriptions to the interface, namespace tools, and decompose into focused sub-agents instead of one agent with all integrations. Audit tool token cost regularly and keep tools well under 20% of context.
- **Caveats**: Blog post with a self-run benchmark; "representative task set" not fully specified, accuracy figures (~95% / ~71%) are approximate and author-measured with no released methodology or statistical treatment. Uses a single model (claude-3-5-sonnet-20241022) in the sample code. Ends with a product pitch (Nebula), so promotional bias possible.
