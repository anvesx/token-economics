# 041 — Claude Code vs Aider: Terminal Agent Benchmarks on Real 500k-LOC Codebases
- **Source**: https://dev.to/grfdsasdvef/claude-code-vs-aider-terminal-agent-benchmarks-on-real-500k-loc-codebases-2d6c (dev.to, 2026-11)
- **Claim**: Across 120 scripted tasks on three ~500k-LOC proprietary codebases, Claude Code wins cross-file/autonomous success (86.7% vs 71.4%) but burns ~2.4× more tokens and runs slower, while Aider is cheaper per PR, token-disciplined, git-native, and the only option supporting local/on-prem models — the gap traces to how each builds its repo map (on-demand grep-and-chase vs a precomputed tree-sitter + PageRank repo-map).
- **Mechanism**: Claude Code is a closed agentic loop: no precomputed repo knowledge, searches on demand (glob/grep via ripgrep, paged Read in ~2k-line windows, string-replace Edit with validation, persistent Bash shell), feeding a ~200k-token context window that auto-compacts at ~92% utilization (summarization pass costs its own tokens; can re-read files or edit against stale summaries). Aider is map-first: a tree-sitter pass extracts symbols from every tracked file, builds a graph, ranks with a PageRank variant, and emits a repo-map capped at a token budget (default 1k, tune to 4k on big repos), shipped with every prompt; LLM emits search/replace blocks verified against current file content (one re-ask then hard stop), then auto git-commits. Both are single-threaded orchestrators (no parallel tool calls); wall-clock dominated by sequential API round-trips. Failure mode for Aider at scale: a 1k-token map surfaces only top ~120 ranked symbols, so peripheral code (migration scripts, rare factories, low-PageRank call sites) is omitted and tasks fail.
- **Numbers**:
  - Decision matrix: cross-file refactor success 86.7% (CC) vs 71.4% (Aider), +15.3 pts; median tokens/task 148k vs 61k (2.4× cheaper); median wall-clock p50 4m12s vs 2m38s (1.6× faster); cold context-mapping latency 3.1s vs 0.4s (7.75×); p99 task latency 18m40s vs 6m05s (3×); unsupervised drift (edits outside scope) 2.1% vs 5.8% of diffs (2.7× cleaner, CC); effective cost per merged PR $3.90 vs $1.85 (2.1×); ratings 4.8/5 vs 4.5/5.
  - `--map-tokens 4096` raised Aider suite success 71.4% → 79.2%.
  - Round-trip latency: CC ~2.8s (thinking-enabled) vs Aider ~1.1s (non-reasoning); avg 14 vs 6 round-trips/task.
  - Task-suite (500k-LOC TS monorepo; CC vs Aider): single-file fix 95.0%/92.5% (24k/11k tokens, 1m40s/0m55s); cross-file rename+type 88.0%/62.5% (190k/78k, 6m30s/3m10s); test gen ≥85% cov 91.7%/83.3% (132k/55k, 4m55s/2m20s); dependency major upgrade 75.0%/47.5% (240k/96k, 9m20s/4m45s); bug localization from stack trace 90.0%/71.7% (88k/34k, 3m05s/1m45s).
  - Repo-scale: cold start 3.1s (CC, no index) vs Aider 0.4s map + 41s full tree-sitter parse (cached), ~11ms incremental; idle RAM 310 MB vs 190 MB; Aider map-rebuild RAM peak 1.2 GB; disk 85 MB (CC transcripts) vs 15 MB (Aider cache).
  - Java codebase: 9% of tasks hit two compactions, each adding ~90s and ~40k tokens. Dependency-upgrade diffs failed compile 9 of 40 runs (Aider).
  - Cost tiers (blended Sonnet ~$3/$15 per M in/out): Startup 3 devs/~150 tasks/mo $100–140/mo (CC Max 5× seat $100) vs Aider $95/mo + $20–40 infra (~$18/mo if routed to DeepSeek-class); Scale-up 15 devs/~2,000 tasks/mo $2,500/mo vs $2,500/mo + $150 LiteLLM proxy; Enterprise 120 devs $25,000/mo vs ~$25,000/mo equiv + 2× vLLM nodes (2× H100 ~$4,500/mo).
  - Hidden-cost examples: a linting MCP server added 8k tokens/call = 31% bill increase; a proxy stripping the format spec burned $4.20 in 11 min retrying malformed diffs. CC rate limits: bursty 40k+ token requests hit org ITPM/TPM caps; Aider requests 2–6k tokens.
  - Egress ~2–6 GB/mo per heavy team (negligible).
- **Token-cost implication**: Choose the architecture to your bottleneck: pay-per-outcome autonomous monorepo work favors Claude Code's grep-and-chase (higher success, worth the token burn when ~15 pts of success ≈ 300 fewer failed tasks/mo at 2,000 tasks); token discipline, model portability, and on-prem/local inference favor Aider — and Aider needs `--map-tokens 4096` at 500k LOC. Keep Claude Code tasks under ~100k tokens (or use SDK headless `--continue` checkpointing) to avoid auto-compact re-reads that bill twice. Audit per-call MCP/hook token overhead (it hides as a flattened usage graph). Mixed routing (cheap model for triage, frontier for hard diffs; LiteLLM proxy for key rotation/cost caps) is the dominant 2026 team pattern.
- **Caveats**: Self-run vendor-style blog benchmark (dev.to, "Snowden SAY Lab") with affiliate links to both tools — not independent/peer-reviewed; self-reported methodology (120 tasks, 3 runs, medians, single Dell Threadripper harness, provider billing logs + human diff review). Specific tool versions (CC v2.x, Aider v0.8x Sonnet backend) and 2026 pricing; results tied to those. Proprietary codebases not disclosed/reproducible. Cost tiers are blended estimates. Drift/latency figures are the author's instrumentation only.
