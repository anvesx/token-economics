# 045 — Agent Retrieval Bench: Evaluating Repository Context Retrieval for Coding Agents
- **Source**: https://arxiv.org/abs/2607.24882 (arXiv, 2026-07)
- **Claim**: Introduces a file-level retrieval benchmark that isolates the "find the right repository files" step that precedes patch generation in coding agents, showing no single retrieval family dominates across workflow signals and that context acquisition is a measurable upstream failure surface and cost center.
- **Mechanism**: 427 samples across 25 repos; each sample = (repo, base_commit, workflow-derived query, gold files). Four positive tasks (code2test, comment2context, trace2code, edit2ripple) plus a selective no-gold subset (50 natural + 32 counterfactual wrong-repo controls). Queries are sanitized to remove fatal shortcuts (gold paths, raw diffs, fix-commit hashes, generated review artifacts). Retrievers (BM25, path-aware lexical, vectorless RepoMap, open-source embeddings like Qwen3-Embedding-4B/8B, Jina, pplx, Nomic) rank files; scored with Recall@5/10/20, MRR, and Budgeted Context Yield (BCY@B) which packs ranked files greedily under a token budget using a deterministic regex tokenizer. Logged agent trajectories (OpenAI strict, Codex CLI GPT-5.4/5.5) and a 45-sample closed-tool seed-intervention pilot measure context-acquisition cost.
- **Numbers**: 427 samples (345 positive: 106 code2test, 80 comment2context, 101 trace2code, 58 edit2ripple; 50 natural no-gold; 32 counterfactual). Corpus manifest: 308 base-commit snapshots, 391,932 files, 7,922,369 chunks; released samples use 271 snapshots. 81.99% duplicate chunk fraction (1,118,431 unique vs 5,092,534 duplicate texts over 287-sample corpus). Leaderboard (345 positive): Qwen3-4B best weighted MRR 0.2379; Qwen3-8B best Recall@20 0.7029; RepoMap best BCY@8k 0.3788. Gin = 88/345 samples (25.5%); 4 largest repos = 58.8%. Interactive agents never touch any gold file on 35.2% of OpenAI samples, 27.2–29.3% of Codex. OpenAI reads 3.2 files/sample; Codex ~6.2–6.5. Median first hit: step 2 (OpenAI), step 3 (Codex). RRF hybrid (Qwen3-8B+RepoMap) raises overall MRR 0.2296→0.2713, Recall@20 0.7070→0.7331; trace2code Recall@20 0.8795. Seed pilot: oracle gold seed raises final File F1 by 0.3115 and rescues 100% of no-seed misses; RRF seed +0.0744 F1; random non-gold +0.0215. Median gold file 515 lines; 51.8% >500 lines, 24.1% >1000 lines, max 10,218; median labeled span evidence 27 lines (4.7% of file). trace2code: RepoMap MRR 0.2742 best, Qwen3-4B only 0.0827.
- **Token-cost implication**: Coding-agent context retrieval should be hybrid (semantic embeddings + lexical/path + repository structure + source-test relations) and task-aware; a better initial ranked context seeds the agent closer to gold and reduces exploration tool calls/tokens, but interaction is still needed where static retrieval misses. File-level hits overstate within-file localization (median gold evidence is 4.7% of the file), so budget for additional within-file search. Raw top retrieval scores are not reliable abstention signals, so do not rely on them to decide "no useful local context."
- **Caveats**: Diagnostic, not web-scale; file-level only (not span or patch localization); does not measure end-to-end patch success and does not establish that a retrieval miss causes repair failure. Repository-imbalanced (Gin-heavy). Seed pilot is single-run per sample-arm with no fixed temperature/seed, so differences between retrieval arms are not statistically resolved. Embedding baselines are prompt-free zero-shot (not model-card-optimized); pplx row provisional due to tokenizer warning. Relevance taxonomy is deterministic diagnostic annotation, confounded with task composition. Self-reported by the benchmark authors (NUS/PKU).
