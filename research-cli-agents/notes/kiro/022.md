# 022 — MCP Compression: Preventing tool bloat in AI agents
- **Source**: https://www.atlassian.com/blog/developer/mcp-compression-preventing-tool-bloat-in-ai-agents (Atlassian, 2026-04)
- **Claim**: Announces `mcp-compressor`, an open-source MCP proxy (Atlassian Labs) that wraps any MCP server and cuts its tool-description token overhead by 70–97% without changing how the agent calls tools, by replacing the full toolset with a tiny discovery interface that expands individual schemas on demand.
- **Mechanism**: Instead of sending every tool schema up front, the proxy exposes two generic wrapper tools — `get_tool_schema(tool_name)` (fetch full schema/docs for one tool) and `invoke_tool(tool_name, tool_input)` (execute with structured inputs) — plus an optional `list_tools()` for the most aggressive tier. Interaction shifts from "send every schema" to "send a tiny index, expand the tool that matters now." The compressed interface is stable across turns so it is prompt-cache-friendly. Uses generated namespaces like `mcp__atlassian__*`. Four verbosity levels: full (names+args+fuller descriptions), brief (names+args+one-line), minimal (names+args only), none (no embedded list; must call `list_tools()`). Drop in via `mcp.json` with `uvx mcp-compressor <server-url> --server-name <name>`.
- **Numbers**: Single large MCP server = 10,000–17,000+ tokens of tool descriptions per request. Official Atlassian MCP server ≈10k tokens (Jira+Confluence). Official GitHub MCP server = 94 tools ≈17,600 tokens. Combining servers → 30k+ tokens/request. GitHub 94-tool compression tiers: Baseline 17,600 → Low 3,900 → Moderate 3,300 → Strong 2,200 → Max 500 tokens. Overall reduction 70–97%. Reported "almost no impact on end-to-end quality" in their eval setup (no numbers given).
- **Token-cost implication**: For agents exposing many/large MCP toolsets, front-load only a compact discovery layer and fetch full schemas on demand — recovers tens of thousands of tokens per request before the model starts the task. Keep the wrapper interface stable to benefit prompt caching across turns. Many tools can be invoked directly from names+arg-names without fetching the schema at all, keeping indirection cost low. Tune the compression tier to server size/model/cost envelope rather than all-or-nothing.
- **Caveats**: Vendor blog promoting Atlassian's own OSS tool; quality claim is self-reported with no benchmark numbers or methodology. Still requires some tool metadata exposed; very large ecosystems may need extra discovery layers. Compared against (not a replacement for) "Code Mode"/code-execution-with-MCP approaches (Cloudflare/Anthropic), which trade tool-calling ergonomics for a programmable sandbox and add a code-generation failure mode. Token figures are for a "GitHub MCP-style 94-tool scenario," i.e. representative not independently audited.
- **Topic**: compression
